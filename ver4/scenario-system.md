# 시나리오 모드·전투 이벤트 시스템 설계 v0.1

작성: 2026-10-04 · 관련: [scenario.md](scenario.md)(스테이지 목록), [script-c1.md](script-c1.md)(서장~계교 대본·전투 설계), [design.md](design.md) 3부 6절

시나리오 모드와 전투 이벤트의 데이터 구조, 그리고 진행 규칙을 정한다. 이 문서는 현재 ver4 구현을 대신할 설계안이고, 아직 구현하지 않았다.

현재 구현이 어떤지는 6절에 따로 정리했다. 요약하면 노드 5종이 한 줄로 이어지고, 화자 구조·분기·전투 이벤트는 없으며, 전투가 끝난 뒤 돌아갈 노드는 코드에 하드코딩되어 있다.

---

## 1. 진행 방식 (사용자 확정: 조조전식)

```
[장면 연출] → [장면 연출] → … → [회의장] → [출전 준비] → [전투] → [전후 장면] → …
                                    ↑ 자유 행동은 여기서만
```

- **장면 연출**
  - 플레이어는 조작하지 않는다. 대사를 넘기기만 한다.
  - 장소마다 배경 맵(`scenes.json`의 무대)이 있고, 그 위에서 평복 캐릭터가 걷고, 인사하고, 감정을 표시한다. 대사는 아래 대화창에 초상과 함께 나온다.
  - 선택지는 드물게, 보조로만 쓴다. 대부분의 선택지는 대사만 바꾸고, 결과를 플래그로 남길 때만 분기에 쓴다.
- **회의장**: 전투 직전마다 한 번 열린다. 조조전의 회의장처럼 막사(또는 관청) 안에 아군 장수들이 서 있다.
  - **대화**: 장수를 클릭하면 짧은 대화가 나온다. 진행 상황, 플래그, 생존 여부에 따라 대사가 바뀌고 반복해서 볼 수 있다. 다음 전투의 힌트, 인물의 사연, 관계 복선이 여기에 들어간다.
  - **상점**: 해금된 상인이 회의장에 있으면 열린다(3절).
  - **편성·장비**: 지금의 출전 준비 화면으로 간다. 출전 장수, 장비, 부관을 바꾼다.
  - **저장**
  - **출진**: 확인을 받은 뒤 전투를 시작한다.
- **전투**: 개전 연출 → 진영 페이즈 반복(전투 중 이벤트) → 승리 또는 패배 연출 → 결과 화면.
- **전후 장면**: 승리하면 다음 장면으로 간다. 패배하면 지금처럼 출전 준비 체크포인트로 재도전한다. 노드가 지정한 경우에만 다른 분기로 간다.

## 2. 시나리오 데이터

### 2.1 파일 구성

| 파일 | 내용 | 비고 |
|---|---|---|
| `assets/content/campaign.json` `Script` | 시나리오 노드 전체 | 기존 `Nodes`를 대신한다. 규칙 데이터라 Core가 실행한다 |
| `assets/content/campaign.json` `Camps`, `Shops` | 회의장, 상점 | 규칙 데이터 |
| `assets/content/campaign.json` `Stages[].Events` 등 | 전투 이벤트(4절) | 규칙 데이터 |
| `assets/scenes.json` | 무대 맵, 출연자 배치, 동작 비트 | 지금처럼 GUI 전용. 노드 ID 대신 `scene` 노드의 `stage` 키로 연결한다 |
| `assets/graphics/portraits*.png` | 초상(표정 차분 포함) | 장수 ID와 표정 키로 찾는다 |

대사가 규칙 데이터에 들어 있으므로 CLI와 GUI가 같은 대본을 쓴다. 지금처럼 GUI가 텍스트를 정규식으로 잘라 화자를 추측하는 방식은 없앤다.

### 2.2 노드

모든 노드는 `ID`, `Kind`, `Next`를 가진다. `Next`가 없으면 다음 줄의 노드로 간다. 노드는 배열 순서대로 이어진다.

| Kind | 필드 | 동작 | 대기 |
|---|---|---|---|
| `scene` | `Place`(장소 이름), `Stage`(scenes.json 무대 키), `Cast`(출연자 [x,y,방향]), `Title`(장 제목, 선택) | 장소를 바꾼다. 장 제목이 있으면 "제 N 장 ○○" 화면을 띄운다 | 아니오 |
| `say` | `Speaker`(장수 ID 또는 이름), `Face`(표정: 기본/웃음/분노/놀람/슬픔/결의), `Text`, `Beats`(선택: 말하기 전 동작) | 대사 한 줄. 화자 하나, 초상 하나 | 예 |
| `narrate` | `Text`, `Style`(자막/연표/편지) | 내레이션. 연표 스타일이면 화면 중앙에 연도와 사건을 띄운다 | 예 |
| `choice` | `Text`, `Options`: `[{ID, Label, Next, Set}]` | 선택지. 고른 결과는 `choice:<노드ID>=<옵션ID>`로 저장한다 | 예 |
| `branch` | `Cases`: `[{If, Next}]`, `Else` | 조건 분기. 위에서부터 처음 맞는 경우로 간다 | 아니오 |
| `set` | `Flags`: `{키: 값}` | 플래그를 정한다 | 아니오 |
| `join` | `Officer`, `Level`(최초 합류 시), `Guest`(bool), `Event` | 합류. 게스트는 4.6절 | 아니오 |
| `leave` | `Officer`, `Event`, `Keep`(bool: 레벨·장비 보존) | 이탈. 장착 장비는 창고로 돌려보낸다 | 아니오 |
| `grant` | `Item` 또는 `Gold`, `Count`, `Event` | 지급 | 아니오 |
| `shop` | `Shop`, `Open`(bool) | 상점을 해금하거나 닫는다 | 아니오 |
| `camp` | `Camp` | 회의장을 연다. 출진하면 `Battle` 필드의 전투로 간다 | 예 |
| `battle` | `Stage`, `Win`, `Lose`(선택) | 회의장 없이 바로 전투로 간다(연전용). `Win`: 승리 후 갈 노드. `Lose`가 없으면 재도전 | 예 |
| `end` | `Ending` | 캠페인 종료. 엔딩 ID | 예 |

- **자동 노드**: `scene`, `branch`, `set`, `join`, `leave`, `grant`, `shop`. 플레이어가 기다려야 하는 노드를 만날 때까지 한 번에 처리한다. 지금의 `automatic()`과 같은 방식이다.
- **이벤트 키**: 지급·합류·이탈 노드는 `Event` 키로 한 번만 실행한다. 지금의 `Executed`와 같다.
- **저장**: 저장할 수 있는 시점은 `say`, `narrate`, `choice`, `camp`에서 기다리는 상태다.

### 2.3 조건식 (`If`)

조건은 문자열 배열이고, 모든 항목이 참이어야 참이다(AND). OR가 필요하면 `branch`의 경우를 여러 개 둔다.

| 형식 | 뜻 |
|---|---|
| `flag:키` / `!flag:키` | 플래그가 참 / 거짓 |
| `flag:키>=N` | 정수 플래그 비교 |
| `alive:장수` / `dead:장수` | 영구 사망 여부 |
| `party:장수` | 지금 편성에 있음(게스트 포함) |
| `choice:노드=옵션` | 그 선택지에서 고른 값 |
| `won:스테이지` | 그 전투에서 이긴 적이 있음 |
| `gold>=N` | 소지금 |

### 2.4 플래그

- 형식: `map[string]int`. 참·거짓은 0과 1로 쓴다.
- 키 이름 규칙: `flag-<주제>-<내용>`. 예: `flag-b01-merchants`, `flag-mifang-follow`(scenario.md 5절).
- 전투의 숨은 조건(4.3)과 이벤트(4.4)도 같은 플래그 저장소를 쓴다.
- 재도전 체크포인트는 플래그까지 함께 복원한다. 전투 중에 정해진 플래그는 승리가 확정될 때 반영하고, 패배하면 버린다.

### 2.5 회의장 (`Camps`)

```json
{
  "ID": "camp-b02",
  "Place": "연합군 진영 · 유비의 막사",
  "Stage": "S_camp_tent",
  "Battle": "B02",
  "Brief": "사수관을 지키는 화웅을 물리쳐라.",
  "Talks": [
    {"Officer": "관우", "If": [], "Lines": "talk-b02-guanyu"},
    {"Officer": "간옹", "If": ["!flag:talk-b02-jianyong-seen"], "Lines": "talk-b02-jianyong", "Set": {"talk-b02-jianyong-seen": 1}}
  ],
  "Shop": "shop-merchants"
}
```

- `Talks`의 `Lines`는 `say` 노드 묶음의 ID다. 대본은 `Script`의 별도 구역(`talk-*`)에 둔다.
- 같은 장수에게 대화가 여러 개 있으면 `If`가 맞는 **마지막** 대화를 보여 준다. 진행이 될수록 대사가 갱신된다.
- 아직 보지 않은 대화가 있는 장수 위에는 "…" 말풍선을 띄운다.
- 회의장에는 편성에 있는 장수(게스트 포함)가 자동으로 서 있다. 상인 NPC는 `Shop`이 해금되어 있을 때만 선다.
- 회의장 대화는 보상을 주지 않는다. 정보와 정취를 위한 것이다. 예외가 필요하면 `Set`으로 플래그만 남기고, 실제 지급은 시나리오 노드에서 한다.

### 2.6 상점 (`Shops`)

```json
{
  "ID": "shop-merchants",
  "Owner": "장세평",
  "Name": "중산 상단",
  "Items": [
    {"Item": "item_001", "Price": 100},
    {"Item": "소군량", "Price": 60},
    {"Item": "item_005", "Price": 300, "If": ["won:B06"]}
  ],
  "SellRate": 0.5
}
```

- **화폐**: `Gold`를 State에 새로 둔다. 전투 보상, 숨은 보물, 시나리오 지급으로 얻는다. 가격과 수입 곡선은 0.8 밸런스 지표에 "회차당 소지금"을 더해 정한다.
- **상인의 서사**: 첫 상인은 B01에서 구한 장세평·소쌍의 **중산 상단**이다. 서주 이후에는 미축의 상회가 더해진다. 의로운 상인이라는 축(scenario.md 4절)을 상점으로도 보여 준다.
- **사용 시점**: 회의장에서만 쓸 수 있다. 전투 중 구매는 없다.
- **팔 수 없는 물건**: 승급템과 고유 보물(design.md 2부 8절의 전설·희귀 등급).

### 2.7 State에 더할 것

| 필드 | 형식 | 용도 |
|---|---|---|
| `Flags` | `map[string]int` | 2.4 |
| `Gold` | `int` | 상점 |
| `Choices` | `map[string]string` | `choice:` 조건 |
| `Won` | `map[string]bool` | `won:` 조건 |
| `Guests` | `map[string]bool` | 4.6 |
| `Shops` | `map[string]bool` | 해금된 상점 |
| `Party` | `[]string` | **명단을 데이터로 관리한다.** 지금 코어 여러 곳에 박혀 있는 4인방 하드코딩을 대신한다 |

저장 형식 버전을 올리고, 이전 저장은 읽지 않는다(초반 개발 단계).

## 3. 장면 연출 규칙

- **화면 배치**
  - 위쪽: 무대 맵(줌 2)과 출연자 스프라이트
  - 아래쪽: 대화창. 왼쪽에 140px 초상, 이름표, 본문
- **초상**
  - 장수 ID와 표정 키로 찾는다.
  - 표정 차분이 없으면 기본 표정을 쓴다.
  - 초상이 아예 없는 인물은 이름표만 띄운다. 지금처럼 황건 장수 얼굴로 대신하지 않는다.
- **시나리오 도트의 방향 (사용자 확정)**
  - 시나리오 도트는 좌상(NW)·좌하(SW) 2방향만 만든다. 우상(NE)·우하(SE)는 각각을 좌우반전해서 쓴다.
  - 무대에서 바라보는 방향은 이 대각 4방향뿐이다.
  - 전투 도트는 지금처럼 8방향이다.
  - 제작 목록은 [script-c1.md](script-c1.md) 부록 B에 있다.
- **동작 비트**: 지금의 `scenes.json` 비트(move, face, play, emote, wait)를 `say` 노드의 `Beats`로 옮긴다. 대사 직전에 실행되고, 클릭하면 건너뛴다.
- **연표**: 장이 바뀌거나 시간이 넘어갈 때 `narrate(Style: 연표)`로 "189년 · 동탁, 낙양에 들어오다" 같은 자막을 띄운다.
- **편지**: `narrate(Style: 편지)`. 종이 질감 창에 보낸 이와 받는 이를 적는다. 형주 위임 때 유비의 편지 등에 쓴다.

## 4. 전투 이벤트

### 4.1 진영

| 진영 | 조작 | 페이즈 순서 | 용도 |
|---|---|---|---|
| `ally` | 플레이어 | 1 | 편성 장수 |
| `guest` | 플레이어 | 1 (아군과 같이) | 게스트 장수(4.6) |
| `npc` | AI | 2 | 우군 NPC. 공손찬, 장세평·소쌍 등 |
| `enemy` | AI | 3 | 적 |

- 페이즈 순서: 아군(게스트 포함) → 우군 → 적.
- 우군과 적은 서로 적대한다. 아군은 우군을 공격할 수 없고, 우군이 서 있는 칸은 아군이 지나갈 수 있다.
- 우군을 회복하거나 버프를 거는 것은 허용한다.
- 클레임 리플레이(design.md 0.9)는 우군 페이즈에도 그대로 적용한다.

### 4.2 스테이지 데이터 확장

```json
{
  "ID": "B01",
  "Name": "황건적 토벌",
  "Width": 18, "Height": 14,
  "Limit": 3,
  "TurnLimit": 15,
  "Tiles": ["…"],
  "Allies": [{"X": 2, "Y": 9}],
  "Units": [
    {"ID": "B01-장세평", "Officer": "장세평", "Faction": "npc", "X": 9, "Y": 7, "AI": {"Policy": "flee", "Goal": [2, 4]}},
    {"ID": "B01-정원지", "Officer": "정원지", "Faction": "enemy", "X": 15, "Y": 1, "AI": {"Policy": "hold"}},
    {"ID": "B01-wave2-1", "Officer": "B01_troop_9", "Faction": "enemy", "X": 17, "Y": 6, "Wave": "w2"}
  ],
  "Groups": {"merchants": ["B01-장세평", "B01-소쌍"]},
  "Victory": [{"Kind": "defeat", "Unit": "B01-정원지"}],
  "Defeat": [{"Kind": "defeat", "Unit": "유비"}, {"Kind": "defeatAll", "Group": "merchants"}],
  "Hidden": [{"ID": "flag-b01-merchants", "If": ["aliveAll:merchants"], "At": "victory"}],
  "Duels": ["…4.5"],
  "Events": ["…4.4"],
  "Treasures": [{"X": 1, "Y": 3, "Item": "소병법단", "Count": 2}]
}
```

- **승패 조건**: `Victory`와 `Defeat`는 목록이다. 하나라도 성립하면 확정된다. 같은 명령에서 둘 다 성립하면 패배를 우선한다(design.md 3부 7절과 같다).
- **조건 종류**
  - `defeat`(지정 부대 퇴각 또는 사망)
  - `defeatAll`(그룹 전원)
  - `hp`(지정 부대 병력 N% 이하. 지금의 Threshold를 대신한다)
  - `reach`(지정 부대가 지정 칸 범위에 도달)
  - `survive`(N라운드 버티기)
  - `annihilate`(적 전멸)
  - `flag`(이벤트가 정한 플래그)
- **턴 제한** `TurnLimit`: 넘기면 패배다. `survive` 조건과 함께 쓰면 그 라운드를 버텼을 때 승리다.
- **숨은 조건** `Hidden`: 화면에 표시하지 않는다. `At: victory`이면 승리가 확정되는 순간 판정해 플래그를 정한다. 결과 화면에 "숨겨진 공적" 줄로 사후에 알린다(영걸전·조조전처럼).
- **증원** `Wave`: 처음에는 배치하지 않고, 이벤트의 `spawn` 행동으로 등장한다.
- **숨은 보물** `Treasures`: 아군이 그 칸에 들어가면 얻는다(영걸전식). 칸 표시는 하지 않는다. 회의장 대화로 힌트를 줄 수 있다.

### 4.3 이벤트

```json
{
  "ID": "b01-dengmao-dies",
  "Once": true,
  "On": {"Kind": "duelEnd", "Duel": "B01-duel-1"},
  "If": [],
  "Do": [
    {"Kind": "say", "Speaker": "장비", "Face": "분노", "Text": "연인 장익덕이 여기 있다!"},
```

**발동 조건 `On`**

| Kind | 필드 | 발동 시점 |
|---|---|---|
| `start` | — | 개전 연출. 첫 아군 페이즈 전 |
| `phase` | `Faction`, `Round` | 그 진영 페이즈 시작 |
| `defeated` | `Unit` 또는 `Group` | 퇴각하거나 사망한 직후 |
| `duelEnd` | `Duel` | 일기토 결과가 확정된 직후 |
| `enter` | `Unit`/`Faction`, `Area`(x1,y1,x2,y2) | 이동을 마친 칸이 범위 안 |
| `adjacent` | `A`, `B` | 두 부대가 인접한 채로 한쪽의 행동이 끝남 |
| `adjacentAll` | `Unit`, `With`(부대 목록) | 목록의 부대가 모두 `Unit`에 인접한 채로 행동이 끝남(B03 삼영전) |
| `hp` | `Unit`, `Below`(%) | 병력이 비율 이하로 떨어짐 |
| `victory` / `defeat` | — | 승리 또는 패배 연출 직전 |

**행동 `Do`**

| Kind | 필드 | 효과 |
|---|---|---|
| `say` | `Speaker`, `Face`, `Text` | 맵 위 대사. 카메라가 화자 부대로 간다 |
| `narrate` | `Text` | 자막 |
| `camera` | `X`, `Y` 또는 `Unit` | 카메라 이동 |
| `spawn` | `Wave` | 증원 등장 |
| `remove` | `Unit` | 부대 이탈(연출상 퇴각) |
| `move` | `Unit`, `To` | 연출 이동. 규칙상 경로 비용을 무시한다 |
| `ai` | `Unit`/`Group`, `Policy`, `Target` | AI 전환(hold, charge, flee, guard, support) |
| `buff` | `Target`(`Unit`/`Group`/`Faction`), `Stat`, `Pct`, `Turns`(0=전투 끝까지), `Text` | 버프·디버프. design.md 1부 7절 규칙을 따르고, 같은 키는 덮어쓴다 |
| `damage` | `Unit`, `Pct` 또는 `Kill` | 연출상 피해 또는 전사(엄강 등) |
| `flag` | `Set` | 플래그 |
| `objective` | `Text` | 화면의 목표 문구 변경 |
| `join` / `leave` | `Officer`, `Faction` | 전투 중 합류(게스트 등장)와 이탈 |
| `grant` | `Item`/`Gold`, `Count` | 획득 |
| `win` / `lose` | — | 즉시 승리 또는 패배 |

**처리 규칙**

- 명령 하나의 효과가 모두 끝나면 승패 판정 전에 이벤트를 검사한다. 맞는 이벤트를 데이터 순서대로 실행한다.
- 이벤트가 만든 상태로 다른 이벤트가 맞게 되면 같은 검사 회차에서 이어서 실행한다. 최대 깊이는 8이다.
- `Once` 이벤트는 `event-<ID>` 실행 기록으로 한 번만 실행한다.
- 이벤트에는 난수가 없다. 같은 명령열이면 같은 결과가 나온다(design.md 15.6 리플레이 조건).
- **클레임 리플레이**: 이벤트는 장벽이다. 이벤트 앞의 행동 재생이 모두 끝나야 대사가 뜨고, 대사를 넘겨야 다음 행동이 재생된다.
- **CLI**: 이벤트 대사를 이벤트 줄로 출력한다. `-json`에서는 `{"kind":"say",…}` 이벤트로 낸다.

### 4.4 일기토 확장

지금의 `Duel` 구조체에 다음 필드를 더한다.

| 필드 | 뜻 |
|---|---|
| `Lines` | 일기토 오버레이에서 보여 줄 대사 줄(화자·표정·텍스트). 지금은 `Text` 한 줄뿐이다 |
| `Rounds` | 합 수 연출(예: "30합"). 결과에는 영향이 없다 |
| `If` | 성립 조건. 예: 턴 제한 일기토(B02 "술이 식기 전에") |

일기토 뒤의 효과(진영 디버프, AI 전환)는 `duelEnd` 이벤트로 붙인다. `Duel`에 효과 필드를 따로 두지 않는다.

### 4.5 우군 NPC AI

| Policy | 동작 |
|---|---|
| `flee` | `Goal` 칸을 향해 최단 경로로 이동하고 공격하지 않는다. 도착하면 `reached` 상태가 되어 맵에서 빠진다(구출 판정) |
| `hold` | 제자리에 머문다. 인접한 적만 공격한다 |
| `guard` | 지정 부대 주변 2칸 안에 머물며 공격한다 |
| `charge` | 지정 대상이나 가장 가까운 적에게 돌격한다 |
| `support` | 회복이나 버프 병법을 우선 쓴다 |

- 적 AI도 같은 정책을 쓴다. 지금의 적 AI 정책(지휘관, 돌격, 책략, 원거리)은 기본값으로 둔다.
- `ai` 행동은 지금 정책을 덮어쓴다.

### 4.6 게스트 장수

조운처럼 잠시 함께 싸우는 장수다.

- **편성**: `guest` 진영으로, 플레이어가 조작한다. 출전 상한에는 세지 않는다. 출전은 이벤트가 정한다.
- **성장**
  - 전투에서 경험치를 받고, 레벨과 특성치가 남는다.
  - 이탈할 때 `Keep`이면 성장 기록을 보관했다가, 나중에 정식 합류할 때 이어받는다.
  - 장비는 고유 장비로 고정하고, 회의장에서 바꿀 수 없다.
- **패배 조건**: 게스트가 퇴각해도 패배가 아니다. 다만 스테이지가 `Defeat`에 지정한 경우는 예외다.

## 5. 처리 흐름 요약

```
시나리오 커서 ──자동 노드 연쇄──▶ 대기 노드(say/narrate/choice/camp)
camp ─출진─▶ 체크포인트 저장 ─▶ 전투 생성(Units, Waves 보류)
     ─▶ start 이벤트 ─▶ [아군/게스트 페이즈 ─▶ 우군 페이즈 ─▶ 적 페이즈] 반복
         명령마다: 효과 → 이벤트 검사(연쇄) → 승패 판정
     ─▶ 승리: Hidden 판정 → 플래그·보상·Won 확정 → 결과 화면 → battle.Win 또는 camp 다음 노드
     ─▶ 패배: 체크포인트 복원(플래그 포함) → 회의장
```
