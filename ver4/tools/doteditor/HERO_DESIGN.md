# 장수 도트 제작 설계 (hero-sprite 스킬)

경보병·경기병 기본형(`units/infantry.yaml`, `units/cavalry.yaml`)에서 장수 도트를 새로 그린다.
그리기와 검수는 에이전트가 그림을 직접 보고 판단한다. 스크립트는 판단하지 않고 보기·찍기·색 바꿔 보기만 돕는다.
공통 기준은 `tools/spritetool/assets/SPRITE_ART_GUIDE.md`, 화풍·얼굴·동작 기준은 `UNIT_ART_GUIDE.md`를 따른다.

## 1. 요청 형식

| 요청 | 결과 |
|---|---|
| `유비 경보병 걷는장군` | 전투 도트: 경보병 기반, 8방향 × 6동작 × 4프레임 |
| `관우 경기병 장군` | 전투 도트: 경기병 기반 |
| `유비 비전투` | 비전투 도트: 무기 없이 걷는 차림, NW·SW × 4프레임 |

기본형(경보병/경기병)이 요청에 없으면 사용자에게 묻는다. 한 장수가 기병 전투 도트와 비전투 도트를 함께 가질 수 있다.

## 2. 산출물

| 종류 | id | 행 | 동작 |
|---|---|---|---|
| 전투 | `<id>` (예: `liubei`) | 8방향 | idle·walk·attack·hit·exhausted·block 각 4프레임, ms·loop는 기본형 그대로 |
| 비전투 | `<id>_noncombat` | NW·SW | idle 1 · walk 2(왼발 앞, 오른발 앞) · action 1 |

- 둘 다 도트 에디터 형식(`mhdemo-unit-pixels` v3)으로 `units/<id>.yaml`에 쌓는다. `unit.source_base`에 기본형 id를 적는다.
- 작업 기록은 `heroes/<id>/`에 둔다: `profile.md`(특징), `review-N.md`(검수 지적), `preview/`(확대 PNG, 지워도 되는 파일).
- 게임 반영은 사용자가 `make apply`로 한다. 스킬은 웹뷰 확인까지만 한다.

### 비전투 도트의 반영 (`apply.py` 변경)

에디터 파일에는 그린 4프레임만 저장하고, `apply.py`가 게임 시트로 펼친다.

- 행: NW·SW만 있으면 좌우반전해 NE·SE 행을 붙인다. 반전 전에 기준점 기준으로 칸을 좌우 대칭으로 넓힌다(`build_assets.py`의 평복 처리와 같은 방식).
- walk: `[대기, 왼발 앞, 대기, 오른발 앞]` 4프레임으로 펼친다.
- action: 장수 성격에 맞는 한 자세다. 예: 주먹 내밀기, 팔 벌려 맞이하기, 부채 내밀기(제갈량), 수염 쓰다듬기(관우).

전투 도트는 지금처럼 그대로 반영한다.

## 3. 테마색 사용

| 태그 | 쓰임 |
|---|---|
| 진영색 1–3 | 진영 따라 바뀌는 천·깃(상의, 두건, 허리띠, 안장 천, 투구 술). 다른 재질에 쓰지 않는다 |
| 테마 A/B/C 1–3 | 용도를 미리 정하지 않는다. 장수마다 `profile.md`에 배정한다. 예: 개인 상징색(관우 녹포), 복대·가슴 장식, 방패·나무 자루 |
| 피부·털·철·말 피부·갈기·안장·외곽선·효과 | 이름 그대로의 재질 |

- 1이 가장 밝고 3이 가장 어둡다. 명암 순서를 뒤집지 않는다.
- 진영색 1–3의 색 값은 게임의 팀 키(`index.json` `factions.team_keys`)와 같아야 하므로 장수별로 바꾸지 않는다.
  다른 태그 색(피부, 털, 테마 A/B/C 등)은 장수마다 바꿀 수 있다(`grid.py colors`).
- 태그 없는 자유색은 쓰지 않는다. 기본형에 원래 있던 반투명 효과색은 예외다.

## 4. 에이전트

### 4.1 특징 추출 → `heroes/<id>/profile.md`

- 자료: 기존 전투 도트(`tools/spritetool/assets/ver2-units/<id>/`), 평복 도트(`ver4-civilians/`), 초상(`tools/illustrations/`),
  `tools/unit3d`의 머리·수염 정의, `ver4/design.md`의 장수 설명.
- 기록 항목:
  - 색과 태그 배정: 부위마다 진영색 / 테마 A·B·C / 고정 재질
  - 옷과 갑옷, 신체 특징(귀, 수염, 얼굴색), 모자·관·투구
  - 무기 모양: 날 수, 떨어진 날이 원래 있는지(화극의 초승달 날) 등. 검수는 이 기술로 무기를 판단한다
  - 공격 방식(베기, 찌르기, 휘두르기)과 각 단계의 모양
  - 모션 특징: 막기 자세, 비전투 action 자세
  - 방향별로 보이는 것과 가려지는 것. 예: N·NW·NE에서는 수염이 안 보임, 무기가 몸 뒤로 감
- 사용자 확인 없이 다음 단계로 넘어가되, 초안을 사용자 보고에 포함한다.

### 4.2 도트 작가

기본형의 같은 프레임을 밑그림으로 놓고 에이전트가 도트를 고친다. 한 번 고칠 때마다 렌더해서 보고 다시 고친다.

1. **모델 시트**: 대기 8방향(프레임 0–3)을 무기까지 그려 머리·얼굴·옷·무기·태그 배정과 방향별 앞뒤 관계를 확정한다
   (비전투는 대기 NW·SW).
2. **사용자 확인 (필수 관문)**: 대기 8방향 시트와 웹뷰 주소를 사용자에게 보여 주고 승인을 받을 때까지 다음 단계로
   넘어가지 않는다. 지적이 있으면 모델 시트를 고쳐 다시 보여 준다. 승인 전에는 동작 작가를 띄우지 않는다
   (유비 1차 작업에서 모델 시트를 동작 작가들이 그린 뒤에 고쳐 전 동작을 다시 손봐야 했다).
3. **동작**: 걷기 → 공격 → 막기 → 피격 → 탈진 순서로 그린다.
   - 동작 단위로 하위 작가에게 나눠 맡길 수 있다. 모두 모델 시트와 profile을 기준으로 삼는다.
   - 변하지 않는 부위는 직전 프레임의 픽셀을 그대로 쓴다(공통 기준).
4. 비전투: 모델 시트 → 왼발·오른발 → action 순서로 그린다.

### 4.3 검수 (새 컨텍스트, 작가와 분리)

확대 이미지와 연속 재생 시트를 보고 판단한다. 지적은 `방향/동작/프레임: 증상`으로 `review-N.md`에 적고 작가에게 되돌린다.
반복은 최대 4회로 하고, 그때까지 남은 지적은 사용자에게 보고한다.

- **특징**: profile 항목이 방향별로 살아 있는지. 방향별 예외는 profile의 가려짐 표를 따른다.
- **테마색**: 태그 그룹마다 색을 크게 바꾼 시트를 원본과 나란히 본다. 바뀌어야 할 부위만 바뀌는지,
  다른 재질이 따라 물들지 않는지, 바꾼 뒤에도 명암이 자연스러운지 본다.
- **도트·동작**:
  - 무기가 profile의 모양과 다르게 끊기거나, 두 번 찍혀 겹치지 않는지
  - 머리-몸통, 팔-손-무기의 연결이 자연스러운지
  - 동작 서술과 그림이 맞는지: 공격의 힘 모으기→터뜨리기→마무리, 막기에서 무기가 공격 방향을 막는지
  - 가려짐 순서가 맞는지: 막는 무기가 머리 앞에 있는지, 뒤를 보는 방향에서 무기·팔이 몸 뒤로 가는지
  - 발 기준점 고정, 머리 크기 일관성, 셀 가장자리 잘림, 떨어진 잡픽셀

### 4.4 웹뷰 `viewer.html`

`make serve` 후 `http://localhost:8000/viewer.html?unit=<id>`로 연다. yaml을 직접 읽고 태그 색을 바꿔 그린다.

- 위쪽 고정 바: 정지 / 재생 / 다음 프레임 / 속도 ×1·×2·×4·×8 / 장수 선택
- 본문: 전투 도트는 대기 → 이동 → 공격 → 피격 → 탈진 → 막기 순서로 한 줄씩 놓고, 각 줄에 8방향을 둔다.
  비전투 도트는 대기 → 걷기 → action을 4방향(NE·SE는 반전)으로 둔다. 모두 같은 시계로 동기 재생한다.
- 아래쪽: 태그 그룹별 색 선택기, 그룹별 원복, 전체 원복
- 검수 에이전트도 이 페이지를 headless Chrome으로 캡처해서 본다.

## 5. 보조 스크립트 (`heroes/tools/`)

판단은 하지 않고 입출력만 한다. 사용법은 각 파일의 docstring과 스킬(`.claude/skills/hero-sprite/SKILL.md`)에 있다.

| 스크립트 | 하는 일 |
|---|---|
| `grid.py new` | 기본형을 복사해 `units/<id>.yaml`을 만든다. 비전투는 NW·SW의 대기 1장, 기본형 걷기 2장, 액션 1장(대기 복사)으로 만든다 |
| `grid.py export/import` | 프레임을 `heroes/<id>/grid/<동작>/<방향>-<n>.txt` 문자 격자로 꺼내고 다시 넣는다. 태그마다 고정 문자, 반투명은 숫자, 범례는 파일 머리에 있다 |
| `grid.py colors` | 장수별 태그 색 지정(진영색 제외) |
| `render.py` | 프레임 확대(기본형과 나란히), 동작×방향 시트, 태그 그룹 색을 바꾼 시트. 격자 작업본을 바로 읽는다 |
| `live.py` | 작업 중 격자를 주기적으로 렌더해 `heroes/live/`에 쓰고 진행 줄을 출력한다. `progress.html`이 이것을 보여 준다 |

격자 파일이 작업본이다. 여러 작가가 서로 다른 프레임 파일을 동시에 고치고, yaml 반영(`import`)은 마지막에 한 번 한다.

## 6. 진행 순서

1. 이 문서 확정 → `apply.py`의 비전투 펼치기, 보조 스크립트, `viewer.html`, 스킬 `SKILL.md` 작성
2. 유비 경보병 전투 도트로 전체 흐름 검증
3. 관우·장비·여포 경기병 전투 도트(병렬)
4. 유비·관우·장비·여포 비전투 도트

## 7. 결정 사항

- 비전투 도트의 밑그림은 경보병(말에서 내린 차림, 무기 제거)이다. 기병 장수도 같다.
- 비전투 도트는 나중에 장면용 평복 `civ_<id>`를 대체한다. 게임 코드 연결은 별도 작업이다.
