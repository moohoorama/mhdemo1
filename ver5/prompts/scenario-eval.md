# 시나리오 장별 평가 (평가자 셋)

게임의 모든 장을 Sonnet 서브에이전트 셋이 각자 기준으로 채점하고, 점수표와 그래프 페이지로 합치는 절차다.
요청할 때는 "`prompts/scenario-eval.md` 대로 시나리오 평가해 줘"라고 하면 된다.

결과 구조: 장마다 기준 점수 9개(평가자 3 × 기준 3) + 평가자별 총점 3개(각 30점) + 최종 총점 1개(90점) + 평가자별 코멘트 3개.

## 0. 준비

1. 대본 문서를 새로 만든다. 평가는 이 문서만 읽는다(게임 데이터·코드는 읽지도 고치지도 않는다).
   ```
   cd ver5 && make scenario-doc      # output/chapters/chNN.md (30개, 25v·26v·27v 포함)
   ```
2. 작업 폴더를 만든다: `mkdir -p ver5/output/eval` (`output/`은 gitignore 대상이다).
3. 평가자 A·B·C를 **한 번에 병렬로**, 서브에이전트 `general-purpose`, `model: sonnet`, 백그라운드로 띄운다.
   각자 한 장씩 읽고 곧바로 결과 파일에 한 줄씩 덧붙인다(30장을 한꺼번에 읽고 쓰면 컨텍스트가 넘친다).

## 1. 평가자와 기준

| 평가자 | 담당 | 기준 1 | 기준 2 | 기준 3 |
|---|---|---|---|---|
| A | 대본·연출 | 서사 구성 | 대사 품질 | 연출 |
| B | 플레이어 경험 | 동선·목표 명확성 | 플레이어 주체성 | 진행 리듬·보상 |
| C | 전투 설계 | 목표의 이해 가능성 | 맵·배치 설계 | 전투와 이야기의 연결 |

기준마다 0~10 정수, 엄격하게. "평균을 6 전후로 두고 장 사이에 차이가 나게" 매기라고 적어야 점수가 몰리지 않는다.
요소가 없는 장(탐험·전투가 없는 장)도 N/A 없이 점수를 주고 사정을 코멘트에 적게 한다.

## 2. 평가자 공통 프롬프트 틀

`<...>`만 채운다. 결과 파일 경로는 `ver5/output/eval/<A|B|C>.jsonl`의 절대 경로로 쓴다.

```
당신은 삼국지 SRPG(유비 주인공, 영걸전풍, 연의 톤) 시나리오 평가자 <A/B/C>(<담당>)입니다.
읽기 전용 평가이며 게임 데이터·코드는 절대 수정하지 마세요. 결과 파일만 쓰세요.

대상: <ver5 절대 경로>/output/chapters/ 아래 30개 마크다운(ch01.md ~ ch27.md, ch25v/ch26v/ch27v 포함).
게임 데이터에서 자동 생성한 '현재 구현 상태' 대본으로, 장면(S장-#n: 장소·등장 인물 자리·대사·〔연출〕),
탐험(X: 동선·인물·상점·출진·이벤트 호출 지점), 전투(B: 목표·ASCII 맵·배치·일기토·전투 중 사건)가 들어 있습니다.
<담당 범위 설명>

평가 기준 3개(각 0~10 정수, 엄격하게. 평균을 6 전후로 두고 장 사이에 차이가 나게 매기세요):
1. <기준 1 정의>
2. <기준 2 정의>
3. <기준 3 정의>
chapter별 총점 = 세 점수의 합(0~30).

방법: 한 장씩 읽고 곧바로 결과를 파일에 누적하세요. 결과 파일: <절대 경로>/<A|B|C>.jsonl —
한 줄에 JSON 하나, 장 하나당 한 줄(Bash의 >> 사용 가능), 형식:
{"chapter":"22","scores":[기준1,기준2,기준3],"total":합,"comment":"2~4문장의 한국어 평가. 잘된 점 하나 이상과 가장 고칠 점 하나 이상을 구체적 장면·노드·이벤트 ID로 짚기"}
장에 해당 요소가 거의 없어도 N/A 없이 0~10 정수를 주고 그 사정은 comment에 적으세요.
30줄이 다 채워지면 "끝: 30줄 작성"이라고만 보고하세요.
```

기준별 정의 문구(위 틀의 1~3에 그대로 넣는다):

- **A 서사 구성**: 장 안에서 사건의 인과·긴장·마무리가 이어지는가, 이야기만 늘어지거나 급박·어색하지 않은가, 앞뒤 장과 이어지는가.
- **A 대사 품질**: 인물별 말투 구분, 정사·연의에 비춰 시대·입장 개연성, 설명조·나레이션식 대사, 낯간지러운 유비 띄우기, 어색한 호칭(유비를 형님이라 부르는 건 관우·장비뿐) 여부.
- **A 연출**: 〔연출〕 지시(입장·이동·방향·표정)와 등장 인물 배치가 대사를 살리는가, 장면이 정적이거나 빈약하지 않은가, 연출 없는 긴 대사 구간이 얼마나 되는가.
- **B 동선·목표 명확성**: 어디로 가서 누구와 말해야 다음으로 가는지 알 수 있는가, 출구·조건·출진 지점이 자연스러운가, 막히거나 헤맬 위험은 없는가.
- **B 플레이어 주체성**: 이야기가 장면으로만 주르르 흐르지 않고 걷고 고르고 말을 거는 활동이 있는가(탐험 비중, NPC 대사의 쓸모, 선택·분기, 이벤트 호출 방식).
- **B 진행 리듬·보상**: 장면·탐험·전투의 배분과 길이, 상점·획득·합류·이탈 같은 보상과 변화가 적절한가, 지루하거나 급한 구간은 없는가.
- **C 목표의 이해 가능성**: 승리·패배·부목표가 명확한가, 어떻게 이겨야 하는지 짐작 가능한가(사건 조건이 복잡해 의도가 안 읽히면 감점), 이야기가 정한 결말과 맞는가.
- **C 맵·배치 설계**: 지형·구조물·강·진영이 장소 이름과 사건을 표현하는가, 적 배치·정책(제자리·반응·돌격 등)이 전술적으로 의미 있는가, 맵 밖 배치(`⚠맵 밖`)·한쪽 쏠림·밋밋한 맵은 없는가.
- **C 전투와 이야기의 연결**: 전투 중 대사·증원·일기토가 서사를 살리는가, 전투 전후 장면과 이어지는가, 일기토·사건이 싱겁거나 끼워 맞춘 느낌은 아닌가.

담당 범위 설명: A는 장면 대사와 연출(탐험·전투 중 대사도 대사 품질 판단에 포함 가능), B는 플레이어가 무엇을 하며 이야기를 겪는가(장 전체), C는 전투 설계(전투가 둘 이상이면 모두 아우르고, 장면·탐험은 맥락 이해용으로만 참고).

## 3. 합치기

세 파일이 모두 30줄이 되면(서브에이전트 완료 알림을 기다린다. `wc -l`로 확인) 검증하고 합친다.

- 각 줄이 JSON이고, 장 ID가 30개 모두 있으며, `scores` 길이가 3이고 `sum(scores) == total`인지 본다. 어긋나면 그 장만 해당 평가자에게 다시 시킨다.
- 장 ID 정렬은 `01 … 27, 25v, 26v, 27v`(스토리 순서)로 한다.
- 최종 총점 = A·B·C 총점의 합(90점 만점). 기준별·평가자별 평균도 구한다.

## 4. 보고 페이지

HTML 아티팩트 하나로 만든다(제목 예: 「시나리오 30장 평가」).

- **그래프 셋**: ① 장별 최종 점수 누적 막대(막대 호버에 세부), ② 평가자별 총점 추이 꺾은선, ③ 기준 9개 평균 가로 막대.
- **점수표**: 열은 A 기준 3·합, B 기준 3·합, C 기준 3·합, 최종. 맨 아래 평균 줄. 칸 색은 점수에 비례해 진하게.
- **코멘트**: 장마다 점수 줄 바로 아래에 평가자 셋의 코멘트를 **기본으로 펼쳐** 둔다(접기 버튼은 보조).
- 점수가 낮은 장·높은 장 5개씩을 위에 요약한다.
- 평가자 색은 검증된 범주 색 슬롯 1~3(밝은 모드 `#2a78d6` `#eb6834` `#1baf7a`, 어두운 모드 `#3987e5` `#d95926` `#199e70`)을 평가자 순서 A·B·C로 고정한다. 보라·파랑 조합은 색각 이상 검사에서 떨어진다.
- 라이트·다크 둘 다 토큰으로 정의한다.

보고에는 평균(평가자별·최종), 낮은 장 순서, 눈에 띄는 경향, 한계를 짧게 적는다.
한계: 평가자가 Sonnet 셋이고 기준이 달라 절댓값보다 장끼리의 순서와 코멘트의 구체적 노드가 쓸모 있다. 점수는 `make scenario-doc` 시점의 구현 상태 기준이다.

## 5. 해서는 안 되는 것

- 평가 도중 게임 데이터·코드·대본을 고치지 않는다(평가와 수정은 따로 한다).
- 평가자에게 내 가설이나 기대 점수를 알려 주지 않는다.
- 이전 평가 결과 파일을 지우지 않는다. 다시 돌릴 때는 `output/eval/`에 날짜 폴더(예: `output/eval/2026-11-18/`)를 만들어 덮어쓰기를 피한다.
