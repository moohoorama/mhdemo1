# 이야기 중심 일기토 제작

일기토를 장수의 실력·성격·감정과 승패가 동작으로 드러나는 짧은 전투극으로 만든다. 사용자가 지정한 이야기와 수정 사항을 우선한다.

## 시작할 때 읽을 것

프로젝트 루트를 기준으로 `README.md`, `docs/duel-animation.md`, 해당 스테이지의 `assets/data/maps/<ID>.json`과 `assets/duels.json`을 읽는다. 이야기 근거는 해당 내용이 있는 `docs/scenario.md`·`docs/script-c1.md`에서 확인한다. 사용자에게서 전개를 받았다면 그것을 구현 기준으로 삼는다. 엔진 승패는 `internal/core/formation.go`, 동작은 `internal/duel/timeline.go`, 검증은 `internal/duel/scripts.go`, 화면은 `internal/duelview/`, 재생과 건너뛰기는 `internal/gui/player.go`·`internal/gui/duel.go`다.

## 예제보다 이야기를 우선

- `duel.New`의 공통 도입·일곱 결말과 기존 동작은 참고 예제다. 장면 목록을 완성된 문법이나 필수 순서로 취급하지 않는다. 모든 승부에 연타·탈진·교차 돌진을 넣지 않는다.
- 먼저 누가 공격하고 누가 방어하는지, 누가 지치는지, 누가 두려워하는지, 어떻게 이동하고 끝나는지를 정한다. 기존 동작에 부수적으로 포함된 다른 장수의 자세·이동·대사까지 읽는다.
- 필요한 의미를 표현할 동작이 없다면 타임라인·상태 표현·렌더러·검증을 필요한 만큼 확장한다. 데이터만 편집하려고 이야기와 맞지 않는 예제를 끼워 넣지 않는다.
- 압도적인 승자는 불필요하게 피격되거나 헉헉거리지 않는다. 두 장수의 동작을 따로 지정한다. 기존 `rest`는 양쪽을 탈진시키므로 한쪽만 지치는 장면에 그대로 쓰지 않는다.
- 강한 공격이 방어되는 경우, 공격의 섬광·충격 효과와 방어자의 피격·밀림·흔들림을 구분한다. `critical`은 피격을 동반하므로 완전 방어에 쓰지 않는다. `critical-block`은 그 공격을 막는 동작의 한 예다.
- 도주는 시작 위치와 상대 위치를 보고 경로를 선택한다. `escape`·`catch` 예제의 옆으로 돌아가는 `Lane`은 공통 필수 효과가 아니다. 진영으로 곧장 달아나는 상황은 직선으로 이동하고, 추격·접촉·베기의 위치와 방향을 이어 준다. `straight-chase`는 현재 직선 추격 예다.
- 예: 화웅은 기세 좋게 연속 공격 → 강타까지 관우가 쉽게 방어 → 공포 → 직선 도주 → 관우가 추격해 베기. 관우에게 탈진을 붙이지 않는다. 등무는 중앙에 당당히 나와 정면 대치한 뒤 한 합에 패한다. 이 전개를 다른 장수에게 자동 복제하지 않는다.

## 데이터와 규칙

`assets/duels.json`의 키는 스테이지 일기토 ID다. `Outcome`은 엔진 이벤트의 승패와 맞춘다. `Beats`에는 동작, 저작용 `Title`, 대사, `Side`와 시간을 기록한다. `Supports`는 합류할 두 장수의 콘텐츠 ID를 기록한다. `Side` 2·3은 지원군이며 `reinforcements` 이후 대사·방어되는 공격·회피되는 공격에 참여할 수 있다. `Side`는 0=아군, 1=적군이며 공격 동작에서는 공격자를 의미한다. 기존 `block`·`dodge`의 `Speech`는 방어자에게 표시된다. 의도한 화자를 확인하고 필요하면 별도 대사 구간이나 표현 필드를 추가한다.

연출은 규칙 상태나 난수를 바꾸지 않는다. 사망·퇴각을 바꾸라는 요청이 있으면 해당 맵의 `AllyResult`·`EnemyResult`도 함께 맞춘다. 요청 없이 연출만으로 규칙 결과를 바꾸지 않는다. 맵 데이터가 바뀌면 콘텐츠 해시와 기존 저장 자료 호환에 영향을 준다. 일기토 종료·건너뛰기 후 후속 이벤트를 유지한다.

## 화면과 검증

일반 감상 화면에는 상황 설명·동작 제목·진행률·분석용 조작을 표시하지 않는다. 장수 초상, 실제 대사와 건너뛰기 버튼을 사용한다. 저작용 설명과 탐색은 본편 감상 모드의 명시적인 `-duel-debug` 모드에 둔다. 말풍선은 `internal/duelview/bubble.go`의 흰색 PNG 조립을 쓴다.

검증은 결과뿐 아니라 이야기 의미를 확인한다. 방어 순간의 자세와 효과, 여유로운 장수의 피격·탈진 여부, 도주 경로, 추격자의 도착, 첫 타격 전후 시점, 사망·퇴각 결과가 관찰 가능한 테스트 대상이다. 바뀐 동작은 타격 전·접촉·이후 및 마지막 구간을 확인한다. 입력한 JSON과 같은 문자열인지 확인하는 테스트로 대신하지 않는다.

```sh
go test ./internal/duel ./internal/core ./internal/gui
go vet ./internal/duel ./internal/duelview ./internal/gui ./cmd/srpg-gui
go run ./cmd/srpg-gui -duel <ID> -duel-capture reports/duel-story-preview
go run ./cmd/srpg-gui -duel <ID> -duel-debug
SRPG_RENDER_TEST=1 go test ./internal/gui -run '^TestRenderedCampaignDuels$' -count=1 -v
```

실제 렌더링을 확인해 동작과 시선, 말풍선 화자, 피격과 방어 효과가 의도대로 보이는지 검토한다. 최종 보고에는 바뀐 전개와 규칙 결과, 검사 결과를 짧게 적는다.

삼영전여포의 세 도입은 서로 다르다. 장비는 밀리지 않는 격전, 관우는 강공과 여포의 회피, 유비는 밀리는 방어와 버티기다. 나머지 두 형제가 눈에 보이게 합류해 공격하고, 여포는 세 사람을 감당하기 어렵다고 판단해 `retreat` → `withdrawn`으로 직선 퇴각한다. 퇴각자는 사망·탈진 자세를 취하지 않는다.

지원군은 화면 좌하단과 우하단에서 각각 진입해 기존 상대와 적을 세 방향으로 포위한다. 적이 세 장수 사이에 있는지 확인하고, 방어자가 각 공격자를 실제로 바라보게 한다. 퇴각은 병사 대열 입구에서 멈추며 병사 그림과 섞이지 않는지 실제 렌더링으로 확인한다. 이름은 굵기 800, 대사는 400으로 구별하고 속말은 괄호로 표현한다. 기본 일기토 재생은 2배 속도이며 본편 장벽 시간과 감상 시계를 함께 맞춘다.
