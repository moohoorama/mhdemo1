# 소타일 기반 맵 표현 및 맵에디터 구현 계획

작성일: 2026-10-10  
상태: 본 구현 및 사용자 추가 요청 구현 완료 / 자동 테스트·실제 렌더링 검증 완료

범위: 전투맵 렌더링 개선, 비전투 외곽 지형, 시작 메뉴에서 실행하는 맵에디터

## 1. 목표와 현재 구조

게임상의 한 칸을 **대타일**, 그 안에서 그림과 지형을 각각 편집하는 2×2 칸을 **소타일**이라고 부른다. 이동 거리, 공격 범위, 병력 배치, AI와 지형 효과는 대타일 기준으로 유지한다. 소타일은 화면 표현과 지형 편집에 사용한다.

구현 전 코드에서 확인한 내용(현재 저장 구조는 7절 및 아래 구현 기록 참고):

- `internal/gui/field.go`의 `K = 2`에 의해 지면과 `Structures` 그림은 2배로 확대된다. 유닛 그림은 원본 배율이다. 사용자가 느낀 픽셀 밀도 차이는 실제로 존재한다.
- 현재 대타일 커서는 원본 32×16 마름모를 확대한 64×32 픽셀이다. 기본 지면 조각은 원본 16×8에서 화면상 32×16으로 확대된다. 이하 크기는 카메라 줌을 적용하기 전 기준이다.
- 기존 지면에도 대타일마다 2×2 그림 조각이 있다. B01은 14×10 게임 칸에 지면 조각 560개를 가진다. 그러나 이 조각들은 각각 독립적인 게임 지형 정보를 갖지 않는다.
- 전투맵의 숲은 `Props[forest_*]`를 원본 배율로 그린다. 일반 타일 장식과 비전투 장면에는 확대 경로도 있으므로 나무를 모두 같은 방법으로 일괄 축소하면 안 된다.
- 전투 규칙은 `assets/data/stages/*.json`의 `Stage.Tiles`, 그림은 `assets/graphics/maps/*.json`의 지면·장식·구조물을 사용한다. 두 자료의 일관성을 유지해야 한다.
- 시작 메뉴에는 새로 시작, 불러오기, 설정, 종료가 있다. 여기에 맵에디터를 추가한다.
- 현재 `Spawn`은 캐릭터, 위치, 레벨, 진영 색상 재정의만 지원한다. 배치별 병종·방향·HP·MP·특성·장비 설정은 추가 구현이 필요하다.

### 핵심 설계 결정

**게임 칸의 화면 크기 64×32와 유닛 크기를 유지하면서, 타일·구조물의 그림 픽셀 배율을 2에서 1로 줄인다.** 대타일 내부에는 각각 32×16인 소타일 4개를 둔다.

현재 16×8 지면 조각을 단순히 절반으로 그리기만 하면 빈 공간이 생긴다. 소타일 하나를 원본 배율의 기존 지면 조각 2×2로 구성하거나, 같은 면적의 32×16 원본 소재로 구성한다. 기존 소재를 재사용할 때 대타일 하나에는 지면 조각이 4×4로 들어간다. **편집 지형은 2×2, 내부 그림 조각은 4×4**이며 두 개념을 혼동하지 않는다.

| 요소 | 현재 | 목표 |
|---|---|---|
| 대타일 | 화면 64×32, 지형 하나 | 화면 64×32, 소타일 4개에서 지형 산출 |
| 소타일 | 독립적인 지형 데이터 없음 | 화면 32×16, 지형 종류 개별 저장 |
| 기본 지면 그림 조각 | 원본 16×8 → 화면 32×16 | 원본 16×8 → 화면 16×8, 필요한 면적만큼 구성 |
| 기존 구조물 그림 | 2배 확대 | 원본 배율, 소타일 위치에 배치 |
| 전투맵 숲 나무 | 원본 배율 | 크기·픽셀 배율 유지 |
| 유닛 | 원본 배율, 대타일 중심 | 그대로 유지 |

이 방식은 새 디테일을 자동 생성하는 것이 아니라 기존 확대 픽셀을 줄이고 더 촘촘히 조합하는 방식이다. 특정 구조물에 필요한 연결 그림이 없으면 별도 소재 제작이 필요하다. `K` 하나만 바꾸는 구현은 하지 않는다.

## 2. 좌표와 지형 판정

### 대타일과 소타일

- 대타일 좌표 `(u, v)`에 소타일 `(2u, 2v)`, `(2u+1, 2v)`, `(2u, 2v+1)`, `(2u+1, 2v+1)`이 대응한다.
- 화면 변환과 역변환을 한곳에 모으고 전투·에디터가 공유한다. 전투 입력은 대타일, 지형 편집 입력은 소타일을 구한다.
- 외곽에는 음수 좌표도 사용한다. 소타일에서 대타일을 구할 때 음수 정수 나눗셈은 내림으로 처리한다. 경계선 판정은 반열린 구간으로 통일한다.
- 이동 경로, 사거리, 턴 진행, 충돌 검사는 소타일 개수를 세지 않는다.

### 단독 최다 종류로 변경하고 동률이면 기존 판정 유지

소타일을 변경했을 때 **단독으로 가장 많은 종류가 있으면** 대타일 판정을 그 종류로 변경한다. 3:1, 4:0뿐 아니라 2:1:1도 단독 최다이므로 변경한다. 2:2 또는 1:1:1:1이면 **변경 직전의 대타일 판정을 유지**한다. 소타일 위치나 순서로 승자를 고르지 않는다.

최초 이관 시 기존 `Stage.Tiles`로 판정을 초기화한다. 이후에는 단일 문서의 `Resolved`를 읽는다. 새 영역은 생성 시 기본 지형으로 초기화한다. 편집 원본에는 현재 대타일 판정을 함께 저장한다. 로드·저장은 저장된 판정을 사용하며 동률을 재판정하지 않는다. 실행 취소/다시 실행도 소타일과 대타일 판정을 함께 복원한다.

연속 칠하기는 실제로 소타일이 변경되는 순서대로 판정을 갱신한다. 드래그 작업을 실행 취소 한 번으로 묶더라도 중간에 확정된 판정을 최종 집계만으로 덮어쓰지 않는다.

| 변경 전 판정 | 변경 후 소타일 4개 | 변경 후 판정 |
|---|---|---|
| 물 | 초원 / 초원 / 초원 / 황무지 | 초원: 단독 최다 |
| 초원 | 초원 / 물 / 물 / 물 | 물: 단독 최다 |
| 초원 | 초원 / 물 / 물 / 성벽 | 물: 2:1:1 단독 최다 |
| 초원 | 초원 / 물 / 초원 / 물 | 초원 유지: 2:2 동률 |
| 물 | 초원 / 물 / 초원 / 물 | 물 유지: 같은 소타일 구성이어도 기존 판정 유지 |
| 숲 | 초원 / 황무지 / 숲 / 물 | 숲 유지: 1:1:1:1 동률 |

현재 데이터의 초원에 해당하는 이름은 `평지`이며, 최초 브러시는 기존 지형 이름을 사용한다.

유닛의 모든 판정은 대타일만 따른다. 이 결과를 이동 비용, 방어 보정, 숲 매복, 물 인접 조건, 성내 효과, 턴 시작 HP·MP 회복에 공통 적용한다. 소타일에 물이나 성벽이 있어도 별도 충돌·통행 제한을 추가하지 않는다. 에디터 오른쪽에는 4개 구성, 최종 판정과 `동률: 기존 판정 유지` 이유를 보여준다.

### 구조물·높이·나무

- 평지/황무지/물 같은 지면은 소타일 경계에 맞춰 연결한다. 물 애니메이션과 해안 연결도 소타일 기준으로 생성한다.
- 마을, 산, 성벽 등의 구조물은 원본 배율로 줄이고 해당 소타일에 자동 반복 배치한다. 개별 건물 선택·수동 배치 모드는 이번 범위에 추가하지 않는다. 성문·다리·텐트처럼 현재 원본 배율로 그리는 소재도 구조물인지 자연물인지 명시적으로 분류한다. 구조물은 요청한 축소 결과가 되도록 기존 소재별 배율을 확인한다.
- 성벽·성문·다리 연결은 시각적인 소타일 이웃을 사용하되, 통행과 전투 효과는 산출된 대타일을 사용한다.
- 높이가 있는 성벽 등은 대타일의 게임 지형에 따라 유닛 발 위치·커서·공격 효과의 공통 높이를 결정한다. 구조물 축소에 맞춰 시각 높이를 조정한다. 소타일마다 유닛 높이가 달라지지 않는다.
- 대타일 판정이 평지인데 소타일 하나만 성벽이면 해당 구조물은 시각적 표현이다. 오른쪽에 `게임 지형: 평지`를 명확히 표시한다. 부분 구조물 때문에 판정되지 않은 칸이 실제로 막혀 보이지 않도록 연결·높이 표현을 검토한다.
- 숲 나무는 현재 크기와 픽셀 밀도를 보존한다. 소타일 4개 모두 숲이라고 큰 나무 4개를 무조건 생성하지 않는다. 대타일 단위의 일정한 밀도와 결정적인 배치 규칙을 사용한다.
- 나무 밑동 위치로 깊이 정렬하고 기존 가림 시 유닛 반투명 표시를 유지한다. 나무의 클릭 영역 대신 지면 좌표로 칸을 선택한다.

## 3. 전투맵 외곽

맵 자료에는 **전투 가능 영역**과 **그림을 갖는 영역**을 별도로 저장한다. 전투 영역은 대타일 사각 격자이고 화면에서는 마름모 형태다. 그림 영역은 이를 감싸는 더 큰 소타일 격자다.

- 기본 외곽 폭은 전투 영역 사방 대타일 4칸이다. 기존 맵 이관 시 경계 지형을 자연스럽게 연장해 초기 외곽을 만든다. 이후 에디터에서 외곽 소타일도 직접 수정한다.
- 카메라에 저장된 그림 영역 밖이 보이면 결정적인 기본 지면을 연장해서 빈 검정 배경을 막는다. 확대·이동 범위와 외곽 생성 범위를 함께 관리한다.
- 외곽 지면에 어두운 색조를 적용한다. 초기값은 밝기 약 45%이며 실제 화면에서 조정한다. 외곽의 구조물·나무·그림자도 외곽 소속에 맞춰 어둡게 표현한다.
- 어둡게 하는 기준은 화면 직사각형이 아니라 전투 영역의 실제 마름모 경계다. 경계를 넘는 나무 가지가 전투 칸을 함께 어둡게 만들지 않도록 지면 마스크와 물체 색조를 구분한다.
- 전투 중 외곽에는 선택, 이동, 공격 대상 지정, 병력 배치가 불가능하다. 외곽 그림이 물·숲이어도 엔진의 맵 바깥 규칙은 그대로 적용한다.
- 에디터에서는 외곽 지형을 칠할 수 있지만 병력을 놓을 수 없다. 외곽 어둡게 보기 토글로 원래 그림도 확인할 수 있다.
- 그림 영역까지 매 프레임 전체 탐색하거나 물 프레임별 거대 캔버스를 생성하지 않는다. 화면에 보이는 범위와 변경된 영역을 기준으로 그리기·캐시를 갱신한다.

## 4. 시작 메뉴와 에디터 화면

`시작 메뉴 → 맵에디터 → 전투맵 목록 → 편집 화면`으로 진입한다. 목록에는 맵 이름, ID, 대타일 크기, 미리보기, 수정본 여부를 표시한다. 기존 캠페인 전투맵을 선택해 수정할 수 있다.

```text
┌──────────────────────────────────────────────────────────────┐
│ 맵 이름 / 변경됨     저장  다른 이름으로 저장  시험 전투  나가기 │
├──────────────────────────────────────────────┬───────────────┤
│                                              │ 선택 칸 정보  │
│       전투 영역 + 어둡게 보이는 외곽           │ 소타일: 평지  │
│                                              │ 대타일: 숲    │
│        ◇ 대타일 커서                         │ 구성/효과     │
│          ◇ 내부 소타일 커서                   │ 병력 상세     │
│             평지(숲)                         │               │
├──────────────────────────────────────────────┴───────────────┤
│ [타일] [병력 배치]  1 평지  2 황무지  3 물  4 숲  5 산 ...   │
└──────────────────────────────────────────────────────────────┘
```

### 커서와 타일 브러시

- 마우스 아래 대타일 전체에 마름모 테두리를 그리고, 그 안의 소타일에도 더 작은 마름모 테두리를 항상 그린다. 두 테두리는 색과 두께를 달리한다.
- 커서 이름은 `평지(숲)`처럼 `소타일 이름(대타일 이름)`이다. `$`는 화면에 표시하지 않는다. 좌표와 `외곽` 여부는 오른쪽 패널에 표시한다.
- 병력 배치 탭에서도 두 커서를 유지한다. 실제 배치 강조는 대타일 전체에 적용한다.
- 브러시는 기존 지형 자료에서 가져온다. 기본 순서는 평지, 황무지, 물, 숲, 산, 마을, 성벽, 성내, 다리, 성문, 주둔지이다. 성을 단일 브러시로 뭉치지 않고 기존 게임 종류를 구분한다.
- 단축키는 1~9, 0을 첫 10개에 할당하고, 이후 q,w,e,r,t,y,u,i,o,p 순서로 확장한다. 각 항목에 키를 표시한다. 더 늘면 다음 문자 행과 스크롤을 사용하며 키가 중복되지 않게 한다.
- 좌클릭/드래그는 소타일 칠하기다. 빠르게 움직여도 지나간 칸을 연결해서 빠짐없이 칠한다. 드래그 한 번이 실행 취소 한 번이다.
- 타일 탭 우클릭은 해당 소타일 종류를 브러시로 가져온다. 병력 탭 우클릭은 제거다. 현재 동작을 하단 도움말에 표시한다.
- 좌측 하단 탭을 누르거나 Tab으로 `타일 ↔ 병력 배치`를 전환한다. 팝업과 텍스트 입력 중에는 탭 전환·브러시 단축키가 실행되지 않는다.
- 카메라는 중간 버튼 드래그 또는 Space+좌드래그로 이동한다. 휠은 지도에서 줌, 브러시/팝업 위에서 목록 스크롤이다. 브러시 문자 키와 WASD 이동이 충돌하지 않게 한다.
- Ctrl+S 저장, Ctrl+Z 실행 취소, Ctrl+Shift+Z 다시 실행, Esc 팝업 닫기를 제공한다. 조합키 처리 시 같은 문자의 브러시가 선택되지 않는다.

### 네 모서리로 전투 영역 크기 변경

- 전투 영역의 네 꼭짓점에 드래그 손잡이를 표시한다. 화면상 위치와 격자 축이 다르므로 좌상·좌하·우상·우하 손잡이에 대응하는 경계를 표시한다. 역투영으로 두 격자 축의 경계를 조정한다.
- 드래그한 꼭짓점의 반대 꼭짓점은 고정한다. 대타일 1칸 단위로 스냅하며 변경 중 `14×10 → 16×12`처럼 크기를 보여준다.
- 왼쪽/위쪽 확장도 월드 좌표 기준으로 처리한다. 기존 지형과 병력의 월드 위치를 유지하고, 전투 자료를 생성할 때 새 전투 원점을 빼서 엔진 좌표로 정규화한다.
- 확대 시 기존 외곽 지형이 전투 영역에 편입된다. 그림 자료가 부족한 부분은 기본 지형으로 채운다. 축소해도 지형 그림은 외곽으로 남는다.
- 크기 조절 드래그가 끝나 마우스를 놓으면 **항상 예/아니오 확인창**을 연다. 확대, 축소, 제거 대상이 없는 경우에도 확인한다. 변경 크기와 제거될 병력·아군 배치 칸을 미리 표시한다. `예`이면 크기 변경을 확정하고 영역 밖 배치를 삭제한다. `아니오`이면 드래그 전 크기와 배치를 유지한다. 확인 전에는 원본 문서에서 배치를 삭제하지 않고 자동으로 다른 위치에 옮기지도 않는다.
- 보스나 일기토 대상 제거로 시나리오 참조가 깨지면 저장·시험 전투를 막고 수정할 항목을 표시한다.
- 지원 크기는 대타일 가로/세로 각각 4~64칸으로 확정한다. 최대 크기 렌더링 검사 결과에 맞춰 정적 지면 캐시 크기를 제한한다. 손잡이가 화면 밖이면 축소 줌/영역 맞춤 기능으로 접근한다.

## 5. 병력 배치

### 아군 배치 가능 칸

- 아군 모드는 실제 장수를 넣는 대신 대타일에 `아군 배치 가능` 표시를 넣는다. 좌클릭/드래그로 추가, 우클릭/드래그로 제거한다.
- 실제 출전 장수 선택은 게임의 기존 출전 흐름에 맡긴다. 기존 `Stage.Allies`로 내보낸다.
- 전투 영역 밖, 적과 겹치는 칸은 배치할 수 없다. 이동 불가능 지형과 배치 칸 수 부족도 검증한다. 병종별 통행 차이가 있으므로 모든 출전 후보가 사용 불가능한 칸은 오류, 일부만 사용 가능한 칸은 경고와 상세 설명을 제공한다.
- 고정 아군 `Stage.Party`가 있는 전투맵은 이를 읽고 보존하며 별도 표시한다. 배치 가능 칸으로 임의 변환하지 않는다.

### 적 유닛 선택

하단 병력 창은 다음 순서로 구성한다.

1. 아군 배치 칸 / 적 병력 모드.
2. 계열: 보병, 기병, 궁병, 사마, 적병, 무인 등.
3. 해당 계열의 병종: 예를 들어 경보병, 중보병, 근위병, 장창병, 전차대.
4. 레벨: 게임의 최대 레벨 규칙 안에서 선택.
5. 초기 방향: 스프라이트의 지원 방향 8종을 화살표와 유닛 미리보기로 선택.
6. `[일반병] [장수]` 선택 버튼.

계열은 전투용 이동 그룹과 별도 메타데이터로 정의한다. 실제 구현된 병종만 선택할 수 있다. 미구현 병종도 계열 내 목록에는 표시하되 **비활성화**하고 `미구현` 표시를 붙인다. 해당 항목은 선택·배치·시험 전투에서 사용할 수 없다. 목록 메타데이터와 실행 가능한 클래스 정의를 구분하며, 이번에는 없는 병종을 구현하지 않는다.

### 일반병

- 선택한 계열·병종·레벨·방향으로 빈 대타일에 좌클릭하면 배치한다. 브러시를 유지해 여러 칸에 연속 배치할 수 있다.
- 일반병은 템플릿을 사용하며 각 배치에 고유 인스턴스 ID를 부여한다. 같은 템플릿을 여러 번 사용해도 개별 상세 설정이 섞이지 않는다.
- 드래그 연속 배치 중 이미 병력이 있는 칸은 건너뛴다. 첫 좌클릭이 기존 병력 위에서 시작되면 그 병력의 상세창을 연다.
- 우클릭/드래그는 해당 대타일의 적 배치를 제거한다.

### 장수 팝업

- 장수 버튼을 누르면 선택한 계열에 속한 장수의 초상화 팝업을 연다. 화면 크기에 맞춘 N×M 표에 초상화, 이름, 기본 병종을 표시하고 스크롤한다.
- 위쪽 진영 탭은 유비군, 조조군, 손권군, 원소군, 동탁군, 기타 순서다. 계열 필터와 진영 필터를 함께 적용한다. 이름 검색도 제공한다.
- 현재 `Look.Faction`은 그림 색상용이다. 장수의 소속 진영을 색상만으로 추측하지 않고 편집기용 명시적 진영 메타데이터를 추가한다. 미분류 장수는 기타로 표시한다.
- 장수를 선택하면 팝업을 닫고 배치 브러시가 된다. 빈 대타일 좌클릭으로 배치하고 기존 병력 좌클릭으로 상세창을 연다. 우클릭으로 제거한다.
- 같은 이름 있는 장수는 한 전투에 한 번만 배치한다. 이미 배치된 장수는 팝업에서 위치를 표시하며 중복 배치를 막는다. 아군 출전 후보와 충돌하는 적 장수도 검증한다.
- 장수의 고유 능력치·초상화·고유 외형을 유지한다. 병종 변경은 선택한 계열 안에서 허용하고 다른 계열로 변경하는 것은 막는다. 변경 시 미리보기와 장비 호환성을 다시 계산한다. 같은 장수는 중복할 수 없지만 일반병 템플릿은 반복 배치할 수 있다.

### 배치 상세 설정

배치 직후 오른쪽에 상세 정보를 표시하되 일반병 연속 배치를 막는 모달은 열지 않는다. 기존 병력을 클릭하면 동일 패널에서 편집한다.

| 항목 | 동작 |
|---|---|
| 이름/템플릿 | 장수 또는 일반병 원본 표시 |
| 계열·병종·레벨 | 선택값 재정의, 파생 능력치 재계산 |
| 방향 | 초기 바라보는 방향과 미리보기 |
| 병력량 HP | 현재값 설정, 산출된 최대 HP 표시 |
| 병법치 MP | 현재값 설정, 산출된 최대 MP 표시 |
| 특성 | 배치별 부여 특성 선택; 병종·장비 자동 특성은 출처 표시 |
| 장비 | 무기, 방어구, 장신구; 병종에 호환되는 목록만 선택 |
| 초기화/적용 | 원본 기본값 복원 또는 해당 배치에 적용 |

- `미지정`과 명시적인 `0`을 구분한다. 현재 엔진의 적 기본값인 HP 최대/MP 0을 그대로 표현할 수 있어야 한다.
- HP·MP는 시작 현재값만 설정한다. 최대값 직접 편집은 제공하지 않으며 레벨·병종·특성·장비에 따라 엔진에서 산출한다.
- HP는 1~최대 HP, MP는 0~최대 MP 범위로 검증한다. 레벨·장비 변경으로 최대값이 감소하면 초과값을 표시하고 적용 시 정리한다.
- 기본 능력치 산출은 엔진과 같은 함수를 사용한다. 에디터가 별도 공식으로 HP·MP를 계산하지 않는다.
- 장비 슬롯 중복, 병종 비호환, 존재하지 않는 ID, 특성 선행 조건을 검증한다. 클래스/장비 자동 부여 특성을 수동 목록과 중복 적용하지 않는다.
- 설정은 캐릭터 원본 정의가 아닌 해당 배치의 재정의다. 다른 맵이나 다른 일반병에 전파되지 않는다.
- 방향은 관찰값과 GUI 초기 상태까지 전달한다. 전투 시작이나 재생 동기화가 기본 아군/적 방향으로 덮어쓰지 않도록 한다.

## 6. 자료와 저장 구조

### 편집 원본

새 편집 원본 하나에서 게임용 자료와 그림 자료를 함께 만든다. 필드명은 구현 단계에서 기존 JSON 스타일에 맞추되 다음 정보를 갖는다.

```text
MapDocument
  Version, ID, Name
  PlayRect                전투 대타일 영역: 월드 원점 + 너비/높이
  VisualRect              그림 소타일 영역: 월드 원점 + 너비/높이
  SmallTiles              소타일별 지형 ID
  ResolvedTiles           대타일의 현재 판정: 동률 유지와 저장/복원에 사용
  Decorations/Props       나무·장식의 앵커, 종류, 방향, 배율 분류
  AlliedDeployment        아군 배치 가능 대타일 목록
  EnemyPlacements         고유 배치 ID, 원본 ID, 위치, 개별 재정의
  FixedParty              기존 고정 아군 배치
  StageMetadata           보스, 승리 조건, 일기토, 제한 턴, 보상, 다음 노드
  Seed                    결정적인 장식 변형 선택용
```

- 소타일 지형과 대타일의 현재 판정을 함께 저장한다. 단독 최다일 때만 갱신하고 동률일 때는 유지하므로 대타일 판정은 필요한 상태값이다. 판정만 직접 바꾸는 별도 브러시는 제공하지 않는다.
- 편집기에서 그림만 보이는 외곽도 원본에 포함한다. 실행 자료의 `Stage.Tiles`는 전투 영역만 포함한다.
- 기존 맵은 대타일 지형을 소타일 4개로 복제한다. 기존 장식과 고정 배치를 읽고, 새 외곽을 생성한다. 기존 전투 규칙과 배치 좌표를 보존한다.
- 내부 ID는 기존 영문 ID/지형 기호를 쓰고 화면 이름만 한글로 표시한다. 타일 종류나 장수 이름을 엔진 코드에 하드코딩하지 않는다.

### 단일 문서 저장

- `assets/data/maps/<ID>.json` 한 파일을 에디터와 게임에서 함께 사용한다.
- 저장 전 검증 후 임시 파일을 작성하고 원자적으로 교체한다. 실패하면 기존 문서는 그대로 유지한다.
- 전투용 Stage와 그림은 로드 시 메모리에서 계산한다. 별도 내보내기·맵 빌드 명령·중복 실행 자료는 없다.
- 저장한 기존 전투맵은 캠페인에 적용한다. 새 ID의 캠페인 연결은 시나리오 노드를 별도로 작성한다.
- 미완성 맵의 초안 파일은 따로 저장하지 않는다. 검증 오류가 있으면 편집 내용이 유지되며 적용 가능한 맵만 저장한다.

### 기존 파이프라인과의 관계

- `internal/content`는 데이터 정의·검증, `internal/core`는 게임 규칙, `internal/gui`는 화면과 입력을 계속 담당한다.
- 신규 `internal/mapedit`는 Ebitengine에 의존하지 않는 편집 문서·좌표·지형 집계·변경 이력·컴파일을 담당한다. GUI 편집 화면은 별도 파일로 분리한다.
- 맵용 별도 명령은 두지 않는다. 에디터와 콘텐츠 로더가 공유 문서를 직접 사용한다.
- 공용 런타임 그림은 `assets/`, 공유 맵 문서는 `assets/data/maps/`에 둔다. 실제 그림 원본은 기존 자산 종류별 파이프라인에 둔다. `tools/spritetool`에 게임 전용 변환을 추가하지 않는다.
- 소재 제작이 필요해지면 먼저 `SPRITE_ART_GUIDE.md`와 해당 자산의 설정/README를 읽는다. 유닛 그림을 변경할 경우 `UNIT_ART_GUIDE.md`와 `tools/unit3d/`를 따른다. 이 계획 자체에는 유닛 재제작을 포함하지 않는다.

## 7. 시험 전투와 검증

편집 화면에서 현재 미저장 문서를 컴파일해 독립된 시험 세션을 연다. 아군 출전 선택을 거쳐 실제 전투를 시험하고 에디터로 돌아올 수 있다. 기존 캠페인의 병력·아이템·저장 상태를 변경하지 않는다.

저장 및 시험 전투 전 검사:

- 전투/그림 크기, 소타일 배열 수, 지형 ID, 모든 대타일의 4개 소타일 존재 여부.
- 지형 집계와 실행 `Stage.Tiles`의 일치.
- 배치 범위·중복 점유·장수 중복·레벨·HP·MP·특성·장비·방향의 유효성.
- 아군 배치 공간, 적 수, 고정 아군과의 충돌, 승리 조건에 필요한 보스 존재 여부.
- 보스·일기토·보상·다음 노드 등 기존 시나리오 참조의 유효성.

치명적인 오류는 저장된 실행 자료 생성/시험을 막고 메시지 영역에 첫 오류와 관련 좌표를 안내한다. 미완성 편집 내용은 에디터에 유지하며 적용 가능한 맵만 저장한다.

## 8. 단계별 구현

각 단계는 단독 검증 가능한 결과를 만든다. 아래 체크는 구현 완료 후 표시한다. 복잡한 단계는 1~4시간 정도의 작업 단위로 나누되 전체 일정은 첫 렌더링 시제품과 소재 연결 검사 후 산정한다. 단계가 끝나면 검증 결과와 발견한 제약을 이 문서에 기록하고 다음 단계로 진행한다.

### 1단계 — 편집 문서와 지형 컴파일

- [x] 지형 집계·동률·음수 좌표·전투 원점 변환 테스트를 먼저 작성한다.
- [x] `internal/mapedit` 문서와 공통 좌표 변환, 실행 자료 컴파일을 구현한다.
- [x] 기존 맵을 소타일 문서로 이관하고 시나리오 메타데이터를 보존한다.
- [x] 문서 버전·검증 오류 안내·기본 외곽 생성 규칙을 정의한다.

완료 기준: 기존 전투맵의 지형과 배치가 이관 전후 같고, 3:1·2:1:1의 변경, 2:2·1:1:1:1의 기존 판정 유지, 음수 좌표 테스트가 통과한다. 드래그 중 판정 변화와 저장·로드·실행 취소도 동일한 판정을 보존한다. 집계·좌표·문서 검증 로직의 테스트 커버리지는 80% 이상을 목표로 한다.

### 2단계 — 세밀한 렌더링과 외곽

- [x] 게임 칸 크기와 그림 배율을 분리한다. 먼저 B01 한 장으로 비교한다.
- [x] 소타일 지면 연결, 구조물 축소·연결·높이, 나무 크기 보존을 구현한다.
- [x] 어두운 외곽, 그림 영역 밖 지면 연장, 외곽 전투 입력 차단을 구현한다.
- [x] 움직이는 요소의 화면 범위 렌더링과 정적 지면 캐시를 적용한다. 지면 편집 시에는 전체 캐시를 재생성한다.

완료 기준: 유닛과 대타일 크기를 유지하며 지면 픽셀만 세밀해지고, 나무 크기가 이전과 같다. 성벽 위 유닛·물 애니메이션·외곽 그림자·가림 표시가 정상이다. 이동/사거리/지형 회복 계산에 변화가 없다. 대형 맵 메모리와 프레임 시간을 측정한다.

### 3단계 — 메뉴와 타일 편집

- [x] 시작 메뉴에 맵에디터와 전투맵 선택 화면을 추가한다.
- [x] 중첩 커서, `소타일(대타일)` 이름, 오른쪽 지형 정보 패널을 구현한다.
- [x] 브러시·숫자/문자 단축키·Tab 탭 전환·카메라 조작을 구현한다.
- [x] 연속 칠하기, 입력 소비 우선순위, 실행 취소/다시 실행을 구현한다.

완료 기준: 실제 소타일을 수정하면 대타일 판정과 패널이 즉시 바뀐다. 팝업/입력창 조작이 지도 칠하기로 전달되지 않는다. 외곽도 편집되고 드래그 한 번을 한 번에 취소할 수 있다.

### 4단계 — 전투 영역 크기 변경

- [x] 네 꼭짓점 역투영·스냅·원점 변경·배치 좌표 보존 테스트를 작성한다.
- [x] 네 모서리 손잡이, 크기 미리보기, 영역 맞춤을 구현한다.
- [x] 확대 시 외곽 편입, 드래그 종료 시 항상 예/아니오 확인, 축소 영향 미리보기와 확정 후 제거를 구현한다.
- [x] 크기 변경 전체를 하나의 실행 취소 작업으로 처리한다.

완료 기준: 네 모서리에서 확대/축소해도 기존 병력의 월드 위치가 유지된다. 좌상 방향 확대 후 게임용 좌표가 올바르다. 축소 취소·실행 취소로 지형과 배치가 정확히 복구된다.

### 5단계 — 아군 칸과 일반병 배치

- [x] 계열 메타데이터와 병종/일반병 템플릿 목록을 정리하고 미구현 병종을 표시하되 비활성화한다.
- [x] 아군 가능 칸, 일반병 레벨·방향·연속 배치·제거를 구현한다.
- [x] 배치별 병종·방향·HP·MP 재정의를 `Spawn`과 엔진 초기화에 연결한다.
- [x] 기본값과 0 구분, 고유 인스턴스, 점유·배치 검증 테스트를 작성한다.

완료 기준: 여러 일반병이 서로 독립된 설정으로 배치되고, 시험용 엔진에서 같은 병종·HP·MP로 생성된다. 아군 칸은 장수를 고정하지 않는다. 기존 재정의 없는 전투맵의 초기화 결과를 유지한다.

### 6단계 — 장수 팝업과 상세 설정

- [x] 진영 메타데이터와 계열 필터를 추가한다.
- [x] N×M 초상화 표, 진영 탭, 검색, 선택 및 중복 방지를 구현한다.
- [x] 기존 배치 선택과 신규 배치를 구분하는 입력 처리를 구현한다.
- [x] 특성·장비 상세 설정과 엔진 파생 능력치 미리보기를 연결한다.
- [x] 방향 관찰/재생 전달과 보스·일기토 참조 검증을 구현한다.

완료 기준: 원하는 진영·계열 장수를 골라 배치하고 설정할 수 있다. 중복 장수와 호환되지 않는 장비는 차단된다. 설정 변경이 원본 캐릭터나 다른 배치를 바꾸지 않으며 실제 전투와 미리보기 수치가 같다.

### 7단계 — 저장, 시험 전투

- [x] Git 관리 파일에 맵 저장·불러오기·다른 이름 저장과 캠페인 즉시 적용을 구현한다.
- [x] 콘텐츠 로더와 GUI가 한 문서에서 대타일 판정과 그림을 메모리로 계산한다.
- [x] 단일 파일 안전 저장과 변경 내용 이탈 확인을 구현한다.

- [x] 세이브/리플레이 버전 검사와 README 사용법·파이프라인을 갱신한다.

완료 기준: 편집→저장→재시작→로드→시험 전투의 결과가 일치하고, 같은 ID의 캠페인 전투에도 수정이 적용된다. 쓰기 실패 시 이전 맵과 편집 내용이 보존된다. 시험 전투 때문에 캠페인의 병력·아이템·진행 상태가 변경되지 않는다.

## 9. 검증 방법과 위험 관리

관련 패키지 테스트를 단계별로 실행한다. 문서 작성 단계에서는 신규 구현이나 테스트를 실행했다고 기록하지 않는다.

```sh
go test -v ./internal/mapedit/...
go test -v ./internal/content/... ./internal/core/... ./internal/session/...
go test -v ./internal/gui/...
go vet ./internal/mapedit/... ./internal/content/... ./internal/core/... ./internal/session/... ./internal/gui/...
```

성능 측정이 필요한 렌더링 변경에는 좌표 집계/컴파일·캐시 생성 벤치마크를 추가한다. GUI 프레임 시간과 GPU 메모리는 실제 실행에서 별도 측정한다. 기본 B01과 최대 지원 맵을 비교하고 결과를 기록한다.

```sh
go test ./internal/mapedit/... -bench Benchmark -benchtime 1000x -benchmem
```

| 위험 | 대응 |
|---|---|
| 배율만 줄여 빈틈이나 좁은 유닛 칸 발생 | 대타일 크기 고정, 원본 배율 지면 재구성, B01 시제품부터 비교 |
| 연결 소재 부족 | 성벽/성문/다리 조합을 먼저 확인하고 필요한 소재 목록 작성 |
| 외형과 게임 지형이 다르게 느껴짐 | 중첩 커서·판정 구성·동률 이유와 실제 효과 표시 |
| 외곽 때문에 이동/물 조건이 달라짐 | 엔진은 전투 영역과 산출된 대타일만 사용 |
| 큰 맵에서 캔버스·물 프레임 메모리 급증 | 보이는 범위/변경 영역 캐시, 최대 크기 실측 후 제한 확정 |
| 맵 축소로 보스/배치/일기토 손실 | 영향 미리보기, 취소 가능, 참조 오류 시 게임 적용 차단 |
| 편집 미리보기와 엔진 능력치 불일치 | 동일 콘텐츠와 엔진 계산 경로 사용, 초기화 통합 테스트 |

| 저장 전투에 다른 수정맵 적용 | 맵 버전/콘텐츠 해시 검사, 세션별 맵 스냅샷 고정 |

단계별 변경을 독립된 커밋으로 남긴다. 렌더링 전환이 실패하면 이전 렌더링으로 복귀하되 편집 원본은 유지한다. 공유 맵 문서를 Git으로 관리하여 이전 커밋으로 롤백한다. 저장 실패 시 이전 문서를 유지한다.

### 최종 수동 확인 시나리오

- [ ] 시작 메뉴에서 B01을 선택하고 소타일 하나를 황무지로 칠한다. 커서와 오른쪽에 황무지(평지)가 표시된다.

- [ ] 2:1:1이면 단독 최다 종류로 변경되고, 2:2와 1:1:1:1이면 기존 판정이 저장·로드·실행 취소 후에도 유지되는지 확인한다.
- [ ] 맵 외곽을 숲으로 바꾼다. 전투에서는 어둡고 선택 불가능하며 나무 크기는 기존과 같다.
- [ ] 네 모서리를 각각 드래그한다. 마우스를 놓을 때마다 예/아니오 창이 나오고, 예일 때만 변경과 영역 밖 배치 삭제가 확정된다. 아니오와 실행 취소로 복구된다.
- [ ] 단축키 0과 q로 10번째·11번째 브러시를 선택하고 Tab으로 병력 탭을 연다.
- [ ] 아군 칸을 표시하고 일반병 여러 명을 배치한다. 기존 유닛 클릭은 상세 선택, 우클릭은 제거다.

- [ ] 쓰기 실패와 유효하지 않은 보스 참조를 확인한다. 오류를 보여주고 편집 내용을 유지한다.

### 단일 문서 및 편집 조작 보강 (사용자 요청)

### 로그·상태 그래픽 보강

- 전투 로그 삽입은 큐에 적재하고 화면 프레임마다 한 항목만 표시한다. 전투를 떠나거나 새 맵으로 넘어가면 표시 기록과 대기 큐를 비운다.
- 스크롤바 드래그·트랙 클릭과 기존 휠을 함께 지원한다. 과거 기록을 보는 동안 새 항목이 들어와도 읽던 위치를 유지한다.
- 에디터의 우클릭 제거/가져오기는 버튼을 놓을 때 처리한다. 우드래그는 카메라 이동이므로 병력 삭제와 충돌하지 않는다.
  지도 화면 가장자리에서도 스크롤하며, 팝업과 크기 조절 중에는 스크롤하지 않는다.
- 유닛을 기준으로 하지 않는 지형 정보는 진입 불가나 보정 0%를 표시하지 않는다.
- 다리와 성내 바닥을 물 애니메이션 뒤에 그려 물 지면이 덮어쓰지 않도록 한다.
- 독은 초록빛, 속박은 그물, 봉격은 칼/X, 혼란은 회전 표시, 봉책은 문서/X, 화상은 불꽃으로 표시한다.
  강화·약화는 발밑 중앙 정렬 화살표로 표시한다. 공격 빨강, 방어 파랑, 정신 초록, 순발·사기 노랑, 이동 흰색이며 노랑 두 종류는 작은 기호로 구분한다.
