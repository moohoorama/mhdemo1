# 병력·피해 표시 배율 계획

## 목표와 원칙

병력과 그 증감량의 기본 표시를 내부 수치의 1/6로 바꾼다. 첫 출전의 유비·관우·장비 병력 합계가 약 500으로 보이게 한다. 디버그 설정에서 배율을 바꿔 비교한다. 전투 계산, AI, 경험치, 저장된 전투 상태와 기존 데미지 배율은 바꾸지 않는다.

## 설계

- 설정에 표시 배율을 분수 단위로 저장하고 기본값을 1/6으로 한다. 디버그 UI에는 예를 들어 1/1, 1/2, 1/4, 1/6, 1/10을 제공한다. 저장된 설정에 값이 없으면 1/6이다. 설정은 게임 저장이 아닌 기존 사용자 설정에 둔다.
- 병력의 현재값·최대값과 피해·회복 등 병력 변화량을 같은 변환 함수로 표시한다. 0은 0, 양수는 가장 가까운 정수로 반올림하되 살아 있는 병력과 0이 아닌 변화량은 최소 1로 표시한다. 부호는 유지한다. 이때 반올림 때문에 표시 전후 차이와 표시된 피해가 1 이상 다를 수 있다. 게이지 길이와 사망 판정은 원래 값으로 계산한다.
- 적용 대상은 아군·동맹·적 모두의 HUD, 부대 상세·병력일람·편성 및 관리 화면, 전투 예측, 떠오르는 피해·회복 숫자, 전투 로그, 아이템·책략·특성의 고정 병력 수치와 그 설명이다. 퍼센트·공격력·방어력·병법치·경험치·레벨은 변환하지 않는다. 실제 출력 경로를 검색해 누락을 점검한다.
- 이벤트가 문자열로 조립되기 전에 구조화된 병력 증감값만 변환한다. 모든 숫자에 일괄 적용하거나 텍스트를 정규식으로 재해석하지 않는다. GUI 외 CLI 및 JSON 인터페이스는 사용처와 계약을 확인한 후 범위를 정한다. 기계용 원시 데이터는 유지하고 사람용 출력에는 동일 규칙을 적용한다.

## 단계와 검증

각 단계는 독립 실행 가능해야 하며 완료 후 해당 테스트와 빌드를 통과한다. 체크 항목은 구현 시 갱신한다.

### 1. 설정과 변환 (1~3시간)

- [ ] `internal/storage`에 기본값·허용 선택지·저장과 불러오기를 추가하고 기존 설정 호환을 검증한다.
- [ ] 표시 변환 함수에 0, 작은 양수, 음수, 반올림 경계와 1/1 테스트를 추가한다.
- [ ] 디버그 설정에 선택지를 추가하고 일반 모드에서 숨김을 검증한다.
- [ ] 설정 화면을 캡처해 선택지와 다른 설정이 겹치지 않는지 확인한다.

### 2. 병력 화면과 예측 (1~4시간)

- [ ] HUD, 장수 상세, 병력일람, 편성·관리, 전투 예측의 병력 값을 변환한다. 정렬과 게이지는 원래 값 기준으로 유지한다.
- [ ] 아군과 적, 현재·최대·예측 병력 및 1/1·1/6 설정을 검증한다.
- [ ] 첫 출전 GUI를 캡처해 세 장수의 합계가 약 500인지 확인한다.

### 3. 전투 결과와 설명 (1~4시간)

- [ ] 실제 피해·회복 애니메이션과 전투 로그의 병력 변화량을 변환한다. 광역·지속 피해와 회복도 확인한다.
- [ ] 고정 병력 수치를 표시하는 아이템·특성·책략 설명을 조사해 동일하게 변환한다. 비율 표현은 유지한다.
- [ ] 예측·결과·로그의 동일 사례 및 소량 피해 경계를 테스트하고 GUI 캡처로 확인한다.

### 4. 누락 검사와 마무리 (1~3시간)

- [ ] CLI의 사람용 표시와 기계용 JSON 계약을 확인하고 적용 범위를 문서화한다.
- [ ] `HP`, `MaxHP`, 피해·병력·회복 출력 경로를 검색해 누락을 점검한다.
- [ ] 관련 패키지 테스트 및 빌드를 실행하고, 디버그 설정 변경 후 저장·재시작을 확인한다.
- [ ] 사용법과 `docs/history.md`를 갱신한다.

## 위험과 복구

| 위험 | 영향 | 대응 |
|---|---|---|
| 출력 경로 누락 | 화면마다 수치가 달라 보임 | 구조화된 수치별 호출부 조사와 화면별 캡처 |
| 반올림 불일치 | 표시 피해와 병력 차이가 다름 | 위의 규칙을 테스트하고 검수 |
| 표시값이 계산에 유입 | 전투 밸런스 변화 | 변환을 출력 경계에만 적용하고 원본 상태 비교 테스트 |
| 설정 창 공간 부족 | 항목 겹침 | 디버그 창 캡처 후 필요시 배치 조정 |

문제 발생 시 해당 단계의 표시 호출과 설정 추가를 되돌린다. 내부 전투 상태와 저장 형식은 수정하지 않으므로 전투 저장 마이그레이션은 필요 없다.
