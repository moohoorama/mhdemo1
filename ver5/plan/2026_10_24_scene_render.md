# 장면 렌더링 규칙 확립과 장면 맵 형식 단순화

작성일: 2026-10-24
기준 구현: `cmd/_scene`(사용자가 만든 브라우저 뷰어, `go run ./cmd/_scene`)

## 1. 목표

장면(이야기 화면) 맵을 **"칸마다 무엇이 놓였는지"만 적은 작은 데이터**로 바꾸고, 나머지는 정해진 규칙으로 그린다.
- 그리는 순서와 그림 선택을 규칙 하나로 정한다. 맵마다 그때그때 보정하는 예외를 없앤다.
- 장면 맵 JSON을 지금의 수백 KB에서 수 KB로 줄인다.
- 뷰어(`cmd/_scene`)와 게임 렌더러(`internal/gui`)가 같은 규칙으로 같은 그림을 낸다.

**최종 확인 기준**: 기존 맵을 장식 없이 그린 그림과, 새 형식을 규칙으로 장식 없이 그린 그림이 같아야 한다. 같다는 것이 확인되면 그 위에 장식 규칙을 얹는다. 장식(풀 포기, 그림 변형 등)은 기존과 달라져도 괜찮다.

## 2. 지금의 문제 (근거)

### 2.1 그리는 순서
`cmd/_scene/static/viewer.js`의 `render()`는 바닥 타일과 물체를 한 목록에 넣고, 기준점 한 점의 화면 y로만 정렬한다.
- 바닥 타일이 물체보다 나중에 그려져 물체를 덮는다.
  - 탁자 `desk`(높이 20px, 기준점 14px)는 아래 6px가 가려진다.
  - 관청 `hall_u`(78px, 기준점 56px)는 아래 22px가 가려진다.
- 군막 `S_tent_mid`는 바닥 타일이 전부 풀밭이고, 마루 `floor_tent`를 소품으로 깐다.
  - 마루 앞쪽 절반을 풀밭 타일이 덮는다.
  - 마루 그림은 62×32라 64×32 칸보다 좁아서 가장자리로 풀이 비친다.
- 여러 칸을 차지하는 건물도 점 하나로 정렬되어, 그 위에 선 사람·소품과의 앞뒤가 틀어진다.
- 그림마다 기준점 위치가 제각각이라 순서가 기준점에 따라 바뀐다. 그래서 성문·절벽에 "반 칸 늦게 그리기" 같은 예외가 붙었다.

### 2.2 맵 크기
장면 맵 40개가 합쳐 3.7MB이고, 큰 것은 250KB 안팎이다(`S_road` 254KB).
- 92%(3.4MB)가 `ground`다. `tools/scene_maps/build.py`가 칸 글자 격자(`small_tiles`)에서 규칙(`mask`·`ground_layers`)으로 계산한 타일 그림 목록을 그대로 저장한 것이다. 같은 규칙으로 그릴 때 계산하면 저장할 필요가 없다.
- 풀 포기 `decorations`(175KB)도 무작위 위치를 하나하나 적어 둔 것이다.
- 정작 사람이 정한 정보는 작다: `small_tiles` 61KB, `highland` 6KB, 관문의 `small_props` 1KB.
- 비교: 전투 맵(`assets/scenario/hero/maps/mapNN.json`)은 같은 방식(글자 배치 → 규칙으로 이음)으로 11~28KB다.

## 3. 렌더링 규칙

### 3.1 세 단계로 그린다

| 단계 | 그리는 것 | 순서 |
|---|---|---|
| 1. 평면층 | 높이 0의 바닥 타일 → 바닥 물체(`layer: ground`: 마루, 포석, 길) → 바닥 장식(풀 포기) → 바닥 그림자(물체 그림자, 절벽 밑동 띠) | 정렬하지 않고 이 순서대로 전부 먼저 그린다 |
| 2. 입체층 | 세워진 물체, 높은 땅 블록(윗면·옆면), 성벽·성문 조각, 사람 | 3.2의 규칙으로 정렬 |
| 3. 덧그림층 | 가려진 사람의 반투명 표시, 효과, 커서·선택 표시 | 마지막 |

바닥은 입체층의 어떤 것도 덮지 않는다.

### 3.2 입체층 정렬
- 모든 물체는 차지하는 바닥 칸(footprint)을 가진다. 작은 칸 단위 `[U, V, 폭, 깊이]`, 기본 1×1.
- 정렬 키: `(footprint 앞 모서리의 U+V, 높이, 종류 순위, 화면 x)`
  - 종류 순위: 땅 옆면 < 성벽·성문 < 소품 < 사람 (같은 칸일 때의 기본 순서)
- 여러 칸짜리 물체가 다른 물체와 화면에서 겹칠 때만 footprint끼리 비교한다. 한쪽 footprint가 다른 쪽보다 완전히 뒤(U 또는 V가 작은 쪽)면 먼저 그린다.
- 그림의 기준점(pivot)은 화면에 놓는 위치에만 쓰고 순서에는 쓰지 않는다.

### 3.3 높은 땅과 면
- 높이 격자의 칸 하나는 "윗면 + 보이는 옆면(SW·SE)"을 가진 블록 하나다. 그 칸의 깊이로 입체층에서 정렬한다.
- 블록 윗면 위의 사람·물체는 높이만큼 올려, 같은 칸에서 블록 다음에 그린다.
- 면에 얹는 덧그림(삼각형 그림자 `jshade`, 외곽선)은 독립 물체가 아니라 그 면 항목에 묶어, 면을 그린 직후 그린다.

### 3.4 그림 선택
- 땅 경계 이음: 이웃 칸 글자로 고른다(지금 `build.py`의 `mask`·`ground_layers` 규칙을 옮긴다).
- 절벽 옆면·모서리: 높이 격자의 차로 고른다.
- 그림 변형과 장식: 칸 좌표로 정해지는 난수(시드 고정)로 고른다. 같은 맵은 언제나 같은 그림이 나온다.
- 맵 바깥 여백: 가장자리 칸을 이어서 그린다.

## 4. 새 장면 맵 형식

맵에는 세 가지만 적는다.
1. **땅 격자** `ground`: 작은 칸마다 글자 하나(`.` 풀, `d` 흙, `~` 물, `i` 포석, 실내 바닥 종류 등). 여백 범위까지 포함하거나, 여백은 규칙으로 잇는다.
2. **높이 격자** `height`: 작은 칸마다 높이 단계(0, 한 단, 높은 절벽 …).
3. **물체 목록** `objects`: `[이름, U, V, (방향), (미세 위치 dx, dy)]`. 성벽은 줄(`[시작, 끝, 축]`)로 적고 성문은 그 줄 위의 위치로 적을 수 있다.

물체 정보(그림, 기준점, footprint, 층, 그림자 여부)는 맵이 아니라 소품 목록(`tiles.json` → `index.json`)에 둔다. 실내 바닥(마루, 깔개)은 소품이 아니라 땅 글자로 둔다.

## 5. 단계

### 1단계: 뷰어를 기준 구현으로 (cmd/_scene)
- 3장의 규칙으로 뷰어를 고친다.
- 4장의 새 형식을 읽어 그리게 한다. 기존 형식도 계속 읽는다(비교용).
- 확인용 표시를 넣는다: footprint 윤곽, 정렬 번호, 단계별 보기(평면층만, 입체층까지, 전체), 장식 켜기/끄기.
- 맵 데이터와 뷰어에 있는 옛 예외를 함께 뺀다.
  - 앞 절벽을 반 칸 늦게 그리는 `lcliff_*`
  - 안 A를 반쯤 넣다 멈춘 흔적(`swall_*_up`, 늘린 성벽 줄)
  - 뷰어의 `hidden()`·`normalize()`·`turnName()` 안 예외
- 시험 맵 셋을 새 형식으로 만든다: `S_checkpoint`(관문), `S_tent_mid`(군막), `S_castle_town`(영천 성 안 민가).
  - 새 형식 데이터는 레포의 `assets/graphics/maps/`에 바로 쓴다(사용자 결정, 2026-10-24). 게임도 이 파일을 읽으므로, 게임 로더가 새 형식을 읽게 될 때까지(3단계) 이 세 맵은 게임에서 어색하거나 깨질 수 있다. 1단계와 3단계를 이어서 진행해 그 기간을 짧게 한다.
- **검사 도구**: 같은 맵을 (가) 기존 데이터로 장식 없이, (나) 새 형식을 규칙으로 장식 없이 그려 픽셀을 비교하고 차이 부분을 표시한다. 차이는 정렬 규칙을 고쳐서 생긴 의도된 차이(바닥이 물체를 덮던 것 등)만 남아야 하며, 남은 차이마다 이유를 적는다.

### 2단계: 규칙 문서 확정
- `docs/presentation-scene.md`에 3·4장을 장면 렌더링 표준으로 옮긴다.

### 3단계: 게임 렌더러를 같은 규칙으로
- `internal/gui`의 장면 그리기(`field.go`, `field_native.go`, `scene.go` 등)를 같은 규칙과 형식으로 바꾼다.
- 그때 게임 코드의 예외를 뺀다(이름으로 거는 그림자 예외, 높은 절벽·성벽 순서 보정 등).
- 시험: 뷰어와 게임이 같은 맵에서 뽑은 그리기 목록(순서와 그림 선택)이 같은지 비교한다.
- 시험 맵 셋을 레포 데이터로 바꾸고 게임 화면으로 확인한다.

### 4단계: 전체 장면 맵 옮기기
- 나머지 장면 맵을 새 형식으로 옮긴다. 맵마다 1단계 검사 도구(장식 없이 픽셀 비교)를 통과시킨다.
- 장식 규칙을 켜고 전후 캡처로 확인한다(장식 차이는 허용).
- `tools/scene_maps`의 생성 도구를 새 형식을 쓰도록 정리하고, 남은 옛 흔적(`ground` 저장, 장식 좌표 목록, 쓰지 않는 그림)을 지운다.
- 이미 연출된 장면의 배치 검사(`check_scenes.py`)와 장면 테스트를 통과시킨다.

## 6. 주의

- 작업 트리는 다른 세션과 공유한다. 커밋할 때는 이 작업의 파일만 스테이징한다.
- 1단계는 `cmd/_scene`, 변환 도구, 시험 맵 셋의 레포 데이터를 고친다. 게임 렌더러 코드는 3단계에서 바꾼다.
- 시작 시점 백업 커밋이 있으니, 되돌릴 때는 그 커밋을 기준으로 한다.
- 그림 선택 규칙(이음, 변형, 장식 난수)은 뷰어와 게임 두 곳에 같게 구현해야 하므로, 3단계의 비교 시험에 그림 선택 결과도 넣는다.
