# 일기토·맵 목록과 에디터 선택 창 정리

## 문제와 범위

일기토 감상과 맵 목록은 1280×850 고정 좌표에 모든 항목을 나열한다. 항목 수가 늘면 화면 밖으로 나가며, 일반 게임의 목록 입력 처리보다 먼저 반환하므로 휠·드래그도 작동하지 않는다. 에디터 선택 창은 별도 페이지 입력을 쓰며 상단 닫기 버튼과 작은 항목이 남아 있다.

## 구현

- 감상 목록과 맵 목록을 현재 UI 배율을 따르는 최대 960×720 판으로 바꾼다. 제목·개수는 위, 닫기는 오른쪽 아래에 고정하고 목록만 스크롤한다.
- 기존 `listRows`·`tableList`를 재사용한다. 두 독립 화면에서도 드래그·휠 입력을 처리하고, 누른 뒤 움직이지 않고 놓았을 때만 항목을 연다.
- 실제 맵 편집 캔버스와 일기토 재생은 기존 좌표를 유지한다. 목록의 스크롤 위치는 항목을 열고 돌아와도 보존한다.
- 에디터 장수·병종·특성·장비·일기토 편집 목록도 같은 스크롤 입력과 하단 닫기를 쓴다. 팝업 뒤 목록에는 입력이 전달되지 않게 한다.
- 기존 작업 중인 게임·음악·시나리오 변경은 보존한다.

## 검증

목록 끝 접근, 드래그와 선택 구분, 목록 복귀 시 위치 보존, 캠페인 상태 불변을 회귀 시험한다. UI 데모에 두 목록과 에디터 선택 창을 추가하고 PC·폰 기준 실제 PNG로 제목·본문·하단 버튼의 겹침과 마지막 항목 접근을 확인한다. 관련 GUI·맵 편집 시험과 vet를 실행한다.
