# 해야 할 일: GPU 메모리(텍스처)와 아틀라스

범위: 게임이 GPU에 올리는 이미지의 양. 목표는 폰(갤럭시 보급형까지)에서 넉넉하도록 최대 300MB 이하.
2026-11-14 작업의 결과와 이유는 [history.md](../history.md)에 있다.

## 지금 숫자 (2026-11-14, 맥, `a28c32c`)

ebiten이 세는 GPU 이미지 메모리(`ebiten.ReadDebugInfo` → `TotalGPUImageMemoryUsageInBytes`).

| 상태 | 화면 1280×850 | 화면 2560×1700 |
|---|---|---|
| 게임을 켜고 맵을 안 연 상태 | 512MB | 512MB |
| 전투맵 최대 (B02 밤) | 552MB | 649MB |
| 장면 맵 최대 (S_pond_deck) | 618MB | 718MB |

같은 측정으로 수정 전(`c98d0d7`)은 바닥 704MB, 최대 900MB(1280×850)·986MB(2560×1700)였다.
책략 시트(장당 최대 약 10MB)와 초상(장당 0.25MB)은 쓸 때 더해지는데 위 숫자에는 없다.

## 1. 바닥 512MB의 정체 찾기 (먼저)

맵을 열어 더해지는 건 25~105MB뿐이고 대부분은 `LoadAssets`에서 생긴다. 그림 파일 크기로 센 상시 시트는 50MB 안팎이라 10배 차이다.

- 가장 유력한 원인은 ebiten 아틀라스다. `NewImage`·`NewImageFromImage`로 만든 그림은 큰 텍스처(아틀라스 페이지)에 모이고, 페이지는 가득 차면 가로세로 2배로 커진다(… 4096 → 8192 → 16384). 메모리는 안에 든 그림이 아니라 페이지 크기만큼 잡힌다. 512MB는 16384×8192 한 장과 같다.
- 페이지는 그림을 지워도 완전히 빌 때까지 줄지 않는다. 불러오는 도중에 잠깐 만들고 버리는 그림도 페이지를 키운 채 남긴다.
- 바닥이 704 → 512MB로 줄었는데 그날 바꾼 것 중 켤 때 불러오는 건 바탕 무늬 축소(−3MB)뿐이다. 경계를 살짝 넘고 안 넘고에 따라 크게 뛰는 것으로 보인다. 그림을 조금 더하면 다시 뛸 수 있다.
- 할 일: `LoadAssets`(그리고 `gui.New`의 글꼴·유닛 시트)를 단계로 나눠 단계마다 `ReadDebugInfo`를 찍는다. 어느 그림이 페이지를 키우는지 표로 만든다.
  후보: 유닛 도트 시트(`internal/sprite/art.go:41`, 시트마다 통째로 텍스처), 효과 `fx`·`fx_light`(1536×1138, 2~3%만 그림), UI `ui.png`(768×5505, 8%만 그림), 소품 `extra.png`(1024×1799), 나무 흔들림 `sway.png`, 글꼴 글리프 캐시.

## 2. 줄이는 방법 (1의 결과를 보고 고른다)

- **쓸 때 불러오기**: 그 맵·그 화면에 나오는 것만 올린다. 유닛 시트가 크면 효과가 가장 크다. 책략 시트와 초상은 `c0937fc`에서 이미 이렇게 했다.
- **큰 시트는 아틀라스 밖으로**: `Unmanaged`로 만들면 자기 크기만큼만 받는다(`newLayer`처럼). 대신 다른 그림과 GPU 호출 하나로 묶이지 않는다.
- **빈칸 잘라 다시 싸기**: `ui.png` 16.1MB → 약 2.7MB, `fx` 두 장 13.3 → 약 3.1MB(32px 칸 기준 추정). 시트를 만드는 도구와 좌표를 읽는 로더를 같이 고쳐야 한다.
- 어느 방법이든 아틀라스 페이지 경계에서 여유를 두어야 한 단계 뛰는 일이 없다.

## 3. 남은 맵 크기 층

- 장면 맵의 높은 땅 위층(`sceneLevel.top`)은 아직 맵 크기로 구워 둔다. 높은 땅이 있는 장면 맵 8개, 층마다 10~22MB(S_cliff_coalition 21.5MB, S_pond_deck 2장 21.8MB).
  땅처럼 32×16 조합으로 매 프레임 그리면 없어진다. 다만 그 층의 그림자를 위층 모양으로 자르는 마스크(`l.shadows`에 `DestinationIn`)를 땅처럼 순서 바꾸기로 풀 수 없어서 방법을 따로 정해야 한다.
- 화면 크기 층(캔버스·그림자·바깥 풀밭, 밤에는 어둠)은 기기 해상도로 잡힌다. 레티나 2560×1700이면 장당 16.6MB, 폰 2400×1080이면 9.9MB. 확대 2배 이상에서는 캔버스 점 단위로 만들고 마지막에 키우면 1/4이 되지만, 정수배가 아닌 확대에서 점 폭이 고르지 않을 수 있어 화면으로 확인해야 한다.

## 4. 폰에서 재기

- 무선 adb로 게임을 띄운 채 `adb shell dumpsys meminfo <패키지>`의 Graphics를 본다. 맥 숫자와 같은지, 안드로이드에서 ebiten이 GPU 상태를 잃을 때를 대비해 사본을 들고 있는지(그러면 RAM이 더 든다) 확인한다.
- 텍스처 한 장의 최대 크기: 오래된 폰은 4096, S21 이후 갤럭시 S는 대부분 16384. 아틀라스 페이지가 16384까지 커지면 4096 기기에서는 문제가 된다.
