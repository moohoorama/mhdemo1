# 잘못 누름·취소 효과음 전수 조사

조사일: 2026-11-15. 대상: `ver5`, 3장 탐험 방향 수정 적용 후·승인 효과음 수정 전의 작업 트리. 본문 위치·계수와 `reports/sfx-audit/`는 조사 당시 기록이다.

## 후속 수정: 승인·안내 확인

같은 날 사용자 요청에 따라 확인 질문의 ‘예’는 승인 중 창 정리를 무음으로 하고, 작업 자체의 구매·저장·출진 등의 소리를 우선한다. 별도 소리가 없으면 `ok`를 한 번 재생한다. 실패음이 있으면 확인음을 보태지 않는다. 전투 목표·레벨업·승급·특성 안내도 `ok`를 사용한다. 취소·일반 창 닫기·획득 위 설명 닫기는 `close`다.

`reports/uidemo/confirmation-after/sfx.txt`의 210·330프레임이 기존 `close`에서 `ok`로 바뀌었다. 비활성 메뉴의 `ui-denied`+`ui-select` 중복은 조사 당시와 같다. 아래 ‘결과’ 표의 승인·안내 취소음 사용은 수정 전의 발견 기록이다.

## 결과

`ui-denied`를 직접 요청하는 코드는 **2곳**이다. 하나는 비활성 전투 메뉴 클릭, 다른 하나는 빨간 오류 알림이다. 빨간 오류 알림을 호출하는 곳은 **20곳**이다. 소리가 비슷하게 느껴질 수 있는 `close`는 별개의 파일이며, 원본은 `cancel.mp3`다. `close`를 직접 요청하는 코드는 **4곳**이다.

이번에 확인한 추가 문제는 다음과 같다. 조사용 시험과 데모만 추가했으며 게임의 효과음 동작은 변경하지 않았다.

| 항목 | 현재 동작 | 판단·근거 |
|---|---|---|
| 비활성 전투 메뉴 클릭 | 같은 틱에 `ui-denied`와 `ui-select`를 모두 요청 | 효과음 중복. `leftClick`이 거부음 뒤에 `sfxCalls`를 기록해서 일반 클릭음을 막지 못한다. 실제 버튼 클릭 데모 90프레임에서 두 요청 확인. |
| 확인 질문의 ‘예’ | 확인 동작 전에 `close` 재생 | 출진·턴 종료·구매/판매·저장 덮어쓰기 등 정상 승인에도 취소음 원본 사용. 공통 확인 창의 버튼이 `closeOverlay`를 부른다. 실제 데모 210프레임 확인. |
| 전투 목표·레벨업·승급·특성 안내 확인 | 모두 `close` 재생 | 취소가 아닌 안내 확인에도 취소음 원본 사용. 레벨업의 ‘특성 배우기 ›’도 이 경로다. 시험에서 네 종류를 각각 확인. 목표 안내는 실제 데모 330프레임에서도 확인. |

획득 안내는 앞선 수정으로 `ok`를 사용한다. 3장 저택 대화 종료의 `InvalidFace` 오류는 앞선 8방향 수정으로 해소됐고, 같은 위치 기록 경로를 모든 탐험 영역에 확장해 검사했을 때 추가 오류음은 없었다.

## 1. 비활성 전투 메뉴를 누르는 경우

생성: `internal/gui/menu_panel.go:150`. 재생: `internal/gui/game.go:944`.
`drawPanel`은 전투의 명령 메뉴와 그 병법·도구 하위 목록에서만 호출된다.

| 메뉴 | 거부 조건 |
|---|---|
| 공격 | 현재 상태에서 엔진이 허용하는 공격 명령이 하나도 없음. 사거리 내 적 부재나 행동·상태 제한 등은 `LegalActions`의 판정을 따른다. |
| 병법 | 현재 실행 가능한 병법 명령이 하나도 없음. 보유 병법·병법치·상태·대상·범위 등의 판정을 따른다. |
| 도구 | 현재 실행 가능한 도구 명령이 하나도 없음. 재고·행동 여부·사용 대상 등의 판정을 따른다. |
| 개별 병법 | 보유 목록에는 있으나 현재 해당 병법을 실행할 수 없음. 병법치 부족이면 설명에도 표시한다. |
| 개별 도구 | 현재 해당 도구를 사용할 수 없음. 인수는 전투 중 사용 불가이므로 항상 해당한다. |
| `(없음)` | 병법·도구 하위 목록이 비어 표시한 행. |

위 행을 누르면 동작 없이 거부음을 낸다. 현재는 일반 클릭음도 중복된다. 대기는 활성 동작으로 등록되어 이 비활성 행 경로에 포함되지 않는다.

다른 화면의 회색 버튼이 모두 거부음을 내는 것은 아니다. 공통 `btnFace`는 콜백이 없으면 클릭 영역을 등록하지 않는다(`skin.go:488`). 상점에서 돈이 모자란다는 빨간 글자도 `toast`가 아닌 화면 텍스트이므로 그 자체로는 소리가 없다(`shop.go:147`).

### 공통 세션 요청 실패의 하위 조건

`game.go:312`는 하나의 호출 지점이지만 실패 원인은 여러 종류다. `send`는 어떤 화면에서 보낸 요청인지와 관계없이 같은 거부음을 사용한다.

- 게임·진행 상태: 진행 게임 없음, 지금 할 수 없는 명령, 적 차례에 아군 명령, 오래된 revision, 학습 선택 대기, 잘못된 선택지·웨이포인트·난이도·명령 등.
- 전투·배치: 사거리/대상/행동/이동/병법치/병력/상태 제한, 부적절한 병법·무기·도구, 배치할 수 없는 칸, 중복 배치, 미배치 장수, 배치 공간 부족 등.
- 장수 관리: 장비 호환/재고, 부관·필수 장수·군주 제한, 승급 장소/레벨/병종/아이템, 특성 조건/포인트 제한 등.
- 탐험·상점: 잘못된 방향, 닫힌 출구, 현재 없는 이벤트/출진/상점, 판매하지 않는 물건, 돈·보유 수량 부족 등.
- 저장·설정: 없는 저장 슬롯의 파일 읽기 실패, 잘못된 슬롯/설정, 손상·비호환 저장, 저장·설정 파일 쓰기 실패 등. 파일 시스템이 반환하는 상세 오류 문자열도 이 경로로 온다.
- AI 요청: 합법 명령 부재, 반복 한도·시간 제한, 선택한 AI 명령 적용 실패 등.

예외인 `OverwriteRequired`·`DiscardRequired`·`ChangedContent`는 오류음 대신 확인 질문을 연다(`game.go:304`). 다만 질문 자체를 배치하지 못하면 위 #6의 오류음이 날 수 있다. 질문에 ‘예’를 누르면 별개인 `close`가 난다.

정적 오류 문자열과 위치는 `reports/sfx-audit/static.json`에 함께 보존했다. 이 목록은 문자열 리터럴을 추출한 참고 자료로, 변수·중첩 오류·운영체제 오류를 열거하는 자료는 아니다. 소리의 호출 지점 전수 목록은 위 두 직접 지점과 20개 알림 지점이다.

## 3. 취소음 원본 `close`의 전체 직접 호출 지점

| 위치 | 재생 조건 |
|---|---|
| `windows.go:59` | 열린 최상위 창 닫기. 닫기·취소·우클릭·Esc뿐 아니라 확인 질문의 ‘예’도 포함. |
| `windows.go:67` | 열린 창 모두 닫기. 메뉴의 ‘게임으로’, 창을 연 채 새 게임/불러오기/재시도, 난이도·장면 이동 및 일부 에디터/목록 전환 등에서 호출. 열린 창이 없으면 무음. |
| `windows.go:450` | 획득 카드 위에 연 장비/특성 설명을 한 겹 닫음. |
| `windows.go:456` | 획득 이외 모달 닫기: 전투 목표·레벨업·승급·특성 안내. |

획득 카드 전체 확인은 `windows.go:454`의 `ok`다. 저장 성공은 창 배열을 직접 비우고 `save`를 재생한다(`game.go:334`).

`ui-back`은 별도로 합성한 효과음이다. Esc 처리의 기본 피드백과 전투 맵에서 명령을 한 단계 취소할 때 쓴다(`game.go:877`, `984`). 창 자체의 `close` 등 다른 효과음이 있으면 Esc의 기본음은 생략한다. 우클릭으로 창 없이 명령만 취소하는 경로는 자체 효과음을 요청하지 않는다(`game.go:701`).

## 4. 소리가 나지 않는 경계

- ‘반드시 출전합니다’ 알림은 `muted`라 거부음이 없다(`sortie.go:178`).
- 저장/불러오기 성공, 배속 변경, 부목표 달성 알림은 `gold`라 거부음이 없다.
- 닫힌 탐험 출구를 정상적으로 눌렀을 때는 `Shut` 대사를 보여 준다. 닫힌 출구 명령을 엔진에 강제로 보내는 실패와는 경로가 다르다(`explore.go:443`).
- 상점 잔액 부족이나 사용할 수 없는 승급 장수의 흐린 표시는 그 자체로 오류 알림을 만들지 않는다.
- 자동 저장 실패는 `autosave-failed` 이벤트로 전투 기록에 남기며, 그 이벤트 자체가 `ui-denied`를 호출하지 않는다(`session/session.go:387`, `gui/events.go:15`).
- 소리 설정이 ‘음악만’ 또는 ‘끄기’이면 효과음은 실제 재생되지 않는다. 효과음 기록은 설정·오디오 장치 유무와 관계없이 **요청**을 남긴다. 같은 효과음의 3틱 이내 재요청은 실제 재생 때 중복 억제한다(`sound.go:211`). 서로 다른 `ui-denied`와 `ui-select`는 이 억제로 합쳐지지 않는다.
