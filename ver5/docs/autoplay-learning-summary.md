# 자동 플레이 AI 개발·학습 결과 정리

작성일: 2026-11-17. 대화에서 진행한 구현·학습·검증을 코드와 저장된 보고서에 맞춰 정리했다. **학습과 후속 작업은 사용자 요청으로 일시중지한 상태이며, 이번 정리에서는 재개하지 않았다.**

## 1. 확인된 결과와 적용 범위

**당시 캠페인 B01~B20을 정상 새 게임에서 재도전 없이 모두 이긴 모델을 만들었다.** 시드 310004의 보고서에서 `ExpectedBattles=20`, `UnbeatenStages=20`, `Cleared=true`와 전투별 `Tries=1`, `Won=true`를 확인했다. 데이터 전이 후에도 같은 시드의 20전투 완주를 재현했다.

그러나 완주가 안정적인 수준은 아니다. 별도 미사용 시드 8개에서는 **완주 0/8, 평균 무패 진척 5.625탄, 최고 9탄**이었다. 최고 기록 달성과 다른 시드에서도 잘하는 일반화 성능을 구별해야 한다.

| 항목 | 확인한 상태 |
|---|---|
| 당시 목표 | 첫 패배 없이 당시 최종 B20까지 완주 |
| 최고 기록 | 시드 310004, 20전투 모두 첫 시도 승리 |
| 개발 4시드 | 5·5·5·20탄, 완주 1/4 |
| 미사용 8시드 | 평균 5.625탄, 최저 3·최고 9탄, 완주 0/8 |
| 학습·평가 조건 | `hard`(당시 매우 어려움), 기본 피해·경험치 배율 80% |
| 현재 저장된 기본 모델 | `assets/autoplay/battle.json`, 아래 9절의 최종 가중치 |
| 현재 작업 상태 | 자동 감독 도구는 완주 후 종료, 추가 작업은 사용자 요청으로 일시중지 |

이 결과는 **2026-11-15에 검증한 데이터·엔진 조건의 20전투**에 관한 것이다. 이후 B21과 병법·특성·AI 규칙 변경이 추가됐다. 현재 최신 캠페인 전체나 B21까지 검증한 결과로 해석하면 안 된다. 기존 README와 일부 문서의 ‘최고 11탄’ 문구는 이전 단계의 기록이다.

## 2. 이 방식을 부르는 이름

기술 명칭은 **커리큘럼 기반 모방·강화학습 AI**, 게임 안의 짧은 표기는 **학습형 AI**가 적절하다.

| 구성 | 역할 |
|---|---|
| 교사 모방 학습 | 기존 규칙·탐색 AI가 실제로 이긴 플레이를 신경망이 배움 |
| PPO 강화학습 | 신경망이 직접 플레이하고 결과로 정책·가치망을 갱신 |
| 성공 기록 재학습 | 신경망 자신의 승리 명령을 저장해 다시 모방 |
| 커리큘럼 학습 | 현재 막힌 전투를 집중 학습하고, 기록이 늘면 다음 실패 전투로 이동 |
| 전투별 전문가 | 특정 전투의 가중치를 따로 보존해 앞서 배운 전투의 망각을 줄임 |

게임 실행 중에는 저장된 신경망으로 **추론**한다. GUI의 `학습(시험)`은 그 정책을 사용하는 모드이며, 버튼을 켜 두면 앱 안에서 가중치를 계속 학습한다는 뜻은 아니다. 학습은 별도 CLI 도구에서 수행했다.

## 3. 실제 게임에서 구현한 자동실행

`go run ./cmd/srpg-gui`의 debug 실행에 자동실행을 연결했다. 정상 새 게임이나 현재 진행에서 이야기, 탐험, 구매, 출전 준비, 전투, 결과 확인을 이어간다. 경험치·재고·장비·특성은 실제 게임 상태로 다음 전투에 승계된다.

| 판단 영역 | 최종 모델의 담당 방식 |
|---|---|
| 전투 | 신경망이 행동할 장수와 이동·공격·병법·아이템·대기 명령 선택 |
| 장비 | 준비 신경망이 유지·해제·창고 장비 착용 선택 |
| 특성 | 준비 신경망이 구매 또는 포인트 저축 선택; 전투 중 레벨업 학습창에도 사용 |
| 승급·편성·부관 | 기존 규칙 유지 |
| 이야기·탐험·상점 | 기존 진행·구매 규칙 유지 |

실제 엔진이 허용하는 후보를 제공하고, 포인트·재고·선행 조건을 지킨 명령만 적용한다. 최고 장비 지급, 무한 소모품, 임의 레벨 상승으로 완주 상태를 만들지 않았다. 교사의 위험 계수나 행동 순서 설정은 학습용 성공 사례 수집에 사용하며, 일반 신경망 플레이의 행동을 그 규칙으로 강제하지 않는다.

GUI에서는 준비 계산을 상태 복사본에서 수행하고, 결과의 엔진·리비전이 여전히 일치할 때 실제 세션에 적용한다. 중지·새 게임·로드 등에서는 진행 중 계산을 취소한다. 장비·승급·특성 선택은 기존 게임 창으로 보여 준다.

빌드와 조작은 다음처럼 정리했다.

- `go run ./cmd/srpg-gui`: 기본 debug 실행. `학습(시험)`을 확인하고 왼쪽 위 `자동실행`을 켠다.
- 중지 상태에서 정책 버튼을 누르면 기존 `전투: 탐색`으로 전환한다.
- `make`: release 빌드. 자동실행 등 디버그 도구를 숨긴다.
- Android 디버그 도구 포함: `make android android-install ANDROID_MODE=debug`.
- 일반 명령 앞 0.8초·뒤 0.6초의 고정 대기를 제거했다. 한 프레임의 선택 표시와 실제 이동·공격 연출, 계산 완료를 기준으로 다음 명령을 진행한다.

GUI 자동실행은 패배 뒤 재도전할 수 있다. 아래의 **무패 기록은 GUI의 재시도 결과가 아니라 CLI에서 `-tries 1`로 측정한 결과**다. 과거 debug APK 빌드·서명 검증 기록은 있지만, 최종 20전투 모델을 넣은 APK의 재배포·실기 검증을 완료했다는 기록은 없다.

## 4. 학습을 바꿔 온 과정

### 4.1 규칙·탐색 자동 플레이에서 전투 신경망으로

처음에는 특성·장비·승급과 전투를 규칙·탐색 AI로 처리했다. 이후 사용자의 요청에 따라 전투 명령을 모방 학습과 PPO로 고르는 모델을 추가했다. 초기 공통 모델은 B01~B06을 대상으로 누적 640전투 PPO를 수행했다.

초기 캠페인 결과에는 전투당 최대 5회 재도전이 포함돼 있었다. 예를 들어 2·2·3번째 시도에 승리한 것은 첫 시도 승리나 높은 승률을 뜻하지 않는다. 이를 구별하도록 보고서와 설명을 정정했다. B06의 준비를 포괄적으로 ‘약하다’고 부른 해석도 근거가 부족해 철회하고 실제 레벨·재고·출처를 기록했다.

### 4.2 첫 전투의 경험치·물자 집중 학습

사용자가 제시한 기준은 **소모품 없이 승리하면서 보스 외 적이 1기 정도 남을 때까지 경험치를 얻는 것**이었다. 승리·경험치와 함께 물자 절약·일반 적 정리를 보상하는 B01 추가 학습을 진행했다. 아이템이나 일기토 후보를 금지하는 방식은 쓰지 않았다.

| 항목 | 결과 |
|---|---|
| 추가 실험량 | PPO 단독 12,416전투 + 성공 재학습 병행 8,192전투 = 20,608전투 |
| 선택한 B01 체크포인트 | 공통 640 + B01 추가 10,240 = 누적 10,880전투 |
| 선택한 PPO, 고정 준비·미사용 RNG 512개 | 511승 1패, 무소모품·일반 적 1기 이하·승리 동시 달성 415/512 |
| 성공 재학습 비교 모델, 같은 512개 | 500승 12패, 동시 달성 491/512 |
| 당시 정상 새 게임 B01 10회 | 10승, 무소모품 9회 |
| 두 모델의 당시 캠페인 비교 | 최대 B06, 모두 완주 실패 |

여러 실험의 총량 20,608과 선택한 가중치의 누적 횟수 10,880은 다른 수치다. 목표 달성률이 높아도 패배가 더 많았던 비교 모델을 기본으로 고르지 않았다. 선택 모델 역시 경험치를 완전히 최적화한 것은 아니었다.

이 단계의 일부 평가는 실제 준비 상태를 고정하고 전투 RNG만 바꾼 **단일 전투 평가**다. 이를 정상 새 게임의 캠페인 완주율로 해석하지 않는다.

### 4.3 첫 패배 전 진척과 준비·전투 공동 학습

평가의 중심을 **새 게임에서 첫 패배 전에 몇 전투를 연속으로 이겼는가**로 변경했다. 특성과 장비도 같은 캠페인 결과로 학습하도록 준비망을 추가했다.

| 단계 | 실험·검증 결과 |
|---|---|
| 전체 새 게임 공동 학습 | 320회, 1,838전투 실행 |
| 10탄 목표의 추가 구간 학습 | 1,928회 실행 |
| 최고 기록 변화 | 6 → 8 → 9 → 11탄 |
| 11탄 모델 개발 4시드 | 5·5·5·11탄, 최고 시드의 첫 패배 B12 |
| 같은 모델 미사용 8시드 | 평균 5.5탄, 최고 8탄, 완주 0/8 |

도착형 목표의 방향·거리 입력이 부족했고, 공통 준비망을 한 전투에 맞추면 이전 전투의 성능까지 떨어지는 망각이 있었다. 승리 구역 관측과 전투별 준비 전문가를 추가해 개선했다.

사용할 병법이 없는 대상에게 MP 회복 물자를 쓰는 문제도 관측했다. 병법 보유·MP 사용 가능성 입력을 보강했으며, 이 학습 작업에서 아이템 처리 규칙 자체를 바꿔 해결한 것으로 기록하지 않는다.

### 4.4 최종 20전투 목표와 자동 감독 도구

11탄 모델에서 이어서 막힌 전투를 학습하고 정상 새 게임으로 재검증했다. 기록은 **11 → 12 → 13 → 16 → 17 → 18 → 20탄**으로 늘었다. 모든 전투에 별도 정책을 만든 것은 아니다. 최종 모델에도 B20 전용 전문가가 없으며 공통 정책으로 마지막 전투를 이겼다.

자동 감독 도구의 반복은 다음과 같다.

```text
정상 새 게임에서 첫 패배 확인
  → 실제 무패 진입한 준비 전 상태 수집
  → 교사 탐색 + 두 신경망 강화학습을 병렬 실행
  → 신경망 승리 기록의 집중 모방 작업 추가
  → 더 긴 기록을 새 게임에서 다시 검증
  → 다음 실패 전투로 이동, 또는 20전투 완주 후 종료
```

구간 학습은 수집한 스냅샷의 자원·성장·전투 RNG를 보존한다. 정책 행동을 샘플링하는 난수는 별도로 사용한다. 교사나 구간 단독 승리는 최고 무패 기록에 포함하지 않고, 처음부터 다시 진행한 검증만 인정한다.

| 자동 완주 시점의 집계 | 횟수 |
|---|---:|
| 새 게임 수집·평가 실행 | 130 |
| 추가 구간 강화학습 전투 | 1,096 |
| 교사 탐색 전투 | 72 |

130회는 개발 시드 반복을 포함한 실행 수이며 서로 다른 시드 130개가 아니다. 앞선 10탄 목표 실험량과도 구별한다. 자동 완주 보고서는 **2026-11-15 22:15:23 KST**에 저장됐다. 목표를 확장한 뒤 약 64분 만에 나온 기록이다.

스테이지 진척, 성공 기록 재학습, 정상 새 게임 재검증과 완료 판정은 자동화했다. 실행 과정에는 관측 보완·저장 형식 개선·데이터 해시 전이 같은 개발·운영 개입도 있었으므로, 전체 개발 과정을 처음부터 끝까지 무인 실험이었다고 표현하지 않는다.

## 5. 모델 구조와 주요 보완

학습·추론은 Go로 구현한 MLP와 PPO를 사용한다. 은닉층은 tanh 32→32이고 출력은 후보 행동별 점수 1개다. 행동 가능한 아군 장수들의 합법 명령을 함께 점수화한다. 평가·일반 플레이에서는 그중 최대 점수를 선택한다.

| 망 | 입력 크기 | 용도 |
|---|---:|---|
| 기본 전투 정책 | 128 | 상태 64 + 행동 특징 64 |
| 승리 구역 관측 포함 정책 | 136 | 도착 목표의 대상·거리·방향·진입 여부 등 8개 추가 |
| 효과 관측까지 포함한 정책 | 152 | 강화 효과·지속·아이템 양/가격/재고 등 16개 추가 |
| 준비 정책 | 128 | 실제 장수 상태와 장비·특성 적용 전후의 변화 |
| 가치망 | 64 | 학습 중 최종 결과 예측 |

최종 파일의 전투 전문가는 B01·B07·B09·B10·B12·B13·B14·B17·B18·B19다. 준비 전문가는 이 중 B09·B10·B12·B13·B14·B17·B18·B19에 있다. 해당 전문가가 없으면 공통 가중치를 사용한다.

주요 보완은 다음과 같다.

- **준비 후보의 실제 효과**: 엔진 복사본에서 명령을 적용해 능력치·열리는 병법·포인트 비용·장비 효과를 구한다. 명령 생성 과정에서 실제 상태는 바꾸지 않는다.
- **망각 방지**: 전투별 준비망을 분리해 특정 전투 추가 학습이 공통 준비 전략까지 바꾸는 문제를 줄였다.
- **목표 구역 관측**: 엔진의 `GoalMarks`를 입력으로 사용한다. 이동 좌표를 직접 정하는 전투별 행동 규칙은 넣지 않았다.
- **병법·아이템 구분**: 공격/방어 강화나 원래 회복량이 다른 아이템이 같은 입력으로 표현되던 문제를 보완했다. 최종 파일에서는 B17·B18·B19가 확장된 효과 입력을 사용하며 기존 초기 정책의 관측까지 일괄 교체하지 않았다.
- **기존 예측 보존**: 새 입력의 초기 가중치를 0으로 두고, 입력 확장 순서와 저장·로드 후 예측을 검사했다. 차원이 다른 옛 학습 표본은 거부한다.
- **희소한 승리 보상 보완**: 실패 구간 직접 학습에서 목표 피해·도착 접근을 최대 0.25점으로 구별했다. 한 전투 승리의 1점보다 작고, 전체 캠페인의 정식 진척은 계속 정수 무패 승리 수다.
- **기록과 저장 공간**: 성공 명령·가중치·실행 인자를 보존하고 큰 표본은 gzip으로 저장한다. 일부 완료 실험 자료는 원본 해시 대조 후 무손실 보관했다.

## 6. 최종 완주와 일반화 성능

완주 조건은 `Cleared=true`뿐 아니라 **예상 전투 20개, 보고된 전투 20개, 전부 승리·시도 1회**까지 확인했다. 20탄 상한으로 실행을 끊은 결과나 재도전 승리는 이 조건을 만족하지 않는다.

| 구분 | 시드 | 첫 패배 전 승리 수 | 완주 |
|---|---|---|---|
| 개발 평가 | 310001~310004 | 5·5·5·20 | 1/4 |
| 완주 모델 별도 새 게임 검증 | 310004 | 20, 첫 패배 없음 | 성공 |
| 후속 데이터 전이 검증 | 310004 | 20, 가중치 변경 없이 두 번 확인 | 성공 |
| 미사용 평가 | 470001~470008 | 5·3·7·4·9·5·8·4 | 0/8 |

미사용 평가의 평균은 5.625탄이다. 완주에 성공한 개발 시드 310004는 학습과 선택 과정에서 사용했으므로, 그 기록을 미사용 시드 성능으로 제시하지 않는다. 이전 11탄 모델의 미사용 8시드와 이번 8시드는 다르므로 두 평균만으로 성능 향상률을 계산하지 않는다.

**확인한 것은 특정 시드에서의 정상 20전투 무패 완주이며, 안정적인 전체 캠페인 공략이나 확정 승리는 아직 달성하지 못했다.**

## 7. 사용자 1탄 경험치 기록과 비교

사용자는 경험치 배율이 기본 80%였다고 확인했다. 11탄 목표 모델을 정상 새 게임 10회로 측정하고 GUI 표시와 같은 단위로 비교했다. 실제 경험치 이벤트 합을 시작·종료 레벨과 경험치 차이로 대조했다.

| 장수 | 사용자 무소모품 기록 | 모델 10회 평균 |
|---|---:|---:|
| 관우 | +232 | +160.2 |
| 장비 | +198.3 | +162.3 |
| 유비 | +147 | +90.0 |
| 합계 | +577.3 | +412.6 |

모델은 10전 10승, 모두 3라운드·적 1기 잔존이었다. 무소모품은 9회이고 1회는 콩 1개를 썼다. 같은 경험치 배율에서 합산 경험치가 사용자 기록보다 약 **28.5% 적었다**. 사용자의 시드는 제공되지 않았고 동일 시드의 대조 실험은 아니다.

이 표는 해당 11탄 모델의 측정이다. 최종 20탄 모델에 기존 B01 가중치가 보존된 것은 대조했지만, 이후 변경된 최신 게임에서 같은 표를 다시 측정한 결과는 아니다. 긴 캠페인 최고 기록을 냈다는 사실과 1탄 경험치 수급이 우수하다는 주장은 구별한다.

## 8. 데이터 버전·GUI 검증·중지 상태

실험 도중 다른 게임 자료 편집으로 콘텐츠 해시가 달라졌다. 파일을 되돌리는 대신 복사본으로 조건을 고정하고, 전이할 때는 `-transfer-content`를 명시했다. 전이 검증은 `-warm 0 -episodes 0`으로 수행하고 정책·가치 가중치가 유지됐는지 대조했다.

| 데이터 해시 앞부분 | 사용한 기록 |
|---|---|
| `e59a78…` | 공동 학습과 11탄 모델, 20탄 목표의 출발 조건 |
| `a7d4af…` | 탐험 인물 위치 변경 뒤 17탄 전이 검증 및 최초 20전투 완주 |
| `e3dff5…` | 완주 후 후속 데이터에서 20전투 무학습 전이 재현, 현재 저장 모델의 메타데이터 |

검증 뒤에는 별도 16탄 맵·이벤트 편집 중 데이터 로딩 오류가 발생했다. 검증 데이터는 `reports/autoplay/goal20/final-data-snapshot/`에 보존하고 UI 데모에 선택적 `-root` 전달을 추가했다. GUI의 콘텐츠 일치 검사는 유지했다.

11탄 모델은 실제 GUI 로딩과 첫 전투 캡처를 확인했다. 20탄 모델은 가중치를 기본 파일에 반영했고, 검증 데이터의 GUI 로그에서 신경망·준비망 로딩과 B01 진입을 확인했다. 다만 최종 PNG 캡처와 GUI 전체 캠페인 완주를 완료한 기록은 없다. 이후 사용자가 답변만 요청하며 중지를 지시해 후속 작업을 멈췄다.

현재 작업 트리에는 B21과 추가 규칙 변경도 있다. **과거 검증 해시를 최신 데이터에 맞는 것처럼 바꾸거나, 최신 버전에서도 그대로 완주한다고 가정해서는 안 된다.** 새 버전의 실행 가능 여부와 성능은 별도 검증 대상이다. 이번 문서 작성에서는 게임 실행·학습·모델 교체를 하지 않았다.

## 10. 재개할 때 남은 과제

1. 현재 B21까지의 데이터·엔진 버전을 고정하고 모델 호환성과 정상 새 게임 성능을 다시 측정한다.
2. 미사용 시드에서 자주 막힌 B04~B06 등 초반 전투의 안정성을 높인다.
3. 최고 기록 외에 미사용 시드의 완주율·평균 진척·첫 패배 분포를 중심으로 검증 범위를 넓힌다.
4. 1탄 경험치 수급과 물자 절약을 사용자 기록 수준으로 개선할 여지가 남아 있다.
5. 새 모델의 GUI 진행·최종 캡처와 필요 시 Android 재빌드·실기 검증을 마무리한다.

이 항목들은 재개 시 검토할 목록이며, 현재 추가 학습을 실행한다는 뜻은 아니다.
