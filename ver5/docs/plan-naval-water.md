# 수전: 낮은 물과 배

상태: 1~6단계 구현(2026-10-28). 확인용 데모 `go run ./cmd/_uidemo-vm -ui naval` (가장 큰 맵에 강을 칠하고 `Boats`를 켬). 아직 `Boats`를 켠 실제 스테이지는 없다.

시안: https://claude.ai/artifact/NwKVGU8HAq8mZP5UFovE36 (2026-10-28 사용자 확정, 배는 "들린 배").

## 확정 사항

- 전투맵의 물(`w`)은 한 종류다. 수면을 땅보다 9 캔버스 px 낮게 그리고, 좌상(NW, u−1)·우상(NE, v−1) 이웃이 물·다리가 아니면 그 변에
  9px 흙 절벽(위에 풀 테두리, 발치에 물거품)을 세운다. 우하·좌하 변은 앞쪽 땅이 가리므로 1px 어두운 선만 긋는다. 다리는 땅 높이 그대로다.
- 전투마다 `Boats` 설정 하나로 물의 쓰임이 갈린다. 없으면(기본, 지금 모든 스테이지) 물은 진입 불가. 있으면 물에 배를 타고 들어간다.
- 배 스테이지의 물 칸 규칙: 보병·도적 비용 1·보정 1.1, 궁병·책사 비용 1·보정 1.0, 기병 비용 2·보정 0.9(말 탄 채 큰 배에 탄다), 병기는 진입 불가.
- 물 위 병력은 그림자 → 배 → 병사(대기 프레임) → 앞 뱃전 순서로 그린다. 배는 수면(9px 아래)에 뜨고, 앞쪽 땅 칸의 땅에 가려진다.
  물 위에서 움직일 때는 걷기 모션 없이 대기 프레임이 미끄러지고 살짝 출렁인다. 그림자는 기존 그림자 생성기로 배와 병사 실루엣에서 만든다.
- 배는 `tools/unit3d` 소품 카메라(1칸 64×32)로 모델링한 들린 배. 보병용·기병용(말이 들어가는 긴 배) 두 크기 × u·v 두 방향,
  각각 전체와 앞 뱃전 두 겹. 방향은 유닛이 보는 쪽(SE·NW → u, SW·NE → v)을 따른다.

## 정한 세부

- 부서진 다리(`wbx`)는 배 스테이지에서도 진입 불가로 둔다. 잔해가 물길을 막는다는 뜻이고, 상태 층이 맨 위라는 지금 규칙과도 맞는다.
- 물을 실제로 9px 내려 그리지 않는다. 물 텍스처는 이음새 없이 반복되므로, 땅 높이의 물(물가 블렌드 없이) 위에 강둑 면을 덮으면 낮아 보인다. 마스크 층이 필요 없다.
- 이동 범위·대상 하이라이트와 커서는 물 칸에서도 땅 높이(칸의 발자국)에 그린다. 클릭 판정(`Field.Cell`)과 같은 마름모라서 어긋나지 않는다.
- 배 방향은 두 가지(u·v)만 둔다. 들린 배는 앞뒤가 같아서 네 방향이 필요 없다.
- 장면 맵(형식 1·2)은 범위 밖이다. 전투맵(`!Scene && SceneMap == nil`)에서만 물을 낮춘다.

## 구현 순서

1. 규칙: `Stage.Boats`, `terrain.json`의 `Boats` 덧씌움 표, `Data.Move(group, cell, boats)`와 다섯 호출처, 저장 검사의
   `openWater`, `waterNear`가 자기 칸도 보도록. 테스트·문서.
2. 그리기 게이트(`MapArt.SunkWater`)와 `Field.Lift`의 −9(물 칸). 유닛 바·효과·메뉴는 lift를 따라 내려온다.
3. 낮은 물 층: 물 마스크·물 정적 층(물 장식 +9, 강둑 면, 1px 선)을 한 번 굽고, 매 프레임 물 애니메이션 조각을 +9로 그린 뒤
   마스크로 잘라 바닥 다리 앞에 얹는다. 물결도 +9.
4. 배 에셋: 3D 렌더 → `assets_candidate/tiles` → `build_extra.py`.
5. `drawUnit`의 배 그리기: 걷기 → 대기, 출렁임, 방향, 앞 땅 지우기, 그림자 합치기.
6. 시험 스테이지에서 `_uidemo-vm`으로 캡처(map02·07·10 물 맵).
7. `history.md`, `data-map.md`, `data-scenario-node.md`, `logic-combat.md`.
