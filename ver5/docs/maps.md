# 단일 맵 문서

맵별 `assets/data/maps/<ID>.json` 한 파일을 게임과 에디터가 함께 사용한다.
소타일·대타일 판정 이력·외곽·배치·승리 조건·장식 정보를 이 문서에 저장한다.
전투 시작에 사용할 정규화된 대타일 Stage와 GUI 그림 자료는 로드 시 메모리에서 만든다.
전투맵의 별도 stages/ 자료와 graphics/maps/ 자료, tools/mapeditor/maps/ 원본은 유지하지 않는다.

공유 문서와 좌표·지형 계산은 content 패키지에 두어 콘텐츠 로더가 직접 읽을 수 있도록 한다.
mapedit 패키지는 편집 이력과 단일 파일의 검증·안전 저장을 담당한다.
GUI는 content가 읽은 문서로 그림을 만들며, 같은 파일을 에디터에서 수정한다.
저장은 임시 파일 작성 후 원자적으로 교체하고 실패 시 기존 파일을 유지한다.

별도 preview/check/mapbuild 실행 명령과 지원 코드를 제거한다.
기존의 편집 원본을 단일 문서 위치로 옮기고 중복 실행 자료와 맵 그림 인덱스를 제거한다.
초안 저장은 제거한다. 검증을 통과한 맵만 저장하며, 미완성 편집은 현재 에디터에서 계속할 수 있다.
시험 전투와 실행 취소는 유지한다. 재로드·캠페인·그림 생성·저장 실패는 Go 테스트로 검증한다.
테스트용 최소 콘텐츠의 단순 Stage JSON은 테스트 픽스처로만 유지한다.

## 필드

- `Version`: 문서 버전(1).
- `Play`: 전투 영역의 월드 좌표와 대타일 크기(4~64칸).
- `Visual`: 외곽 그림 영역. 초기에는 전투 영역 사방에 대타일 4칸을 더한다.
- `Cells`: `x,y` 키의 소타일 지형. 대타일의 두 배 좌표이며 음수도 허용한다.
- `Resolved`: 대타일 판정 이력. 2:1:1처럼 단독 최다 종류는 변경하고, 동률은 기존 판정을 유지한다.
- `Stage`: 월드 좌표 배치·승리 조건·보상·다음 노드·일기토 등 전투 메타데이터.
  저장된 Width/Height/Tiles는 사용하지 않는다. 실행에 필요한 값은 Play와 Resolved로 만든다.
- `Decorations`, `Props`: 장식과 소품. 지면 타일셋·구조물·나무 스프라이트는 기존 공용 자산을 사용한다.

시험 전투와 GUI는 같은 문서 계산을 사용한다. 캠페인용 복제 JSON이나 그림 인덱스 갱신이 필요 없다.
새 ID 저장 시 한 문서가 추가되며, 캠페인에 새 전투를 연결하는 시나리오 작성은 별도다.
이야기 연출 전용 지도는 전투맵과 다른 장소의 독립된 그림 자료이며 기존 graphics/maps/에 유지한다.
