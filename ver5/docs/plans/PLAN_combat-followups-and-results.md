# 전투 후속 공격과 결과 화면 수정

## 범위

- 전투 이벤트의 상단 노란 토스트를 제거한다. 하단 로그, 피격 표시, 턴 배너와 저장·오류 알림은 유지한다.
- 요극은 최초 공격/반격/일기토의 결과가 확정된 뒤 공격자 일반 공격 사거리 내의 살아 있는 적을 순서대로 공격한다. 각 추가 공격은 일반 물리 공방(명중, 치명타, 2회 공격, 협공, 반격, 경험치, 흡혈)을 사용한다. 추가 공격 결과는 요극을 다시 발동시키지 않으며 공격자가 퇴각하면 중단한다.
- 후속 공격의 시작/끝 이벤트로 리플레이를 분리한다. 먼저 원래 공방과 퇴각 점멸을 끝내고 다음 대상의 공격 모션과 공방을 재생한다. 일기토 후속 공격도 동일하게 처리한다.
- 공훈은 직접 조작하는 아군만 대상으로 집계한다. 한 페이지 5명으로 제한하여 보상/진행 버튼 영역과 겹치지 않게 한다.
- 스테이지 `TurnLimit`을 추가한다. 0은 무제한, 양수는 마지막 라운드의 적 차례까지 허용하고 다음 아군 라운드 시작에 패배 처리한다. 현재 B01~B03은 30턴으로 설정한다. 전투 목표와 상단 턴 표시 및 패배 사유에 반영한다.

## 검증

엔진에서 요극 사거리/2회 공격/반격/퇴각 순서/연쇄 차단/공격자 퇴각과 턴 제한 경계를 검증한다. GUI에서 원래 공방과 후속 공방 분리, 일기토 후속 분리, 공훈 필터/페이지 범위를 검증한다. 관련 core/content/gui/replay/session 테스트를 실행한다. 규칙 버전을 갱신하여 기존 저장/리플레이와 변경된 규칙을 구분한다.

## 검증 결과

- core/content/gui/replay/session/mapedit/ai/storage 패키지 회귀 테스트 통과.
- core/content/gui/replay/session/mapedit 정적 검사 통과.
- `TestRenderedCombatFollowupsAndResults`에서 최초 대상의 퇴각 완료 전 후속 피해가 발생하지 않는지, 후속 공격 준비 모션이 나오는지 확인했다. 12명 공훈의 세 페이지와 다음 페이지 버튼을 실제 렌더러로 검증했다.
- 화면 기록: `reports/combat-results/followup-after-retreat.png`, `result-page-1.png`~`result-page-3.png`. 보상 문구를 아이템 표시명으로 바꾸고 공훈 목록·페이지 버튼·보상·진행 버튼 사이 간격을 확인했다.
