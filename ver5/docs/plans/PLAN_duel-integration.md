# 일기토 본편 연결

## 범위와 접근

기존 규칙 엔진의 승패·사망·퇴각·약화 판정을 유지한다. 일기토 이벤트에 ID와 승패를 구조화해 전달하고, 기존 리플레이 장벽 안에서 전용 화면을 재생한다. 종료 후 후속 이벤트를 순서대로 표시한다. 일기토만 건너뛰는 조작은 후속 이벤트를 유지한다.

데모의 화면 렌더러는 internal/duelview로 분리해 데모와 본편이 공유한다. 본편은 실제 장수의 현재 병종, 진영색, 외형과 초상을 사용한다. assets/duels.json은 GUI 전용 전개 데이터이며 엔진 판정이나 콘텐츠 해시에 영향을 주지 않는다. 각 전개는 일기토 ID, 기대 승패, 동작·화자·대사·시간을 지정한다. 없는 ID는 구조화된 승패에 맞는 기본 연출을 사용한다.

## 현재 시나리오

- B01-duel-1: 등무 도발 → 장비 선언 → 양측 중앙 접근 → 등무의 호기로운 대치 → 섬광과 한 번의 결정타 → 승리. 정면에서 장팔사모 한 합.
- B01-duel-2: 정원지 복수 선언 → 관우 응답 → 정원지 단독 돌진 → 관우의 한 번의 결정타 → 승리. 적의 돌진을 받아 베는 구성.
- sishui-guan-yu: 화웅 도발·연타·강타 → 관우의 여유로운 방어 → 화웅의 공포·직선 도주 → 관우의 추격과 베기. 요청에 맞춰 화웅 사망.
- hulao-zhang-fei: 양측 도발 → 번갈아 공격·방어 → 후퇴·교차 돌진 → 재접전 → 승부 유보. 긴 접전, 양측 잔류.

## 검증

전개 데이터의 동작·시간·화자·결말을 검증한다. 현재 모든 스테이지 일기토의 고유 전개와 규칙 결과가 일치하는지 확인한다. 한 합 승부의 타격 수, 긴 접전, 샘플링 재현성을 테스트한다. GUI 재생 종료·일기토 건너뛰기·리플레이 전체 건너뛰기를 확인한다. 관련 패키지 테스트 및 빌드·vet 후 실제 창에서 각 전개를 캡처한다.

## 완료 기록

- 네 일기토 전개 데이터와 공통 렌더러, 구조화된 이벤트, GUI 전환·복귀·건너뛰기를 구현했다.
- 관련 패키지 테스트 통과. 실제 공격 명령으로 네 일기토와 적 선공을 검증하고 41장 캡처를 생성했다.
- 종료와 일기토 건너뛰기 후 규칙 revision·난수 상태가 그대로이고, 사망·퇴각한 적이 화면에서 제거되는 것을 확인했다.
- 2배 화면 크기 렌더링 확인. 독립 데모의 `-duel` 옵션으로 스토리별 미리보기를 지원한다.
- 최종 테스트: duel·core·gui·replay·sim·session·cli 통과. 관련 vet와 게임·데모·시뮬레이터 빌드 통과. 데모 `-duel B01-duel-1 -capture` 실행 및 5장 캡처 확인.

## 화웅 전개와 제작 스킬 개선

화웅의 도발·연타 → 관우의 여유로운 연속 방어 → 화웅의 강한 공격과 섬광 → 관우의 흔들림 없는 방어 → 화웅의 공포·직선 도주 → 관우의 추격과 베기 순서로 변경한다. 강타 방어·한쪽 뒷걸음질·직선 추격 동작을 추가한다. 기존 예제 동작을 억지로 재사용하지 않는다. 사용자 요청의 베기 결과에 맞춰 B02 화웅의 규칙 결과도 사망으로 바꾼다.

본편과 일반 미리보기의 상황 설명·제목·진행 표시·키 안내를 없애고, 장수 초상·대사와 건너뛰기 버튼만 표시한다. 데모의 분석용 설명·조작은 명시적인 `-debug` 모드로 한정한다. 프로젝트 스킬은 `.agents/skills/duel-authoring/SKILL.md`에 두며 이야기 의도, 화자별 동작, 이동 경로, 승패 일치와 검증 절차를 안내한다.

개선 검증 완료: duel·content·core·gui·sim 테스트와 관련 vet, 게임·데모·시뮬레이터 빌드 통과. 실제 맵에서 종료·건너뛰기·사망 후 전투 복귀를 검증했다. 화웅 전개 15장 캡처로 강타 방어·공포·추격 베기 및 설명 없는 감상 화면을 확인했다. 프로젝트 스킬 형식 검증 통과. 콘텐츠 이름 독립성 검사에 맞춰 데모 장수 조합도 스테이지 데이터에서 읽고, 교차 돌진·직선 추격 동작 ID를 콘텐츠 ID와 구분했다.
