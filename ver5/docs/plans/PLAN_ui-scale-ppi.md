# UI 배율을 화면 전체에 (PPI 방식)

설정의 "UI 크기 80–160%"가 지금은 유닛 옆 명령 메뉴와 공격 예측 창에만 먹는다. 우하단 dock(부대 일람·위협 범위·
기록·자동 진행·진영 종료), 우상단 메뉴, 상단 바, 대화 두루마리 같은 나머지는 그대로다. 이 계획은 UI 배율을
특정 패널에 거는 확대가 아니라 **UI 한 칸(1 UI px)의 크기**로 바꿔서 모든 UI에 한 번에 먹게 한다.
같은 일로 화면 비율이 1280:850이 아닌 창·폰에서 생기는 레터박스도 없앤다.

## 지금 구조

- 모든 것이 고정 1280×850 레이아웃 좌표(`game.go:31`)에 그려지고, 전역 `scale = min(w/1280, h/850) ×
  DeviceScaleFactor` 하나로 기기 픽셀에 맞춘다(`game.go:758`). 프레임버퍼가 항상 1280:850이라 다른 비율의
  화면은 레터박스·필러박스가 생긴다.
- UI 배율은 `skin.go`의 `uiZoom/uiOX/uiOY`로, 한 점을 중심으로 그 블록만 키운다. 쓰는 곳은
  `command.go:292`(명령 메뉴)와 `command.go:583`(공격 예측) 둘뿐이다.
- `Width`/`Height` 상수를 테스트가 아닌 파일 25개에서 약 190번 쓰고, `1176`(메뉴 버튼), `312/1250/565`(두루마리),
  `420/453/580`(상단 바), `282/492/582`(턴 글자) 같은 절대 좌표가 많다.
- 그리기 순서는 이미 `layerMap`(맵) → `layerUI`(HUD)로 나뉘어 있다(`game.go:899–906`). 다만 커서 마름모·피해
  숫자·말풍선·명령 메뉴처럼 **맵 위 한 점에 붙는 UI**가 두 계층에 섞여 있다.
- 안드로이드는 `sensorLandscape` 고정이고 `DefaultUIScale = 130`(`mobile/mobile.go:30`), 노치(안전 영역)
  처리는 없다.

## 원칙: 비율 좌표가 아니라 "단위 + 기준점"

좌표를 화면 비율(가로 10%, 세로 5%)로 바꾸면 화면 비율마다 모양이 찌그러진다. 대신 이렇게 한다.

1. **가로세로가 같은 단위 하나**: 1 UI px은 가로든 세로든 같은 수의 기기 픽셀이다. 정사각형은 어느 화면에서나
   정사각형이다.
2. **배율은 그 단위의 크기만 바꾼다**: 160%면 1 UI px이 1.6배 커지고, UI가 보는 캔버스가 그만큼 작아진다
   (예: 1280×850 창에서 800×531).
3. **위치는 기준점 + px 간격**: "우하단에서 12px", "가로 가운데, 위에서 20px". 화면 크기에 따라 바뀌는 건 기준점뿐이고
   간격과 크기는 px 그대로다.
4. **비율은 늘어나야 하는 길이에만**: 상단 바 폭(화면 폭 꽉), 대화창 최대 폭(캔버스 폭까지) 같은 것. 모양은 안
   바뀌고 길이만 바뀐다.
5. **좁은 화면은 배치로 푼다**: 캔버스가 좁거나 세로로 길면 쌓는 방향을 바꾸거나 접는다. 늘리거나 줄여서 맞추지 않는다.

## 기준 화면: 스마트폰 가로

배치는 **스마트폰 가로 화면**을 기준으로 맞춘다. 데스크톱 창은 그보다 넓은 경우로 따라온다.

| 이름 | 기기 크기 | UI 배율 | UI 캔버스 | 역할 |
|---|---|---|---|---|
| 폰 기준 | 2400×1080 | 130% (안드로이드 기본) | 1453×654 | 모든 배치가 겹침 없이 들어가야 하는 기준 |
| 폰 최대 | 2400×1080 | 160% | 1180×531 | 가장 좁은 경우. 여기까지 겹치지 않아야 한다 |
| 4:3 태블릿 | 2048×1536 | 130% | 984×738 | 폭이 좁은 가로 화면 |
| 데스크톱 | 1280×850 | 100% | 1280×850 | 지금 모습과 같아야 한다 |

폰 가로 화면은 **높이가 낮고(531–654) 폭은 넉넉하다(1180–1453).** 그래서 위아래로 쌓는 요소(상단 바, 상세 패널,
dock, 전투 기록, 대화 두루마리)를 낮은 높이에 맞추는 게 이 계획의 대부분이다. 세로 화면은 이 계획에서 하지 않는다
(맨 끝 "나중에: 세로 화면" 참고).

## 좌표계

세 가지 공간을 둔다.

| 공간 | 단위 | 크기 | 누가 쓰나 |
|---|---|---|---|
| 기기 | 기기 픽셀 | 창·화면 그대로 | `Layout`, 터치·마우스 원시값 |
| 월드 화면 | 월드 px (`worldPx` 기기 픽셀) | `worldW × worldH` | 맵 타일·유닛·이펙트·카메라 |
| UI | UI px (`uiPx` 기기 픽셀) | `uiW × uiH` | HUD, 창, 대화, 배너, 맵에 붙는 UI |

```
base           = min(devW / 1280, devH / 850)   // 1280×850 설계가 창 안에 다 들어가는 크기
worldPx        = base
uiPx           = base × uiScale                 // uiScale = 설정 % / 100
worldW, worldH = devW / worldPx, devH / worldPx
uiW, uiH       = devW / uiPx,    devH / uiPx
```

- **설계 크기가 창에 다 들어가는 배율**을 기준으로 한다(skin.go `fit`). 지금 1280×850 창에서는 `base = 1`이라
  100%가 지금 모습과 같다. 100%에서 캔버스는 언제나 1280×850 이상이고, 남는 쪽(넓은 폰은 가로, 4:3 태블릿은 세로)은
  더 많이 보일 뿐 찌그러지지 않는다. 처음에는 짧은 변 기준(`min(devW, devH) / 850`)으로 적었지만, 그러면 4:3
  태블릿 100% 캔버스가 1133 폭으로 설계보다 좁아져서 바꿨다.
- `Layout`이 창 크기를 그대로 돌려줘서 레터박스가 없어진다. 맵은 화면을 꽉 채우고 넓은 화면에서는 더 넓은 범위를 보여 준다.
- 진짜 물리 PPI(인치당 픽셀)는 Ebiten이 주지 않는다. 안드로이드에서 `DisplayMetrics.xdpi`로 받아 `base`를 보정하는
  건 나중 단계(6)로 미룬다. 지금은 `DefaultUIScale = 130`이 그 역할을 한다.

### 맵에 붙는 UI

명령 메뉴, 공격 예측, 피해 숫자, 말풍선, 커서 근처 요약(brief)은 위치는 맵에서, 크기는 UI 단위로 정한다.

```
p := g.toScreen(cell)            // 월드 화면 px
q := worldToUI(p)                // × worldPx / uiPx
// q를 기준점으로 UI 공간에서 그린다
```

지금의 `withUI(x, y, f)`(한 점 중심 확대)와 `uiZoom/uiOX/uiOY`, `toLayout`, `uiBounds`는 없앤다. 모든 UI가 이미
UI 단위로 그려지니 필요 없다.

피해 숫자의 크기는 지금 카메라 줌(`g.zoom`)을 따른다(`damage_popup.go:69–104`). 이것은 "맵의 일부"로 보고 계속
줌을 따르게 하되 UI 배율도 곱한다. 숫자가 작아서 안 읽히는 문제는 UI 배율로 풀린다.

## 코드 구조

### 그리기 도우미

- 전역 `scale` 하나를 `uiPx`, `worldPx` 둘로 나누고, 그리기 도우미는 지금 그리는 공간의 `drawPx`를 쓴다(`inWorld` 안에서만 `worldPx`).
- `rect`, `strokeRect`, `write`, `label`, `drawScaled`, `fillPath` 등 `skin.go`의 도우미는 **UI 공간 전용**이 된다
  (`× uiPx`).
- 맵 쪽은 `field_render.go`의 캔버스 확대와 `game.go:941–948`의 비네이티브 맵 그리기에서만 `worldPx`을 쓴다.
  맵이 UI 도우미를 빌려 쓰는 곳(커서 마름모 `hud.go:59`, 투사체, 화면 번쩍임)은 `worldRect` 같은 월드용 도우미 몇
  개로 옮긴다. 개수가 적어서 따로 둔다.
- 캐시 키에 `scale`이 들어간 곳은 `uiPx`으로 바꾼다: `damage_popup.go:114`(숫자 글자), `duel_cutin.go:305`(빛나는
  글자), `top_bar.go:278`(이름패), 그리고 `*scale`로 직접 계산하는 SubImage 잘라내기(`dialogue_scroll.go:204`,
  `deployment.go:193`, `menu_panel.go:78`).

### 레이아웃 크기

- `Width`/`Height` 상수는 **설계 기준 크기(1280×850)** 로만 남긴다. 고정 캔버스를 쓰는 편집기와 일기토 장면,
  그리고 "기준 크기에서 이만큼" 같은 상한 계산에만 쓴다.
- UI 코드는 `uiW`, `uiH`(지금 프레임의 UI 캔버스 크기)를 쓴다. `LayoutF`에서 매 프레임 갱신한다.
- 기준점 도우미를 둔다. 많지 않게 한다.

```go
// anchored places a w×h box at margin m from the given corner of the UI canvas.
func (s uiCanvas) at(c corner, w, h, mx, my int) image.Rectangle
func (s uiCanvas) centre(w, h int) image.Rectangle
func (s uiCanvas) short() bool // 낮은 화면: uh < 700 (폰 가로)
```

### 입력

- `cursorPos()`는 UI 공간 좌표를 돌려준다(`/ uiPx`). 버튼·`block`·`hovered`가 모두 UI 공간이라 그대로 맞는다.
- 맵 칸 찾기(`updateHover`, `mapRelease`)는 `cursorWorld()`(`/ worldPx`)를 쓴다. "HUD 위인가"(`overHUD`)는 UI
  좌표로 따로 확인한다.
- 카메라 끌기·가장자리 스크롤·두 손가락 확대(`pointer.go:91–97`)는 월드 단위로 나눈다.
- 미니맵(`hud.go:607–623`)은 UI 안에 있지만 월드를 가리키므로 클릭 → 월드 변환을 한 군데에 모은다.

### 고정 캔버스 화면

편집기(`editor.go`, `editor_ui.go`)와 일기토 장면(`duelview`, 1280×850 고정 캔버스)은 배치를 다시 짜지 않는다.
이 둘은 지금처럼 1280×850 캔버스를 화면 가운데에 비율 유지로 그린다(이 화면들에서만 레터박스). 일기토 장면 위의
"건너뛰기" 버튼(`duel.go:120`)만 UI 공간으로 옮긴다.

## 단계

각 단계가 커밋 하나다. 각 단계 끝에 `go test ./internal/gui/... && go vet ./...`가 통과하고, `_uidemo-vm` 캡처를
전과 비교한다. 1·2단계는 **100%에서 화면이 한 픽셀도 바뀌지 않아야** 한다(캡처를 픽셀 단위로 비교).

1. **검증 도구**: `_uidemo-vm`에 `-size 2400x1080`과 `-uiscale 160` 플래그를 넣는다. 지금은 화면이 1280×850 고정이다.
   "기준 화면" 네 가지를 한 장에 모아 보는 `-sheet` 출력도 넣는다. `uiscale` 데모가 전장 HUD 전체(dock·상단 바·상세·기록)와
   대화 장면을 지나가게 고친다.
2. **단위 분리**: `scale`을 `uiPx`/`worldPx`으로 나누고, 월드용 도우미와 `cursorWorld()`를 만든다. 아직
   `uiPx == worldPx`, 캔버스는 1280×850 고정이라 화면은 그대로다.
3. **UI 배율을 단위로**: `uiPx = base × uiScale`. `withUI`/`uiZoom`을 없애고 명령 메뉴·공격 예측·피해 숫자·
   말풍선을 "맵에 붙는 UI" 방식으로 옮긴다. `Width`/`Height`를 쓰는 UI 코드를 `uiW`/`uiH`로 바꾼다. 이 단계에서
   160%에서도 모든 UI가 커진다. 아직 좁은 화면에서는 겹친다.
4. **레터박스 없애기**: `Layout`이 창 크기를 그대로 돌려준다. 짧은 변 기준 `base`, 맵 뷰포트가 화면 전체.
   편집기와 일기토 장면은 고정 캔버스로 그린다. 1920×1080, 2400×1080 캡처로 확인한다.
5. **기준점 배치와 낮은 화면 규칙**: 위 표의 △·× 요소를 기준점과 낮은 화면 규칙으로 옮긴다. 요소가 많아서 묶음별 커밋으로
   나눈다(5a 전장 HUD, 5b 대화·첫 등장·턴 글자, 5c 창·모달·결과·학습, 5d 타이틀·준비·출진).
6. **안드로이드 마무리 (선택)**: 노치 안전 영역(`WindowInsets`)을 UI 캔버스 여백으로 넘기고, `xdpi`로 기본 배율을
   보정한다.

## 위험과 미리 정할 것

- **맵 기준 크기**: 짧은 변 기준이면 넓은 모니터에서 맵이 지금보다 넓게 보인다. 카메라 범위 제한(맵 밖을
  너무 보여 주지 않기)을 다시 확인해야 한다.
- **글자 선명도**: UI 배율이 115%, 145%처럼 정수가 아니면 도트 부품(두루마리 4배 확대 같은)이 고르지 않게
  커진다. 도트 부품은 기기 픽셀 기준으로 정수 배에 맞춰 반올림한다. 두루마리 흔들림을 고친 것과 같은 종류의 문제다.
- **변경 범위**: `skin.go`와 UI 파일 20여 개를 건드린다. 2·3단계는 기계적인 바꾸기가 많아서 화면 변화 없음
  (100%)을 픽셀 비교로 지킨다.
- **6단계는 선택**이다. 1–5단계만으로 "UI 배율이 모든 UI에 먹는다", "레터박스 없음", "폰 가로 화면에 맞는 배치"가 끝난다.

## 나중에: 세로 화면

세로 화면은 이 계획이 끝난 뒤 따로 계획을 세운다. 가로 배치를 늘리거나 접는 방식이 아니라 **UI 구성을 따로** 둔다.

- 위쪽은 맵, 아래쪽은 조작·정보 영역. 지금 화면 여기저기 흩어진 상세 패널, dock, 명령 메뉴, 전투 기록을 아래
  영역에 모은다(탭이나 한 줄 버튼 묶음).
- 대화 두루마리와 장수 첫 등장도 아래 영역 안에서 보여 준다.
- 이 계획의 단위·기준점 구조(`uiPx`, `uiW`·`uiH`, 기준점 도우미, 맵에 붙는 UI)는 세로에서도 그대로 쓴다. 세로는
  `uh > uw`일 때 고르는 **배치 함수 묶음** 하나를 더 두는 것으로 한다. 그래서 이 계획에서 배치 코드를 요소마다
  "크기 계산 → 그리기"로 나눠 두면, 세로는 크기 계산 쪽만 새로 쓰면 된다.
- 안드로이드 `screenOrientation`을 `sensorLandscape`에서 `fullSensor`로 바꾸는 것도 그때 한다.

## 진행 결과 (2026-10-17)

1–5단계를 커밋했다. 데스크톱 1280×850 100%는 모든 데모에서 이전과 같다(창 합성 반올림으로 색값 ±1–2만 다름).

- **단위**: `skin.go`의 `uiPx`/`worldPx`/`drawPx`, `setUnits`, `fit`, `inWorld`, `worldToUI`, `cursorWorld`.
- **낮은 화면**(`lowScreen`, UI 캔버스 높이 830 미만): 오른쪽 320 폭 열에 미니맵, 장수를 고르면 그 자리에 전체 높이
  상세 패널. dock은 그 열 왼쪽 아래. 명령 패널은 상세 패널 왼쪽에 머물고, 하위 목록은 오른쪽에 자리가 없으면 왼쪽으로
  연다. 상단 바 목표 두루마리는 이름패에 가리면 두 줄로 접힌다.
- **창·설계 화면은 프레임**(`inFrame`, `inDesign`): 창, 모달, 결과, 학습, 완료는 자기 상자만, 타이틀과 출전 준비는
  1280×850 설계 전체를 프레임으로 그린다. 화면에 들어가면 설계 위치 그대로, 안 들어가면 그 프레임만 줄인다.
  버튼은 `addButton`/`block`이 화면 좌표로 바꿔 등록한다.
- **대화·첫 등장·턴 글자**: 캔버스 높이에 맞춰 두루마리 높이, 초상, 글자 크기를 줄인다(`dialogueBox`).
- **일기토**: 경기장 캔버스를 화면 비율로 넓히고(`duelview` `fit`), 장수 카드는 캔버스 모서리에 붙인다.
- **고정 캔버스**: 맵 에디터와 일기토 갤러리만 1280×850 그대로 가운데에 그린다.
- **확인 데모**: `uiscale`, `popups`, `deploy`, `duel`, `editor` (`_uidemo-vm -sheet`).

남은 것:

- 타이틀과 출전 준비는 설계 전체를 줄여 넣어서 폰에서는 글자가 100% 크기 정도로 작다. 폰 전용 배치는 따로 짠다.
- 6단계(안드로이드 노치·DPI)는 하지 않았다. 지금 `MainActivity`는 노치 모드를 바꾸지 않아서 가로 전체 화면에서
  안드로이드가 노치 쪽을 비워 두므로 UI가 가려지지 않는다. `xdpi` 기반 기본 배율은 실제 기기로 맞춰 봐야 정할 수 있다.
