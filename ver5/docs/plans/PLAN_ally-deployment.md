# 아군 배치 화면 개선 제안과 구현 계획

작성·마지막 갱신: 2026-10-10

상태: 1/2/3단계 구현 완료. 관련 테스트·정적 검사·실제 렌더링 검증 완료. 운영체제 입력 합성은 수행하지 않았다.
각 구현 단계가 끝나면 체크박스와 검증 결과, 갱신 날짜를 기록하고 통과한 뒤 다음 단계로 진행한다.

## 원하는 화면과 조작

배치 중임을 화면 전체에서 알 수 있게 한다. 배치 가능한 지면은 밝게 유지하고,
배치할 수 없는 타일·전투 영역 밖·적은 어둡게 표시한다. 왼쪽 전투 로그는 숨기고,
화면 아래 약 1/4에는 아군 장수 목록을 가로로 펼친다.

장수 카드를 누르면 해당 장수를 배치할 수 있는 상태가 된다. 실제로 놓을 수 있는 빈칸이
사인 함수로 1초에 한 주기씩 밝아졌다 어두워진다. 그 칸을 누르면 장수가 지도에 나타난다.
배치한 아군을 지도에서 다시 누르면 지도에서 사라지고 하단 목록의 미배치 상태로 돌아간다.

```text
┌───────────────────────────────────────────────────────────────┐
│ 아군 배치 · 배치 2 / 4                  메뉴                   │
├───────────────────────────────────────────────────────────────┤
│                                                               │
│       어두운 지도와 적                                         │
│                          밝은 배치 영역                        │
│                          선택 중이면 빈칸만 1초 주기로 강조     │
│                                                               │
├───────────────────────────────────────────────────────────────┤ ← 약 75%
│ 장수를 고른 뒤 밝은 칸을 누르세요. 배치한 아군 클릭: 배치 해제   │
│ [유비·미배치] [관우·선택] [장비·배치됨] [궁병·배치됨] …         │
│                                        2 / 4   [전투 시작]     │
└───────────────────────────────────────────────────────────────┘
```

### 사용자 요구를 구체화한 기본안

아래 항목은 구현을 위한 제안이며, 사용자가 이미 확정한 규칙과 구분한다.

- 목록에는 출전 준비에서 고른 `State.Deployment`의 장수를 순서대로 보여준다.
  전체 보유 장수의 출전 선택·장비·부관 설정은 기존 출전 준비 화면에서 한다.
- 배치 화면 진입 시 선택 출전 장수는 모두 미배치로 시작한다. 적과 스테이지 고정 아군은 이미 지도에 있다.
- 미배치 카드를 클릭하면 선택한다. 다른 미배치 카드는 선택을 바꾸고, 같은 카드를 다시 누르면 선택을 취소한다.
- 지도에 놓으면 선택을 해제한다. 배치된 장수를 지도에서 누르면 배치를 해제한다.
  배치됨 카드를 다시 눌러도 배치를 해제하도록 맞춘다. 장수는 목록에 계속 남는다.
- 배치 해제 후에는 자동으로 선택하지 않는다. 다시 카드 선택 → 빈칸 클릭으로 배치한다.
- 점유된 칸은 신규 배치 대상에서 제외한다. 현재 코드의 아군 위치 교환은 이 화면에서 사용하지 않는다.
- 출전 준비에서 선택한 장수를 모두 놓은 뒤 **전투 시작**을 누른다.
  군주도 배치 중에는 뺄 수 있지만, 미배치인 채로 전투를 시작할 수 없다.
- 출전 인원을 줄이려면 출전 준비에서 변경한다. 미배치 장수를 남긴 채 출전하는 별도 규칙은 이번 기본안에 넣지 않는다.
- 스테이지의 `Party` 고정 아군은 목록·배치 해제 대상에서 제외한다. 지도의 고정 아군은 원래 밝기로 표시한다.
- 목록이 길면 가로 스크롤을 제공한다. 초상화가 없으면 이름·병종으로 구별한다.
- 우클릭/Esc는 배치 선택을 취소한다. 배치 중에는 일반 이동·공격·대기·진영 종료를 실행하지 않는다.

## 현재 코드에서 흐름이 섞이는 이유

| 위치 | 현재 동작 | 바꿀 방향 |
|---|---|---|
| `internal/core/engine.go`의 `prepare()` | `start`가 즉시 `battle`에 진입하고 `Deployment` 장수를 `Allies[i]`에 자동 배치한다 | 출전 준비 다음에 명시적인 배치 단계 진입 |
| `internal/core/formation.go`의 `Deploying()` | 첫 아군 턴이며 누구도 `Moved/Acted/Done`이 아니면 배치 중으로 추정한다 | 저장되는 단계로 배치 여부 판정 |
| 같은 파일의 `place()` | 기존 아군을 이동시키고 아군 점유 칸이면 서로 위치를 바꾼다 | 미배치 장수 생성·배치, 배치 해제 지원 |
| `internal/gui/command.go`의 `mapClick()` | 배치와 전투 이동이 `ord.stage == "move"` 분기에 섞여 있다. 선택한 아군을 다시 누르면 행동 메뉴로 간다 | 배치 입력을 먼저 처리하고 종료하여 일반 명령과 분리 |
| 같은 파일의 `marks()` | 금색 배치 칸과 파란 일반 이동 범위가 함께 표시될 수 있다 | 배치 단계에서는 배치 표시만 반환 |
| `internal/gui/game.go`의 `battle()` | 안내만 추가하고 로그·일반 전투 버튼·행동 메뉴를 계속 그린다 | 배치 전용 HUD 분기 |
| `internal/gui/battle_log.go`의 `battleLogVisible()` | `battle/result`에서 표시하고 입력도 소비한다 | 배치 단계에서는 표시·입력 모두 비활성화 |
| `internal/gui/view.go`의 `advance()` | `clockMS`가 재생 속도 배율의 영향을 받는다 | 강조 주기는 배율과 독립적인 UI 시간 사용 |

특히 색만 바꾸면 **첫 행동이 배치 종료인 구조**, **미배치 상태가 없는 구조**가 남는다.
장수 클릭과 배치 해제를 정확하게 지원하려면 화면뿐 아니라 배치 상태를 정리해야 한다.

## 권장 상태 모델: `deployment` 단계 추가

```text
scenario/preparation -- start --> deployment -- deployment_finish --> battle
                                   │
                                   ├─ place 장수 x y
                                   └─ unplace 장수
```

`State.Phase`에 `"deployment"`를 추가한다. `Deployment`는 선택한 출전 명단을 계속 뜻하며,
`Units`에는 실제 지도에 놓인 아군과 적만 존재하게 한다. 따라서 출전 명단에는 있지만
`Units`에는 없는 장수가 미배치 장수다. 별도의 좌표 센티널이나 HP=0 표현은 쓰지 않는다.

이 구조를 권장하는 이유:

- 지도에서 사라진 아군은 점유 판정·미니맵·호버에도 자연스럽게 사라진다.
- `Character`는 계속 남으므로 배치 해제가 사망·퇴각·출전 명단 삭제가 되지 않는다.
- 배치 중 저장·자동 저장·불러오기가 엔진 상태만으로 재현된다.
- 배치 완료 후 누구도 행동하지 않았어도 `Phase == "battle"`이므로 배치 화면이 다시 열리지 않는다.
- 기존 `settle()`은 `battle`에서만 승패를 판정한다. 미배치 때문에 아군이 전멸한 것으로 처리되지 않는다.

GUI 안에 위치 초안을 따로 보관하는 방법은 초기 수정량이 작지만,
현재 `send()`가 명령마다 엔진 스냅샷을 자동 저장하므로 화면과 저장 상태가 어긋날 수 있다.
이번 흐름에는 엔진이 실제 배치를 소유하는 방식이 더 적합하다.

### 엔진 명령과 검증

| 명령 | 허용 단계 | 효과 |
|---|---|---|
| `start` | 출전 준비 | 체크포인트 생성, 적·고정 아군 생성, `deployment` 진입 |
| `place` | `deployment` | 출전 명단의 미배치 장수를 유효한 빈칸에 생성 |
| `unplace` | `deployment` | 선택 출전 장수의 유닛만 제거하고 캐릭터·장비·출전 명단 유지 |
| `deployment_finish` | `deployment` | 선택 장수 전체의 정상 배치 확인 후 아군 1턴 `battle` 진입 |

`place`는 유닛이 없는 장수에게도 적용하므로 `execute()`의 기존 `e.unit(c.Actor)` 검사보다
앞에서 배치 명령을 처리해야 한다. `unplace`는 ECS 유닛과 `unitIDs`를 함께 정리한다.
명령은 기존 `Apply()` 트랜잭션을 통과시켜 실패 시 상태·Revision·RNG가 바뀌지 않게 한다.
배치 생성·해제 이벤트는 즉시 화면에 반영하고 전투 이동·퇴각 애니메이션으로 재생하지 않는다.

`LegalActions()`에도 미배치 장수의 `place`, 배치한 장수의 `unplace`를 노출한다.
GUI의 강조 대상과 엔진의 허용 명령이 같은 배치 가능 판정을 사용하게 한다.
배치 완료 명령은 전체 명령이므로 actor 없이 조회 가능한 방식을 정한다.

유효한 칸은 `Stage.Allies`에 포함되고 전투 영역 안이며, 선택 장수가 들어갈 수 있는 지형이고,
살아 있는 적·아군·고정 아군이 점유하지 않은 칸이다. 전투 이동력·이동 경로·적 ZOC는 적용하지 않는다.
병종 지형 판정은 `rules.go`의 기존 지형 규칙을 재사용한다.

배치 해제와 재배치로 HP/MP·장비가 달라져서는 안 된다. 현재 선택 장수는 전투 행동 전이며
기본 `spawn()`이 HP 최대/MP 0으로 초기화한다. 배치 시 한 번 적용할 초기 자원 규칙을 명시하고,
향후 시작 효과가 들어와도 배치 클릭마다 재적용되지 않게 한다. 고정 아군의 `Spawn` 오버라이드는 그대로 유지한다.

### 저장과 고정 아군

`api.go`의 `Restore()`는 현재 phase 허용 목록, 출전 장수 전원의 유닛 존재,
유닛 수 `len(deploy)+len(stage.Enemies)`, 아군의 출전 명단 포함을 검사한다.
단순히 새 phase를 허용하는 것만으로는 부분 배치 저장을 읽을 수 없다.

- `deployment`에서는 선택 출전 장수의 일부 유닛 부재를 허용하되 배치된 장수의 칸·지형·중복 점유를 검사한다.
- 배치된 선택 장수는 `Allies`에 있어야 한다. 적과 `Stage.Party` 고정 아군은 별도로 검증한다.
- `battle/result`에서는 선택 출전 장수 전원이 유닛으로 존재해야 한다. 퇴각 유닛은 기존처럼 HP=0으로 남는다.
- 현재 `start`는 `Stage.Party`도 생성하지만 복원 검증은 위의 유닛 수와 명단 기준을 사용한다.
  고정 아군을 가진 맵의 시작/저장/복원 테스트로 이 불일치를 함께 확인하고 필요한 부분만 수정한다.
- 배치 중에는 Round=1, Turn=ally, Result 비어 있음, 정상 준비 체크포인트를 요구한다.
- 전투 단계 의미가 바뀌므로 `types.go`의 규칙 버전을 갱신하고 이전 세이브·리플레이의 호환 범위를 문서화한다.
  기존 호환 검사 정책에 맞추며 임의의 이전 저장 변환은 추가하지 않는다.

## 화면 구현 방향

### 하단 1/4 목록과 지도 영역

논리 화면 1280×850 기준 목록 높이는 약 212px, 상단은 약 y=638이다.
하단 전체를 불투명에 가까운 패널로 덮고 카드·선택 테두리·배치 상태·배치 수·전투 시작 버튼을 그린다.
기존 `portrait()`와 버튼/창 그리기를 재사용한다. 새 이미지나 스프라이트 작업은 필요 없다.

`internal/gui/deployment.go`를 추가해 배치 목록·선택 상태·클릭 처리를 모은다.
선택 장수 ID만 GUI에 두고 배치 여부는 항상 엔진에서 읽는다. 일반 전투의 `order`는 쓰지 않는다.

패널 영역은 `g.block()`으로 입력을 차단한다. 카드 밖 패널의 빈 곳도 지도 선택·드래그로 전달하지 않는다.
목록 안 휠과 좌우 버튼은 목록 스크롤에 사용한다. 현재 `camera()`의 우클릭 시작·화면 가장자리 이동도
HUD 영역을 검사해야 한다. 하단 패널 위에서 카메라가 움직이지 않도록 한다.

지도는 배치 중 상단 3/4를 viewport로 사용하여 배치 영역이 패널 뒤에 가려지지 않게 한다.
`toCanvas()/toScreen()`뿐 아니라 `battle()`의 `prepareRender`·DrawBounds·Native 배경 변환,
`camera()`의 경계·포커스·미니맵을 같은 viewport 기준으로 맞춘다.
전역 `viewport`를 임시 변경해서 맵에디터에 영향을 주기보다 게임 단계에 맞는 영역을 전달한다.

배치 단계에서는 일반 dock·행동 메뉴·전투 예측·위협 표시를 그리지 않는다.
상단에는 `아군 배치`와 배치 수를 표시한다. `terrainPanel()`은 숨겨진 로그의 높이에 기대지 않도록
목록 위로 옮기거나 배치 전용의 간단한 지형 안내로 바꾼다.
전투 시작 성공 시 선택/드래그를 초기화하고 전체 viewport·로그·전투 버튼을 복원한다.

### 밝기와 1초 주기

장수 미선택 시에는 배치 영역을 고정 밝기로 구분한다. 장수 선택 시에는 해당 장수의
실제 빈 배치 가능 칸만 강조한다. 이미 놓인 아군은 밝게 유지하고 점유 칸에는 맥동을 주지 않는다.
적은 항상 어둡게 유지한다. 어두운 영역은 검게 없애기보다 약 40~50% 밝기로 두어 지형을 읽을 수 있게 한다.

```go
// 설계 예시: t는 재생 속도와 독립적인 UI 경과 초.
p := (math.Sin(2*math.Pi*t) + 1) / 2
alpha := 0.12 + 0.18*p
```

강조는 한 번의 밝아짐/어두워짐이 1초인 완전한 주기다.
전역 UI 경과 시간을 `Update()`의 배율 적용 전 dt로 누적하면 선택을 바꿔도 주기가 끊기지 않는다.
현재 게임은 60TPS 고정 dt를 사용하므로 그 기준으로 시작하고, TPS 변경 시 실제 초 단위를 유지한다.
`g.clockMS`를 그대로 쓰면 ×4 재생에서 주기가 0.25초가 되므로 사용하지 않는다.
`cursor()`의 현재 `sin(clockMS/160)`도 배치 강조와 같은 시계·주기로 맞춘다.

`Field.Draw()`는 지면 → marks → 구조물/유닛 → 상태 표시 순서다.
marks만 추가하면 적·나무·구조물은 어두워지지 않는다. 다음 방식으로 처리한다.

1. 지면을 그린 뒤 배치 영역만 투명한 어두운 마스크를 합성한다. 외곽도 포함한다.
2. 실제 빈 배치 가능 칸에 기존 diamond를 사용한 금색/밝은 강조를 그린다.
3. 구조물·소품은 위치에 따라 밝기를 적용한다. 적 유닛은 위치와 무관하게 어둡게,
   아군 유닛은 원래 밝기로 그린다. HP바·상태표시·가려진 유닛 ghost도 같은 정책을 따른다.

Native/기존 맵 모두 `renderPoint()/renderOp()`와 지형 높이 `Lift()` 기준을 맞춘다.
지면 전체를 마지막에 어둡게 덮고 배치 칸만 뚫는 방식은 키 큰 아군의 몸까지 잘라 어둡게 만들 수 있어 피한다.
배치 마스크 이미지는 재사용하고 화면·지도 크기나 배치 가능 칸이 바뀔 때 갱신한다.
사인 값 변화만으로 지면 캐시나 대형 마스크를 매 프레임 새로 만들지 않는다.

`Observe()`가 배치 단계에서도 `Map`을 제공해야 한다. 미배치 카드의 병종·레벨·능력은
`Characters`와 기존 `CharacterStats()`를 사용한다. 유닛이 없으므로 `unitView()`에 의존하지 않는다.
`sync()`는 관찰에서 사라진 유닛의 이전 표시 상태를 정리해야 한다.

AI는 배치 명령을 일반 공격 점수 계산에 넣지 않고, 배치 단계에서 순서가 고정된 경로로 처리한다.
Space/P/스크린샷 자동 진행과 CLI `auto`, 시뮬레이터가 새 단계에서 멈추지 않게 연결한다.
자동 배치는 실패하면 이유를 반환하고 일부 장수만 놓인 상태에서 전투를 시작하지 않는다.
병종별 허용 지형 때문에 순차 배치가 막히는 경우에는 가능한 칸의 배정을 먼저 계산한다.

`request()`는 현재 이전 단계가 `battle`일 때만 명령을 리플레이한다.
배치 명령은 `send()` 후 즉시 `sync()`하고 전투용 이동 재생을 거치지 않는 흐름으로 정리한다.
맵에디터의 시험 전투도 같은 출전 준비 → 배치 → 전투 경로를 사용한다.

## 위험과 되돌리기

| 위험 | 가능성/영향 | 대응 |
|---|---|---|
| 새 phase에서 자동 진행이 멈춤 | 높음/높음 | 엔진 변경과 CLI/AI/sim 경로를 1단계에서 함께 완성 |
| 부분 배치 저장 또는 고정 아군 저장 복원 실패 | 높음/높음 | phase별 존재 규칙을 분리하고 저장 왕복 테스트 |
| 지도/마스크/클릭 좌표 불일치 | 중간/높음 | viewport 계산 통일, Native/기존 맵 및 확대별 확인 |
| 배치된 아군의 머리·상태표시까지 어두워짐 | 중간/중간 | 지면 마스크와 유닛 밝기 분리, ghost/상태표시 확인 |
| 진행 중인 맵에디터 변경과 충돌 | 중간/높음 | 현재 작업을 보존하고 관련 부분만 수정 |
| 자동 배치의 지형 제약으로 막힘 | 중간/중간 | 허용 칸 배정을 검증한 뒤 완료, 실패 이유 반환 |

각 단계는 그 단계에서 추가한 변경만 되돌린다. 1단계는 엔진과 CLI/AI/sim·버전 변경을 한 단위로,
2단계는 입력/목록/viewport 변경을 한 단위로, 3단계는 밝기/시계/마스크를 한 단위로 되돌릴 수 있게 한다.
작업 중이던 다른 변경을 포함하는 파일 전체 복원은 하지 않는다.

### 최종 구현 기록 (2026-10-10)

- `Phase == "deployment"`를 저장되는 독립 단계로 추가했다. 선택 장수는 지도에서 없는 상태로 시작하며, 적·고정 아군은 그대로 생성된다.
- `place`, `unplace`, `deployment_finish`는 엔진 트랜잭션을 통과한다. 실패한 명령은 Revision·RNG·캐릭터·유닛 상태를 유지한다.
- 배치 좌표·점유·병종 지형을 검증하며 교환 배치는 제거했다. 전체 배치 후에만 전투를 시작한다.
  선택 장수의 시작 자원은 최대 HP·MP 0이며, 배치 중 자원 변경 명령과 변경된 자원의 저장 복원을 거부한다. 고정 아군의 시작 HP/MP·병종·방향은 유지한다.
- 부분 배치 복원은 선택 장수의 유닛 부재를 허용한다. 고정 아군과 적의 존재·진영·원래 위치·자원은 배치 단계에서 검증한다.
- 자동 배치는 이분 매칭으로 모든 미배치 장수의 칸을 먼저 계산한다. 실패 시 배치 명령을 반환하지 않는다.
  CLI `auto`는 배치를 끝내면 멈추며 첫 아군 턴 행동을 이어서 실행하지 않는다. GUI Space/P, AI, 시뮬레이터, JSON CLI 연동을 갱신했다.
- 아래 약 1/4의 장수 카드에 미배치·선택·배치됨을 표시하고, 휠·좌우 버튼으로 가로 스크롤한다.
  카드 클릭과 지도 클릭으로 배치·해제를 처리한다. 카드와 패널 빈 공간은 지도 입력을 차단한다.
- UI 시계를 재생 배율과 분리하고 빈 배치 가능 칸만 1초 주기로 강조한다. 배치 지면은 밝게, 나머지 지면·구조물·적은 약 45% 밝기로 표시한다.
  배치된 아군·고정 아군과 가림 시 표시하는 아군의 몸은 밝게 유지한다. 지면 마스크는 재사용하며 카메라·배율·화면 크기·배치 영역이 바뀔 때 갱신한다.
- 배치 중에는 로그·행동 메뉴·진영 종료·위협 범위를 숨긴다. 단계별 viewport를 화면 변환·카메라·미니맵·렌더링에 사용한다.
- 규칙 버전 `rules-9`, AI 정책 `greedy-6`. 이전 규칙의 저장·리플레이는 기존 호환 검사에서 거부하며 자동 변환하지 않는다.

- 전체 `go test ./...`에서는 별도 추가된 `cmd/srpg-duel`·`internal/duel`의 게임 이름 직접 사용으로 `TestEngineSourceNamesNoGameContent`가 실패했다.
  해당 파일은 배치 작업의 변경 대상이 아니다. 배치 관련 패키지 검증 결과와 구분한다.

### 배치 미리보기

선택한 미배치 장수의 합법적인 배치 칸을 가리키면 실제 병종·개인 팔레트의 유닛을 50% 불투명도로 표시한다.
실제 배치와 같은 남동 방향·지형 높이를 사용한다. 미리보기는 Field.Canvas 위에 그려 카메라 배율을 함께 적용하며 규칙 상태·유닛 목록을 변경하지 않는다.
선택 해제·배치 완료·배치 불가 칸·HUD 및 창 위에서는 숨긴다. 컨트롤러 경계 테스트와 실제 렌더링 캡처로 확인한다.
