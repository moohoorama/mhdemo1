# 법정: 지계 치명타와 보복 특성 설계안 (제안)

게임 데이터(ver5/assets/data/*.json)와 코드는 바꾸지 않았다. 아래는 모두 제안이다.
사용자 방향: 법정은 공격적인 책사다. 지계(토계, 특히 거암)를 치명타로 쓰고, 보복의 성격을 띤다. 단 "나를 친 적을 기억했다가 나중에 되갚는" 효과는 만들지 않는다(현실성·쓸모·구현 복잡도 때문에 거절).

## 한눈에

| 안 | 쉬운 말 효과 | 비용 | 코드 변경 | 보복 느낌 |
|---|---|---:|---|---|
| A. 지공 | 지계 공격 책략이 명중하면 반드시 치명타. | 700 | 없음 (데이터만) | 약함 (치명 보장만) |
| B. 되갚음 (가칭 "추살지계") | 병력이 절반 이하인 적에게 지계 책략이 반드시 치명타. | 1000 (안) | 작음 (critForced에 지계 전용 분기 1개) | 중간 (이미 다친 적을 끝까지 친다) |
| C. 토석위력 | 지계 책략의 피해 +30%. | 700 (안) | 없음 (데이터만) | 약함 (순수 수치) |

**추천: A(지공)를 법정의 핵심으로. B는 A와 함께 밸런스 검증을 거친 뒤 추가. C는 보류.**

## 기존 코드 확인 (사실 확인, 파일 근거)

- 치명타 강제 판정: `ver5/internal/core/combat.go` `critForced()`(약 191행).
  - 책략(`s.Kind == KindMagic`)은 `FxSpellCrit`(심모)와 `e.fx(u, FxCritElement + s.Element) > 0`로 강제된다. `FxCritElement`는 `"crit:"` 접두어다(`internal/content/vocab.go` 99행). 화공 `crit:fire`, 수공 `crit:water`가 이 키를 쓴다. **지공은 `"crit:earth": 1`만 넣으면 된다.**
  - `FxCritWounded`(`crit_vs_wounded`, 추살)는 물리·책략 구분 없이 첫 분기에서 검사한다. 즉 추살은 이미 지계 책략에도 반드시 치명을 준다. 안 B는 이 키를 지계에만 한정하는 것이다.
- 치명타 배율: `combat.go` `boost()`. 치명이면 `Rules.CritMultiplier`(game.json, 1.5) - 1 + `crit_boost`(치명타강화, +0.75)만큼 더해진다. 책략 명중 시 치명 확률 판정은 `strike()`에서 `critForced`가 참이면 건너뛴다.
- 치명은 명중한 뒤에만 판정된다. `strike()`에서 `hit`이 먼저 정해지고 그다음 `crit`이 정해진다. 따라서 지공은 "명중 보장"이 아니라 "명중하면 치명"이다. 거암 명중률 110 기준으로 실제 명중률은 `hitChance`를 따른다.
- 위력: `damage()`에서 책략은 `FxPower + element`(`power:earth`)로 위력이 오르고, `FxFinisher`(집요)로 잃은 병력 비율에 따라 오른다. 안 C는 `power:earth` 키를 쓴다.
- 지계 책략: `ver5/assets/data/skills.json`에 낙석(24 마력, 계수 1), 산사태(계수 1.5), 지진(범위 십자, 계수 0.7), 거암(단일, 계수 2, 명중 110, 마력 48), 지룡(십자, 계수 1), 낙진(사각 0.25)이 있다. 거암은 `Element: "earth"`, `Mode: "any"`, `Min 1 Max 2`다. 거암 해금 조건은 classes.json 책사 Plan에 `earth_boost`(지계강화, Lv 39)가 있어 그쪽으로 보이나 **정확한 게이팅은 미검증**이다.
- 지형 보너스: `internal/content/terrain.go` `ElementTerrain`에 따르면 지계는 황무지·언덕에서 위력이 오른다(Rules.ElementTerrain). 이미 지형 연동이 있으므로 "산에서 강하다" 설명은 중복일 수 있다.
- 기존 특성의 역할 (traits.json):
  - 화공 `crit:fire` (700, 선행 화계) / 수공 `crit:water` (500, 선행 수계) / 화신 `power:fire 0.2 + sure:fire + crit:fire`.
  - 심모 `spell_crit` (500): 성공한 책략 전부 치명.
  - 추살 `crit_vs_wounded` (1000): 병력 절반 이하에게 반드시 치명.
  - 집요 `finisher 0.5` (500): 잃은 병력 비율의 절반만큼 책략 위력 증가.
  - 응징 `retaliate` (500): 물리 반격 전용, 책략에는 반응하지 않는다.
  - 격파 `absorb_mana` (700): 사용자 결정에 따라 법정에게 배정 유지.
  - 귀모 `spell_range +2` (500).

## 안 A: 지공 (추천, 코드 없음)

- 이름 후보: 지공(화공·수공과 같은 짝). 쉬운 이름을 원하면 "토석 필중"도 가능. 특성 이름은 효과가 읽히도록 쉽게 짓는다는 기존 원칙을 따른다.
- 설명: 지계 공격 책략이 명중하면 반드시 치명타가 된다.
- 데이터 초안 (traits.json에 추가, 형식은 화공과 동일):
  ```
  "earth_crit": { Name 지공, Desc "지계 공격 책략이 명중하면 반드시 치명타가 된다.", Kind talent, Tone craft, Cost 700, Requires ["earth"], Effects {"crit:earth": 1} }
  ```
  키 이름은 기존 명명을 따르면 된다(화공은 `firecraft`, 수공은 `flood`). 키가 `earth_crit`일지 `earthcraft`일지는 정하면 된다.
- 학습: 법정은 군사(strategist)이므로 Plan에 지계(earth, Lv 20)가 있다. 장수 개인 특성으로 붙이므로 병종 Pool은 바꾸지 않는다.
- 코드 변경: 없음. 데이터 한 항목과 장수 Traits 목록 추가만 필요. 다만 테스트 데이터 `internal/testdata/mini/traits.json`에는 화공 등이 들어 있으므로 필요하면 같은 형식으로 추가한다(선택).
- 장점: 기존 화공·수공과 완전히 같은 구조. 코드 위험 없음. 지계 책략이 정확히 "치명 보장" 역할을 맡는다. 거암(계수 2)과 만나면 한 방이 크다.
- 단점: 심모(성공 책략 전부 치명)·화신(화염계 치명)과 같은 계열이라 법정이 심모를 함께 가지면 치명이 겹친다. 지공이 생기면 지계 책략 명중 시 치명 확률이 100%가 되어 체감 밸런스를 확인해야 한다. 법정이 화공을 가지면 역할이 "화계 치명 + 지계 치명"으로 같아 보이는 문제가 있다.
- 미검증: 실제 수치(거암 기준 피해). 계산 예: 기본 피해 × 계수 2 × 치명 1.5 = 기본의 3배(명중 시). 실제 전투 식은 방어·마력 보정 등이 더 들어가므로 자동 전투 시뮬레이션(cmd/_balance 등)으로 확인해야 한다.

## 안 B: 되갚음 (추살의 지계 전용판, 코드 작음)

- 이름 후보: "추살지계"(추살을 지계에 맞춘 이름), 또는 "끝까지 몰아침". 보복 느낌을 살리려면 이름보다 설명에서 "이미 다친 적을 끝내는" 행동으로 쓴다.
- 설명: 병력이 절반 이하인 적에게 지계 책략이 반드시 치명타가 된다.
- 효과: 기존 추살과 같은 조건(병력 절반 이하)이지만 지계 책략에만 적용한다. 대상의 과거 피해 이력은 보지 않는다. **지금 상태만 본다.** 따라서 추적·반격 구조가 아니다.
- 코드 변경 (작음):
  1. `ver5/internal/content/vocab.go`에 접두어 키 추가, 예: `FxCritWoundedElement = "crit_vs_wounded:"`. 기존 `FxCritElement`처럼 목록(약 144·151행)에도 넣어야 검증을 통과한다(목록 검사 여부는 확인 필요).
  2. `ver5/internal/core/combat.go` `critForced()`의 책략 분기에 추가:
     `if e.wounded(v) && e.fx(u, content.FxCritWoundedElement+s.Element) > 0 { return true }`
     (기존 `FxCritWounded` 블록은 그대로 두어 추살 동작을 바꾸지 않는다.)
  3. 테스트: `internal/core/traits_test.go`에 "지계 + 절반 이하 적 → 치명", "지계 + 멀쩡한 적 → 비치명 가능", "화계 + 절반 이하 → 기존 규칙 그대로" 세 가지를 추가.
- 장점: 보복 느낌이 가장 강하다. 법정이 "이미 상처 입힌 적을 지계로 끝낸다"는 행동이 읽힌다. 추살(물리 중심 특성)과 역할이 나뉜다. 실제 이력 추적이 없어 구현이 단순하다.
- 단점: 추살과 기능이 거의 같아 보일 수 있다(지계 한정). 안 A와 함께 쓰면 "상처 입은 적에게 지계 명중 치명, 명중하면 치명"이 겹쳐 보인다. 집요(잃은 병력만큼 위력 증가)와도 역할이 겹친다. 즉 법정이 집요·추살계열을 함께 가지면 "상처 입은 적"을 두 번 보상하는 구조가 된다.
- 미검증: 1000 비용은 추살과 맞춘 임시값이다. 과도한지는 밸런스 검증이 필요하다.

## 안 C: 토석위력 (데이터만, 보류 추천)

- 설명: 지계 책략의 피해가 30% 오른다.
- 데이터: `Effects {"power:earth": 0.3}`. 코드 변경 없음.
- 장점: 쉽고 안전하다. 치명과 무관하게 지계를 강하게 만든다.
- 단점: 보복·공격성 느낌이 약하다. 지계강화·확산 같은 기존 강화책과 겹치고, 거암 계수 2에 곱해지면 과도할 수 있다. 특성 이름이 수치로만 읽힌다.

## 법정 특성 구성 제안 (참고)

법정의 개인 특성 슬롯은 기존 draft(격파·귀모·집요·화공)와 사용자 결정(격파는 법정에게)을 그대로 두고, 보복 방향을 넣는 방식으로 제안한다.

- 격파 (유지, 사용자 결정)
- 지공 (안 A, 신규 추천)
- 귀모 (유지, 단 제갈량과 중복 허용 여부 확인 필요)
- 화공 또는 집요 중 하나 (안 B를 넣으면 집요를 빼는 것을 검토)

화공을 지공과 같이 두면 "화계·지계 모두 치명"이 되어 공격성은 강해지지만 특성 설명이 비슷해진다. 이 경우 화공 대신 지공을 두는 것을 검토한다. 이는 기존 화공 결정과 충돌할 수 있으므로 사용자 확인이 필요하다.

## 추천

1. 안 A(지공)를 법정의 핵심 특성으로 쓴다. 코드 없이 가능하고 화공·수공과 같은 구조라 설명이 쉽다.
2. 보복 느낌을 더하려면 안 B를 추가하되, 먼저 A만으로 자동 전투에서 지계 치명의 체감 강도를 확인한다. B는 그 다음에 코드 변경으로 추가한다.
3. 안 C는 지금은 넣지 않는다. 거암 계수와 곱해져 과도해지기 쉽다.

## 미검증 항목과 열린 질문

1. 거암 해금 조건(지계강화·확산 중 어느 것이 필요한지)은 코드에서 확인하지 못했다. 설명은 classes.json과 skills.json 기준으로만 적었다.
2. 치명·위력 수치(3배 등)는 계산 예일 뿐이다. 실제 밸런스는 시뮬레이션이 필요하다.
3. 안 B의 `FxCritWoundedElement` 접두어 키가 검증 목록에 어떻게 들어가는지는 vocab.go 전체를 읽어야 확정된다.
4. 지공과 심모의 중복(성공 책략 치명 + 지계 명중 치명)을 허용할지 정해야 한다.
5. 법정 화공 배정과 지공 추가가 충돌하는지(사용자 결정 확인).
6. 이전 버전(같은 폴더의 이전 design.md)은 이번 설계로 대체했다. 이전 안의 "보복 = 병력 최대보다 적은 적에게 책략 피해 +20%"는 기존 집요(finisher)와 같은 수식 구조라 중복이다. 이전 안의 "지공"은 안 A와 같다.
7. 정사 근거: 법정이 "은혜와 원한을 갚는" 성격이라는 이전 draft의 기록은 확인하지 못했다. 지계·보복 효과는 게임상 해석이다.
