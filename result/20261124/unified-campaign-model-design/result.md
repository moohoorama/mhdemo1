# 목표를 이해하는 단일 캠페인 모델 설계

## 목표와 범위

모든 스테이지와 매 턴에 **같은 정책 가중치 하나**를 사용한다. 스테이지 ID로 가중치를 선택하거나 장별 행동을 강제하지 않는다. 전투 목표, 지도, 아군·적, 현재 합법 행동을 입력으로 받는다. 전체 캠페인을 잘 플레이한다는 것은 전투의 연속 승리뿐 아니라 지속되는 장비·소모품·돈·성장·편성도 고려한다는 뜻이다. 처음에는 이야기 진행과 상점을 기존 규칙으로 유지하는 전투 모델을 만들고, 이후 준비와 소비 결정을 같은 정책으로 넓힌다. 이 구분은 최종 목표가 아니라 검증 가능한 개발 순서다.

## 현재 코드에서 출발

- `BattleInputs`는 행동 가능한 아군 전체의 엔진상 합법 명령을 후보로 나열하고, 64개 전장 요약과 후보별 64개 특징을 만든다. 승리 대상인 적과의 거리·해당 적 공격 여부는 이미 포함한다.
- `GoalInputs`는 영역 목표의 위치·거리 등 8개를 더하지만 선택 사항이며 일부 전투 전용 모델에서만 활성화되어 있다. 승리 외 패배·부목표 및 여러 목표의 구조 전체를 표현하는 것은 아니다.
- 현 배포 모델은 `StageModels`로 여러 스테이지 전문가를 선택한다. 준비에도 별도 모델이 있고, 승급·이야기·상점 등은 규칙 기반이다.
- 현재 모델과 학습 기록은 보존한다. 학습되지 않은 새 목표 입력의 가중치를 0으로 추가하면 초기 동작은 유지할 수 있지만 목표를 이해하게 되는 것은 아니며 추가 학습이 필요하다.

## 관측: 목표를 구조화해 제공

플레이어가 볼 수 있는 현재 정보만 모델에 제공한다. 숨겨진 복병 위치·미발동 사건 조건·미래 목표는 노출하지 않는다. 엔진이 허용 명령 및 피해/명중 미리보기를 제공하는 것은 기존 게임의 계산 범위와 정책을 명시하고 고정한다. NPC나 GUI에서 볼 수 없는 전투 AI 내부 계획·무작위 결과는 주지 않는다.

- 목표: 현재 승리·패배·부목표를 별도 목록으로 인코딩. 종류(격파/생존/도달/전원 도달/턴 버티기 등), AND/OR, 목표 주체와 대상, 목표 영역, 진행도, 남은 턴, 현재 유효/완료 상태를 포함한다. 목표가 바뀌면 즉시 갱신한다. 목표 ID나 스테이지 이름이 아니라 그 역할·조건을 입력한다. 여러 목표, 복합 조건, 보호 대상 여러 명, 다수 영역을 표현하며, 최대 개수/마스킹·초과 정책을 명세한다. 표시되지 않은 숨은 부목표는 제외한다.
- 전장: 타일 지형·이동 비용·장애물·위험과 영역, 턴 제한. 거리만이 아닌 실제 통행 가능 경로와 우회 비용을 전달한다.
- 유닛: 아군·동맹·적의 위치, 병력·병법, 행동 여부, 사거리·이동, 클래스 효과, 상태이상, 군주/보호 대상/목표라는 역할. 이름 대신 역할·효과 중심으로 인코딩하며, 노출되지 않은 정보는 제외한다.
- 캠페인: 현재 보유 장비·아이템·돈, 장수 상태 및 합법적인 준비 선택지. 출전 가능한 정보와 이후에 공개될 내용을 구분한다.
- 행동: 엔진의 합법 후보마다 행위자·행동 종류·위치/대상·비용·예상 효과·아군 피해·목표와의 관계를 동일 규칙으로 계산한다. 불법 행동을 애초에 후보에서 제외하고 학습과 실제 실행의 후보 생성이 같아야 한다. 대상이 없는 강화·범위·회복도 효과를 구별한다.

예: 유비가 지정 구역에 도달해야 한다면 목표 유형은 ‘아군 특정 장수 도달’, 주체는 유비 역할, 영역은 현재 좌표다. 유비가 이동할 때 그 후보가 실제 이동 가능한 거리와 목표 접근도를 얼마나 바꾸는지 평가한다. 적 지휘관 격파에서는 목표가 해당 적으로 바뀐다. 목표 영역을 1개 숫자에 압축하지 말고 복수 조건을 유지한다.

## 모델 구조

첫 시도는 현재 후보별 점수 모델을 확장한 **공유 인코더 + 공유 행동 점수망**이다. 목표·유닛 목록은 같은 함수를 적용해 집계하고, 지도는 작은 격자 인코더로 요약한다. 이를 각 후보 행동 특징과 결합해 점수를 매기고 최고 합법 행동을 선택한다. 맵·장수 수가 달라도 같은 가중치를 쓰며, 고정 상한이 필요하면 명시적 패딩과 마스크를 쓴다. 작은 모델부터 시작해 표현력 부족이 실제로 드러날 때만 attention/GNN을 비교한다.

준비와 전투를 모두 하나의 정책에 넣을 때는 공통 상태 표현에 `행동 단계`와 각 합법 후보의 유형을 넣는다. 하나의 공유 정책 가중치로 준비·전투 후보를 모두 점수화한다. 각 단계의 입력 어댑터나 보조 가치망은 구현에 필요할 수 있지만 전투별 전문가나 장별 정책은 두지 않는다. 이야기 선택·상점을 포함하면 후보 규격과 목표 함수를 먼저 정의해야 하므로 초기에 검증된 규칙을 사용한다.

값(value) 예측은 학습 보조용으로 둘 수 있다. 모델 구조가 바뀌면 기존 가중치를 그대로 합치는 대신 입력 확장·전이 방법과 원래 체크포인트를 별도 보존한다. `StageModels`는 실행 선택에서 사용하지 않는다.

## 학습

1. **계측과 데이터 고정.** 콘텐츠·코드·특징 버전·시드·모델 SHA를 기록하고, 기존 모델과 규칙 탐색의 정확한 기준 성능을 잰다. 기존 학습 파일과 보고서를 보존한다.
2. **교사 데이터로 시작.** 기존 탐색 AI, 기존 전문가 모델, 성공한 실제 전투 기록의 후보별 결정을 모아 하나의 공통 정책에 모방 학습한다. 교사의 스테이지별 결정은 정답 보장이 아니므로 승패·선택 출처를 기록하고 실패 경로도 별도 유지한다. 학습과 평가는 동일한 목표 입력·합법 후보를 쓴다.
3. **다양한 전투로 강화학습.** 각 목표 유형, 초중후반 전투, 실제 캠페인에서 얻은 준비 상태를 섞는다. 상대적으로 어려운 상태를 더 자주 뽑되 쉬운 전투도 일정 비율 남겨 잊지 않게 한다. 시작 상태를 저장해 재현하되 진짜 이어진 캠페인 평가와 구별한다. [Prioritized Level Replay](https://proceedings.mlr.press/v139/jiang21b.html)는 학습 잠재력이 큰 레벨을 다시 뽑는 접근의 근거다.
4. **캠페인 연결.** 새 게임부터 실제 돈·장비·경험치·인원으로 이어 가고 첫 패배까지의 진척과 완주를 최우선 평가한다. 처음엔 기존 준비 규칙을 고정하고 이후 같은 정책으로 장비·소모품·편성을 단계적으로 포함한다. 장기 보상만으로 학습이 어려우므로 전투 승패·부목표 진행 등 보조 신호를 쓰되, 보조 신호 때문에 승리를 미루거나 물자를 낭비하지 않는지 별도로 검증한다.
5. **반복과 회귀 방지.** 새로운 정책의 실제 실패 상태를 학습 집합에 보태고, 고정된 검증 시드 및 전투군의 성능이 떨어지면 이전 모델을 유지한다. 이전 전문가를 교사로 쓰는 것과 배포 시 전문가를 선택하는 것은 다르다.

기본 알고리즘은 기존 Go PPO와 모방 학습부터 비교한다. 지도·목표 정보를 개선했을 때의 효과를 먼저 측정한 뒤 아키텍처나 알고리즘을 바꾼다. 강한 모델을 만들려면 필요한 시행 횟수와 컴퓨팅 비용이 크고, 어떤 구성이 실제로 더 좋은지는 실험 전에는 단정할 수 없다. 알파스타와 같은 대규모 연구의 자원을 그대로 전제하지 않는다.

## 검증 및 합격 기준

- **단일성:** 하나의 배포 체크포인트, 하나의 정책 가중치, 전투 ID별 분기·전문가 없음. 학습용 교사/가치망은 배포 정책과 구분한다.
- **목표 인지:** 격파·특정 인물 도달·전원 도달·보호·생존·목표 변경·AND/OR를 각각 테스트. 동일한 맵/병력에서 목표만 바꾼 짝 사례로 입력과 행동의 차이를 살핀다. 목표 조건 표현의 단위 테스트와 모델의 통계적 행동 평가를 분리한다.
- **전투 범위:** 전투별 승률, 승리 조건별 성공률, 제한 턴 초과, 군주 퇴각, 부목표, 소모품·아군 손실을 기존 탐색 및 기존 전문가 묶음과 같은 초기 상태/시드로 비교한다.
- **캠페인:** 정상 새 게임·재도전 없이 첫 패배 전 연속 승리 수와 완주율을 보고, 평균뿐 아니라 중앙값·최저·분포·신뢰구간을 공개한다. 학습/개발/최종 평가 시드를 완전히 분리한다. 예시 규모는 개발 16~32, 최종 100 이상을 목표로 하되 계산 비용에 맞춰 사전에 결정한다. 수치 합격 문턱은 기존 기준을 먼저 잰 뒤 정한다.
- **일반화:** 미사용 RNG뿐 아니라 장수 조합·합법 장비·지도 변형·목표 조합 또는 학습에서 제외한 전투로 평가한다. 시드만 바꾸면 같은 전투를 암기한 정책도 통과할 수 있다. Procgen 연구는 다양한 환경과 별도 평가가 중요함을 보인다. [Procgen](https://proceedings.mlr.press/v119/cobbe20a.html)
- **안전한 이행:** 예측 입력과 목표 변화, 범위 공격·상태이상·경로·재고 지속성을 검증한다. 같은 상태에서 학습·실행 후보를 비교하고 실제 엔진에 적용 가능한지 확인한다. 기존 모델은 별도 백업하고 새 모델이 기준을 넘기 전에는 기본으로 바꾸지 않는다.

## 게임 변경과 모델 호환성

현재는 콘텐츠 전체 바이트 해시가 다르면 실행을 거부하므로 대사 변경도 정책을 막을 수 있다. **전체 해시를 없애거나 임의로 덮지 않는다.** 전체 콘텐츠 해시는 출처·재현에 남기고, 모델 실행에 필요한 특징 스키마·행동 의미·규칙 버전을 별도로 정의하는 방안을 검토한다. 단순 스토리 문구 변경과 능력치·맵·승리 조건 변경을 다르게 분류하되, 규칙이 같다고 해서 새 전투에서 잘한다는 뜻은 아니다. 의미적 호환성 검사는 API/형식 안전만 확인하며 성능과 일반화는 별도의 재평가로 판단한다. 실패시 원인(모델 없음/손상/스키마 불일치/콘텐츠 변경)을 화면에 구별해 표시한다.

## 제안 단계와 게이트

- [ ] 1. 현 모델/탐색 기준 측정 및 목표 유형 표 작성. 게이트: 재현 가능한 고정 상태·시드·결과.
- [ ] 2. 목표 구조와 공통 후보 입력 추가. 게이트: 복합 목표와 변경, 비공개 정보 누출, 후보 일치 테스트.
- [ ] 3. 전문가 선택 없는 단일 정책 모방 학습. 게이트: 고정 비교 및 정책이 모든 전투를 오류 없이 실행.
- [ ] 4. 공통 전투 정책 강화학습·학습 분포 조정. 게이트: 목표별 회귀와 미사용 상태 평가.
- [ ] 5. 정상 캠페인에서 준비/자원까지 단일 정책으로 확장. 게이트: 장기 자원 보존과 첫 패배·완주 측정.
- [ ] 6. 별도 호환성 관리와 디버그 UI에 검증된 체크포인트 연결. 게이트: 저장/복구, 오류 표시, 예전 모델 보존, 실제 GUI 실행.

위 단계는 순서와 품질 기준에 관한 제안이며 학습 비용/기간 추정이나 구현 착수 승인은 아니다.
