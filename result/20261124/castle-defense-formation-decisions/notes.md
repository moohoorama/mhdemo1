# 번궁 화공 교체·수성 지형 확장·방진 구상 기록

기록만 했다. 게임 코드·데이터는 바꾸지 않았다. 요청: `process/castle-defense-formation-decisions-20261124/castle-defense-formation-decisions-20261124.md`

## 1. 결정 기록 (사용자 결정, 게임 미반영)

1. 번궁: 고유 특성 반격강화(`counter_boost`)를 화공(`firecraft`)으로 교체한다. 보법은 유지한다.
2. 수성 적용 지형: 성·성내에 더해 관문과 열린 성문을 포함한다. 발상은 순욱의 연주 수성.
3. 방진 구상: 주변 8칸 아군 1기마다 자신의 방어력 +4%(0~8기, +0~32%, 자신 제외). 사세삼공과 비교 대상. 이전의 "물리 피해 −10%" 안은 이 요청으로 대체된다.

## 2. 검증 사실

### 2-1. 번궁과 화공

- 번궁(`fangong`): `ver5/assets/data/characters_story.json:593-620`. Traits·Learn 모두 `footwork`(보법)와 `counter_boost`(반격강화). 직업 `fist_saint`(권성, `classes.json:1559`). 소개문: "주먹 못지않게 지형을 읽어 불을 놓는 데 밝다". 화공 방향과 맞는다.
- 반격강화 `counter_boost`: `traits.json:73-80`, 비용 1000, 반격 피해 비율 +50%p. 번궁 외 보유자는 없다(`traits.json`과 `assets/data/*.json` 검색 결과 `characters_story.json:608, 612`뿐). **교체 후 이 특성은 보유자가 없어진다.** 정의를 지울지 남길지 정해야 한다.
- 화공 `firecraft`: `traits.json:718-729`. 비용 700, `Requires: ["fire"]`, 효과 `crit:fire: 1`(화계 책략 명중 시 확정 치명). 치명 키는 `content/vocab.go:99`의 `FxCritElement`.
- 선행 화계 `fire`: `traits.json:1189`, 비용 500, 책략 특성.
- **번궁의 Learn 목록에 `fire`가 없다.** 화공만 넣으면 번궁은 배울 수 없다. 화계를 Learn에 넣거나 선행을 번궁 쪽에서 풀어야 한다.
- 데이터 검증 `internal/content/validate.go:67-70`은 선행 특성이 존재하는지와 순환만 본다. 번궁이 실제로 배울 수 있는지는 검증하지 않는다. 학습 판정은 `internal/core/engine.go:413` 근처 `Requires` 루프에 있다(본 것은 일부).
- 같은 날 다른 결정: 허사(심모→화공), 황보숭(화신→화공) (`result/20261124/firecraft-officer-decisions/notes.md`). 화공이 세 장수에 들어간다. 화계 선행 조건은 세 장수 모두에 같은 문제다.

### 2-2. 수성 적용 지형 (관문·열린 성문)

- 현행 수성(중갑)에는 지형 조건이 없다. 과거 수성(`fortify`)은 `Castle` 칸에서만 턴 버프였다(`fb1cf34` `combat.go:585`). 폐지 경위는 `result/20261124/castle-defense-trait-design/notes.md` 2-2절.
- 지형 데이터는 이미 성 판정을 갖고 있다. `ver5/assets/data/game.json`: 성내(`i`, 307-312행), 성(`o`, 372-379행), 관문(`p`, 380-386행), 열린 성문(상태 `O`, 439-445행) 모두 `Castle: true`. 열린 성문은 커밋 `c68414e`("treat open gates like castles")에서 들어왔다.
- 닫힌 성문(`m`)은 `Castle` 없음이고 진입 불가다.
- 결론: 관문과 열린 성문을 포함하는 것은 **데이터상 이미 가능**하다. 새 수성이 `CellProps(...).Castle`을 읽으면 된다. 지형 자체를 고치는 작업은 필요 없다.
- 순욱 참고: `characters_story.json`의 `xunyu` 항목 — 직업 `mystic`(이름 선술사, `classes.json:1178`), 특성 `self_ward`(수호), `lecture`, `even_hand`, `iron_lock`, `cheer`. 연주 수성 사료 링크는 이번에 열지 않았다.

### 2-3. 방진 4%

- 방진이라는 특성은 데이터에 없다. `방진`은 `docs/history.md:626`, `docs/presentation-scene.md:141`의 장면 진형 용어뿐이다.
- 사세삼공(`four_generations`): `traits.json:998-1006`, 비용 500, `companions: 0.03`. 보유자는 원소(`characters.json:700`)와 원술(`characters.json:993`).
- 엔진: `internal/core/rules.go:68`에서 `k = companions × 아군 수`(주변 8칸, `around(u,true)`, 링 `combat.go:646`은 8방향이고 자신 제외). `rules.go:72-73`에서 `v[0]`·`v[1]`에 `(1+k)`를 곱한다. 이는 **공격·방어 둘 다** 올린다.
- 방진 4%를 넣는 방법: 방어에만 적용하는 새 효과 키(예: `companions_defense`)를 만들어 `rules.go:73` 근처에 `v[1]`만 곱하면 된다. 코드 한두 줄과 데이터 항목 1개.
- 비교 (아군 기수별):

| 아군 수 | 사세삼공 (공·방 각 +3%×n) | 방진 (방 +4%×n) |
|---|---|---|
| 3기 | 공 +9%, 방 +9% | 방 +12% |
| 8기 | 공 +24%, 방 +24% | 방 +32% |

- 방진이 사세삼공과 같은 자리에서 두 번 계산될 때 합산(같은 키 안에서 더하기)과 곱(별도 키로 순서대로 곱하기)에 따라 결과가 달라진다(8기 기준 합산 방어 +56%, 곱 +63.7%). 이 결정은 열린 항목이다.

### 2-4. 진지고수와의 중첩

- 진지고수(`hold_ground`): `traits.json:527-535`, 받는 피해 −30%. 적용은 최종 피해에 곱하는 방식(`combat.go:86-87`).
- 방진은 방어를 올려 기본 피해(`atk×af − def×tf`, `combat.go:46`)를 줄인다. 방어 쪽 감소와 진지고수 곱셈 감소가 겹친다.
- 손계산(공격 100, 원 방어 60): 아무것도 없음 40 → 진지고수 28 → 방진 8기 20.8 → 방진 8기 + 중갑 +20% + 진지고수 약 3.5.
- 위치 조건은 서로 양립한다(진지고수는 이동 없이 끝내기, 방진은 주변 아군). 그래서 같은 자리에서 실제로 겹친다.
- 자세한 계산은 `result/20261124/castle-defense-trait-design/notes.md` 2-4절.

## 3. 이전 기록과의 충돌·정정

- `result/20261124/castle-defense-trait-design/notes.md`(이 작업 전 초안)는 다음이 틀렸다.
  - 순욱 직업을 "방술사"로 적었다. 실제는 `mystic` = 선술사.
  - 사세삼공 보유자를 "원소만"이라고 적었다. 실제는 원소와 원술.
  - "권성의 반격강화 병종화"는 근거가 없다. `counter_boost`는 번궁에게만 있고 병종 풀·계획에는 없다.
  - 방진 "물리 피해 −10%" 안은 이 요청으로 대체된다.
- 화공 교체 결정 3건(허사·황보숭·번궁)은 화계 선행 조건 문제가 같다. 번궁을 추가하면 같은 조치를 한 번 더 해야 한다.

## 4. 열린 항목 (사용자 확인 필요)

1. 번궁 화공: 번궁 Learn에 화계를 넣을지(번궁은 책략 특성을 하나 더 가지게 됨), 아니면 화공 대신 다른 특성을 쓸지.
2. 반격강화: 번궁이 빠지면 보유자가 없다. 정의를 지울지 남길지.
3. 수성 지형: 관문·열린 성문 포함을 확정할지(데이터상 이미 Castle=true).
4. 방진: 특성으로 둘지 진형 규칙으로 둘지. 특성이면 사세삼공과 합산할지 곱할지.
5. 방진 + 진지고수 + 중갑 중첩을 받아들일지, 상한을 둘지.

## 5. 미검증

- 게임 실행·시험 없음. 수치는 손계산이다.
- 번궁의 학습 판정(`engine.go:413` 근처)은 일부만 읽었다. 화계가 없을 때 화공을 배울 수 없는지는 코드 확인 없이 데이터 기준으로 추정했다.
- 연주 수성의 사료 내용은 확인하지 않았다.
- 방진을 특성으로 쓸 때의 AI 처리(AI가 주변 아군을 고려해 움직이는지)는 확인하지 않았다.
