# 수공 연출 시간·효과음 수정 및 영상 (2026-11-23)

요청한 5단계 연출을 구현하고, 효과음이 들어간 새 캡처 영상을 만들었다. 커밋·푸시는 하지 않았다.

## 결과물 (이 폴더)
- `suigong.mp4`: 1280x850, 60fps, 24.83초, 영상 H.264 + 소리 AAC. 소리는 게임이 요청한 효과음 기록(`suigong.sfx`)을 `tools/sfx/dub.py`(--no-music)로 영상에 얹은 것이다. 원래 캡처 도구(`_uidemo-vm`)는 소리를 내지 않으므로 이 방식이 이 프로젝트의 기존 방법이다.
- `sheet.png`: 주요 15장면(시각과 이름 표기). `frames/`: 원본 PNG 17장.
- `suigong.sfx`: 효과음 기록(프레임 번호, 효과음 이름, 음량).

## 타이밍 (영상 시각, 초)
| 시각 | 내용 |
|---|---|
| 0.0 | 여울의 조조군 (기존 도입, 3초 남짓) |
| 2.5~3.2 / 3.2~3.9 | 암전 / 관우가 선 절벽에서 밝아짐 |
| 4.1 | 관우 "무너뜨려라!" 말풍선 |
| 6.6 | 말풍선 정리 시작, 1.0초 동안 사라짐(게임의 `speechFade`) |
| 7.6~9.6 | **2.0초** 카메라가 관우에서 둑으로 부드럽게 이동(smoothstep) |
| 9.6~11.4 | 화면 흔들림(진폭 점점 커짐) + 효과음 `boulder`(거암) |
| 11.4 | 화면이 순간 흰색으로 팍 밝아졌다가 **0.5초** 동안 정상으로. 같은 순간 둑 붕괴 시작, 수계 효과음 `water-big` |
| 11.4~16.4 | 둑 붕괴·물 장면 **5.0초**(약 1.2초 동안 흔들림이 잦아듦) |
| 16.4 | 여울의 조조군으로 컷. 11.4+5.0이며 surge 파일의 `cut`(6.0초)와 일치 |
| 17.1 / 17.9 | 병사 "물이다!" / "피해라!" |
| 18.7 | 물 앞머리가 병사에 부딪힘(물보라 시작, `water-big` 0.6) |
| 20.7~23.7 | 물이 화면 가장자리에 닿은 뒤 3.0초에 걸쳐 점점 흰색으로 |
| 20.7~23.7 | `water-big`을 0.3초 간격 11번, 음량 0.25에서 1.0으로 증가 |
| 23.9~24.8 | 흰 화면 유지 후 종료 |

전체 길이는 기존 약 4.2초에서 24.8초. 장면별로는 둑 붕괴 약 8~9배, 여울 약 4.7배 느리게 보인다.

## 구현
1. `ver5/tools/floodsim.py`: 물 시뮬레이션을 느린 화면으로 다시 구웠다. 시뮬레이션 1~1.9초(둑 장면)를 프레임 4배 밀도로 5.0초에, 1.9~3.5초(여울 장면)를 3배 밀도로 7.5초에 재생한다(`SLOW`). 프레임 수 61에서 253으로, 프레임당 약 46~52ms(약 20fps). 이어 붙임 없는 실제 시뮬레이션 프레임이다. 컷 시각을 1.6초에서 1.9초로, 끝을 3.0초에서 3.5초로, 물보라 시작을 2.3초에서 2.4초로 바꿨다. 시트는 4096 폭(5209 높이), 깊이 시트는 16열로 바꿨다. 둑 모양·판자·흙 복셀·절벽 타일·6칸 강·대군 구도는 그대로다.
2. `ver5/internal/gui/uidemo_suigong.go`: 타임라인 상수와 장면 구성을 새로 썼다(카메라 이동·흔들림·밝기 변화·효과음·병사 외침). 효과음은 게임의 `g.sfxVol`로 호출한다. 그래서 실제 게임과 같은 이름·음량이 기록된다.
3. `ver5/assets/graphics/effects/flood/suigong.{json,png}`, `suigong_depth.png`: 다시 구움(`suigong.json`의 `ms` 합계 13,500ms = 1.0 + 5.0 + 7.5초).

## 사용한 효과음 (assets/sounds, 지계 거암과 같은 자산)
- 흔들림: `boulder.ogg`(거암 스킬의 `Sound`, 1.78초) 9.6초에 음량 1.0, 10.5초에 0.7(흔들림 전체를 덮도록 한 번 더).
- 붕괴: `water-big.ogg`(수룡 등 큰 물 책략의 소리) 11.4초에 1.0.
- 물 흐름: `water.ogg` 음량 0.55를 1.3초 간격으로 12.7초~19.2초(둑 장면과 여울 장면 사이 무음 방지).
- 이후 위 표의 `water-big` 상승 구간.
- 게임의 효과음 음량 0.6과 `dub.py` 방식(`SFX_VOLUME`)을 그대로 쓴다. 영상에서 음량이 오르는 것은 RMS로 확인했다(20초 -28dB, 23초 -22dB, 24초 -20dB).

## 판단한 세부 사항 (요청에 정확히 없는 것)
- 도입 여울 장면 3초 + 관우 대사 약 2.5초 유지. 첫 말풍선 전 암전 연출은 기존 구도를 따랐다.
- 스크롤은 관우 선 곳에서 둑 중앙으로 이동한다. 장면 전환이 암전이 아니라 스크롤이 되었다. 여울로 돌아가는 것만 컷이다.
- 흔들림은 카메라 이동으로 직접 구현했다(기존 `g.shakeT`는 감쇠형이라 점점 커지는 흔들림에 맞지 않았다). 진폭은 월드 픽셀 0.8에서 2.6(화면에서는 4배).
- 흰색 최고 단계(`water-big` 마지막)가 1.0에 도달하는 순간은 영상 끝 직전이다.

## 검증
- `go vet ./internal/gui/`: 통과.
- `go test -p 1 -run TestSuigongDemo -count=1 ./internal/gui/`: 통과(재굽기 후 포함).
- `go run ./cmd/_uidemo-vm -ui suigong -stage B25 -frames 1490`: 영상 1490프레임 캡처 성공. 프레임 PNG로 순서(여울 - 암전 - 관우 대사 - 스크롤 - 흔들림 - 흰 섬광 - 붕괴 - 컷 - 병사 외침 - 물 - 흰색)를 확인했다.
- 소리: 영상의 오디오 스트림(AAC)을 1초 단위 RMS로 확인했다. 9초 전까지 무음, 9.6초부터 소리가 이어지고 마지막 4초 동안 점점 커진다.
- 실제로 들어 보지는 못했다(귀로 확인 불가). 파형 수준의 확인이다.
- gui 전체 테스트와 다른 패키지 테스트는 돌리지 않았다.

## 남은 한계
- 병사는 제자리 걷기라 20초 넘게 걷는 모습은 어색할 수 있다.
- 물이 화면 끝에 완전히 닿기 전(20.7초 시점에 왼쪽 아래 일부는 아직 풀밭)에 흰색이 시작한다.
- 둑 장면 약 20fps(시뮬레이션 프레임)로 느린 화면이므로 매우 부드럽지는 않다. 더 부드럽게 하려면 시트가 더 커진다.
- 25장 본편 연결, 이전 결과의 한계(복셀 크기, 흙탕물 색 등)는 그대로다.
- 다시 만들기: `uv run --with numpy --with scipy --with pillow python tools/floodsim.py --bake`(약 3분), 캡처 후 `python3 tools/sfx/dub.py`는 `uidemo_suigong.go` 주석 참고. 캡처는 디스플레이가 깨어 있어야 하고(`caffeinate -u -t 5`) 샌드박스 밖에서 실행했다.
