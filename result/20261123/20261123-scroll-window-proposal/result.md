# 공통 스크롤 영역 가능성 및 HTML 시안 검토 결과

## 결론

가능하다. 출전 부대에서 카드 위 터치 드래그가 안 되는 원인은 코드에서 확인했다. 공통 스크롤 영역으로 묶는 방향도 타당하다. 이번 턴에서는 구현하지 않았다. 이 요청은 검토와 시안이다.

## 확인한 근거

- `ver5/internal/gui/sortie_unified.go` 52~59행: 출전 부대 목록이 `listRows`를 부를 때 마지막 인자(`pick`)로 `nil`을 넘긴다.
- `ver5/internal/gui/ui_kit.go`의 `listRows`: 행 드래그·선택 등록(`addButton` + `pressTable`)은 `pick != nil`일 때만 한다. 그래서 출전 카드 위에서 본문 드래그가 시작되지 않는다.
- 휠 영역은 `listRows` 끝에서 목록 전체에 등록한다(`g.wheelAreas`). 휠 동작은 실제 기기에서 확인하지 않았다.

## 제안 (`summary.md` 기준)

- 공통 스크롤 영역이 맡을 일: 스크롤 위치·범위, 휠, 본문 포인터 드래그, 스크롤바, 터치 관성, 중첩 입력 우선순위.
- 짧은 누름만 자식 버튼에 넘기고, 끌었으면 버튼 동작을 취소한다.
- 고려할 것: 고정 헤더, 역순 전투 기록, 가변 높이 카드, 중첩 창, 텍스트 입력, 스크롤 중 화면 전환.
- 모든 화면이 같은 방식으로 그리지 않으므로 한 번에 바꾸지 말고, 기존 목록·표·기록을 단계적으로 연결한다.

## 시안

- `result/20261123/scroll-window-proposal/index.html`: 휠, 터치, 마우스 드래그, 카드 선택을 시험하는 독립 페이지. 실제 게임 화면이 아니다.
- 주의: 시안은 브라우저 기본 터치 관성에 기대므로, 게임에서 같은 관성을 보장하지 않는다.

## 확인하지 못한 것

- 실제 기기에서 휠 동작.
- 게임 안에서 터치 드래그 재현.
- 관성의 실제 느낌(시안은 브라우저 동작).
