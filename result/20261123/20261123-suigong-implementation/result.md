# 수공 연출 실제 수정 및 3차 데모 영상 (2026-11-23)

요청 5개를 모두 코드와 에셋에 반영했고, 실제 게임 화면을 캡처해 새 영상을 만들었다. 커밋·푸시는 하지 않았다.

## 결과물 (이 폴더)
- `suigong.mp4`: 게임 캡처 영상. 1280x850, 60fps, 250프레임(4.17초). 앞 1초는 연출 전 도하 장면이고 그 뒤 3초가 수공이다.
- `sheet.png`: 아홉 장면(프레임 30, 100, 115, 128, 140, 165, 190, 205, 225).
- `close.png`: 확대 없는 원본 크기 두 장면(프레임 128 둑 붕괴, 190 여울).
- `frames/`: 위 아홉 프레임의 원본 PNG.

## 구현 방식
1. **원래 타일 절벽 유지.** 기존 데모가 그리던 구운 바위 언덕과 높이장 바위를 모두 없앴다. 협곡은 게임의 절벽 타일(땅 글자 `h`)로 만든다. 좌측은 3열, 우측은 5열이며 둑 줄까지 이어진다. 절벽 높이와 절벽 위 장식(`cliff_top`)은 기존 렌더링이 그린다. 구운 에셋에는 바위가 없다. 물 시뮬레이션에는 절벽이 높이 26의 벽(`CLIFF`)으로만 들어간다. 관우·미축은 우측 절벽 위 (19,7), (20,7)에 서고 높이는 `field.A.CliffRise`(26)다.
2. **둑은 판자와 흙, 무너질 때 함께 흐름.** `floodsim.py`의 `Dam`이 둑을 4단위 복셀 약 3,800개로 만든다. 안쪽은 흙, 겉은 판자다. 디딤면에는 4복셀 길이의 판자 줄을 깔고, 아랫면은 세 층마다 판자 한 줄, 그 사이에는 기둥을 세웠다. 단면은 상류 쪽이 수직이고 하류 쪽은 층층이 물러난다. `Flood.burst`가 둑 바닥을 중앙에서 바깥으로 내리는 것과 같은 시각에, 각 복셀이 위층부터 풀려 각자의 속도를 갖는다. 시뮬레이션의 유속장이 복셀을 끌고 간다.
3. **같은 각도로 흐르는 어색함 제거.** 판자·흙은 회전하는 스프라이트가 아니라 복셀(정육면체)이다. 복셀마다 초기 속도와 끌림 계수가 달라 흩어진다. 판자는 수면에 떠서 하류로 흘러가고(컷 뒤 여울 장면에도 도착한다), 흙은 가라앉아 0.55초 안에 물에 삼켜진다. 복셀은 물과 같은 도트 격자로 그려진다.
4. **강폭 두 배.** 3칸에서 6칸으로 넓혔다(`suigongWidth = 6`, `floodsim.py WIDTH`). 둑·여울·절벽 배치를 같은 폭에 맞췄다. 여울은 하류 전 구간으로 늘렸다.
5. **조조군 가득.** 여울 장면 카메라(4배율)에 보이는 칸을 계산해(`suigongArmy`), 여울 줄(v 이상)에서 화면 왼쪽과 아래쪽 끝까지 224명을 세웠다. 말 탄 병사는 9칸 중 1칸꼴이고 조홍은 선두에 있다. 화면 우상단은 강과 빈 둑이라, 대군의 북동쪽 모서리만 보이는 구도다. 앞 장면도 같은 4배율로 맞췄다.

## 바꾼 파일
- `ver5/tools/floodsim.py`: 바위·언덕 제거, 절벽 벽, 6칸 강폭, 복셀 둑(`Dam`), 복셀 그리기, `--end` 미리보기 옵션 추가.
- `ver5/internal/gui/uidemo_suigong.go`: 절벽 타일 땅, 6칸 강, 여울 전 구간, 대군 배치, 카메라, 아군 대기 칸을 맵 위쪽으로 옮김(병사 칸과 겹침 방지).
- `ver5/internal/gui/field_surge.go`: 문서 주석만 수정.
- `ver5/internal/gui/field_surge_test.go`: 새 배치에 맞게 갱신, 군세·절벽·강폭 항목 추가.
- `ver5/assets/graphics/effects/flood/suigong.{json,png}`, `suigong_depth.png`: 다시 구움(61프레임, 842밴드, 시트 2048x1761, 484KB).
- 위 파일은 모두 원래 미커밋(untracked) 상태였다. 다른 미커밋 변경은 건드리지 않았다.

## 다시 만들기 (`ver5/`에서)
```sh
uv run --with numpy --with scipy --with pillow python tools/floodsim.py --bake   # 약 1분 40초
go run ./cmd/_uidemo-vm -ui suigong -stage B25 -frames 250 -mp4 reports/uidemo/suigong.mp4
```

## 검증
- `go test -p 1 -run TestSuigongDemo -count=1 ./internal/gui/`: 통과(4개 하위 항목).
- `go vet ./internal/gui/`: 통과.
- `go run ./cmd/_uidemo-vm`: 250프레임 캡처 성공. 프레임 PNG와 mp4를 직접 열어 확인했다(절벽 타일 유지, 판자·흙 복셀 붕괴, 여울에 도착한 판자, 대군의 좌·하단 충만).
- gui 전체 테스트와 다른 패키지 테스트는 돌리지 않았다.
- 캡처는 디스플레이가 잠들어 있으면 "no monitor" 오류로 실패한다. `caffeinate -u -t 5`로 화면을 깨운 뒤에 성공했고, 샌드박스 밖에서 실행했다.

## 남은 한계
- 복셀은 4단위(도트 4개)라 4배율 화면에서 한 변이 약 32px로 큰 편이다. 물과 같은 도트 격자이고 주변 그림보다 거칠다. 더 작게 하려면 격자(`DX`)와 복셀 수를 늘려야 하고 굽는 시간이 늘어난다.
- 둑 단면이 카메라에서 위로 눕혀 보여, 벽보다 낮은 둑으로 읽힌다(윗면 판자가 주로 보임).
- 복셀과 물의 앞뒤 관계는 복셀을 물 위에 덧그리는 방식이라, 물에 반쯤 잠긴 판자도 항상 물 앞에 보인다.
- 흙이 잠긴 뒤 흙탕물 색은 따로 표현하지 않았다(복셀을 지우기만 한다).
- 대사는 기존대로 "무너뜨려라!"이고, 25장 본편 장면에는 연결하지 않았다. 병사 대사 두 줄은 앞 데모와 같다.
- 밤·낮, 그림자 문제는 이번에 다루지 않았다(관우·미축 그림자는 절벽 위에서 정상으로 보인다).
