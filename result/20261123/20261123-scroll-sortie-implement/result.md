# 공통 스크롤 전수 적용과 출전 부대 배치 구현 결과 (접수, 미구현)

## 상태

요청은 접수했다. 공통 스크롤 전수 적용과 출전 부대 3열·5열 구현은 아직 하지 않았다. 이번 턴에서 `ver5` 코드는 바꾸지 않았다.

## 구현을 멈춘 이유

- 같은 파일을 다른 세션이 미커밋으로 수정 중이다: `internal/gui/sortie.go`, `sortie_deputy_test.go`, `sortie_unified.go`, 신규 `platform_desktop.go`, `platform_mobile.go`. 이 파일들은 이 요청의 핵심 대상이다. 여기에 바로 구현하면 그 변경과 섞이거나 덮어쓸 위험이 크다.
- 다른 세션이 GUI 캡처(`_uidemo-vm`)와 `go test`를 돌리고 있다. 캡처는 한 번에 하나씩 해야 하므로, 이 요청의 캡처도 그 뒤에 해야 한다.
- 범위: 스크롤바 화면 전수 조사와 적용, 설계 문서, 모바일·PC 캡처, 테스트, `history.md` 갱신. 한 턴에 끝낼 수 있는 크기가 아니다.

## 제안

1. 별도 git worktree(`EnterWorktree` 또는 `git worktree add`)에서 `main` 기준으로 진행한다. 다른 세션의 미커밋 변경은 건드리지 않는다.
2. 설계 문서를 먼저 쓰고, 출전 배치(3열·5열)와 공통 스크롤을 단계별로 나눠 구현한다.
3. 캡처는 다른 세션과 겹치지 않게 순서대로 실행한다.

## 확인이 필요한 점

- 위 방식(별도 worktree에서 진행)으로 진행해도 되는지. 다른 세션의 변경과 합치는 일은 나중에 사용자가 결정한다.
