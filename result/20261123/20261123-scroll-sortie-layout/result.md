# 공통 스크롤 적용 및 출전 부대 3열·5열 결과 (접수, 미착수)

## 상태

요청은 접수했다. 공통 스크롤 적용과 출전 부대 배치 변경은 아직 하지 않았다. 이번 턴에서는 코드를 바꾸지 않았다.

## 요청 범위

1. 공통 스크롤: 스크롤바가 있는 모든 화면에 본문 드래그, 터치 스와이프와 관성, 휠, 스크롤바 조작을 일관되게 적용한다. 자식 버튼 위에서 시작한 드래그도 스크롤되어야 하고, 짧은 누름은 기존 선택 동작을 유지한다.
2. 출전 부대 배치: 모바일 한 줄 3개, PC 한 줄 5개. 작은 화면과 UI 배율에서도 읽기와 터치가 되도록 반응형으로 조정한다.
3. 검증: 모바일·PC 참조 크기에서 게임 캡처와 입력 재현 테스트를 한다. 실제 확인하지 않은 항목은 완료로 적지 않는다.

## 확인한 근거

- 승인 시안: `result/20261123/scroll-window-proposal/index.html`, `summary.md`.
- 관련 선행 작업: `result/20261123/scroll-input-audit/summary.md`(부분 수정, 전수 점검과 관성은 미완료). 이 요청에 흡수된다고 적혀 있다.
- 요청이 적은 현재 상태: `sortie_unified.go`의 `sortieGrid`는 2열 제한, 카드 크기는 PC 104×124, 모바일 120×124 UI 단위. 이 값은 요청 본문 기준이며 코드는 아직 확인하지 않았다.

## 남은 일

1. 스크롤바 화면 전수 목록과 지원 여부 조사.
2. 프로젝트 지침에 따라 설계 문서 작성(여러 파일 변경).
3. 공통 스크롤 영역 구현, 출전 부대 열 수 변경.
4. 테스트와 모바일·PC 캡처, 결과·한계 기록, `docs/history.md` 갱신.

## 확인이 필요한 점

- 범위가 크다. 공통 스크롤 전수 적용과 출전 배치를 한 번에 할지, 출전 배치를 먼저 하고 공통 스크롤을 뒤에 할지 정해 주면 그 순서로 진행한다.
