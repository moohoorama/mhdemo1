# 탐험·시나리오 전환 연속성 문제 수정

사용자는 앞서 조사한 탐험↔시나리오 전환 문제를 **실제로 수정**하라고 요청했다. 조사 보고서 `result/20261125/20261125-explore-scene-continuity-audit/result.md`와 `edge-classification.tsv`, 재현 영상 및 추적 결과를 읽고 수정·검증한다. 기존 요청 `process/20261125-explore-scene-continuity-audit/20261125-explore-scene-continuity-audit.md`의 기준도 따른다.

## 수정 요구

- 제보한 **13장 소패 관청 조운 이별**에서 탐험과 장면이 같은 장소로 이어질 때 인물·방향·카메라가 순간적으로 바뀌거나 불필요하게 암전/페이드인되는 문제를 고친다. 플레이어가 말을 거는 위치가 달라져도 갑자기 초기 자리로 이동하지 않도록 실제 경로를 확인한다.
- 조사에서 확정된 **6건, 4묶음(A1~A4)**: 13장 조운, 14장 서주 거리 미축·미방, 25장 소패 제갈량 보고, 23장 두 차례 및 24장 융중 방문의 인물 튐·사라졌다 재등장을 수정한다. 관련 시선과 위치를 맥락에 맞게 정하고 실제 게임 캡처로 확인한다.
- 같은 장소에서 실제 위치·상황 변화가 없는데 장면→탐험 또는 이벤트→탐험으로 돌아오며 화면이 어두워졌다 밝아지는 불필요한 페이드를 고친다. 건물 출입, 실제 장소 변경, 시간 경과, 명시적 `Cut`, 새 인물 입장, 의도된 배치 전환과 같이 전환이 필요한 경우는 구분해 기존 의도를 유지한다. 단순히 맵 이름만 같다는 이유로 모든 페이드를 없애지 않는다.
- 조사에서 추가 확인으로 남은 42건을 이야기·이벤트·조건과 실제 배치를 바탕으로 재검토해 문제로 확인되는 사례도 고친다. 의도된 장면 변화와 판단 불가능한 항목은 근거와 함께 분류하고, 동적 조건·카메라·분기 등 미확인 범위를 숨기지 않는다.

## 회귀 테스트와 검증

- 보고서의 자동 검증 설계를 검토해 합리적인 콘텐츠/단위 테스트와 실제 엔진 전환 테스트를 구현한다. 동일 장소의 인물 위치·방향 유지, 13장 플레이어 위치 변화, 페이드 생략, 실제 장소 이동/건물 출입/의도적 Cut의 정상 전환, 조건·분기·`Stay`/`Off`/`Enter`의 예외를 검증한다. 단순히 실패를 허용 목록에 숨기지 않는다. 수정 전 문제를 테스트로 재현하고 수정 후 통과를 확인한다.
- 관련 테스트와 게임 캡처/영상으로 13장 전후와 다른 확정 사례, 정상 전환을 확인한다. 프로젝트의 `ver5/README.md`, `docs/presentation-scene.md`, `docs/presentation-facing.md` 및 스토리 작성 규칙을 따르고, 관련 코드와 데이터를 읽어 여러 파일 변경 전에 설계 문서를 작성한다. 기존 미커밋 변경은 보존한다.
- 이번 요청은 새 요청 처리 절차를 따른다: `process/<name>/progress.md`에 1분마다 실제 시각·진행을 기록하고, 구현 후 요청 문서를 `test/<name>/`으로 옮겨 테스트 실제 시각·결과·발견한 버그·수정·재시험을 기록한다. 필수 테스트가 모두 통과했을 때만 `result/YYYYMMDD/<name>/`으로 옮긴다. 실패하거나 검증하지 못하면 test 단계에 남기고 이유를 기록한다.
- 결과 폴더에 변경 파일, 사례별 해결/정상/미확인 목록, 테스트·실행 시각, 실제 게임 캡처·영상, 남은 한계를 기록하고 `ver5/docs/history.md`를 갱신한다.
