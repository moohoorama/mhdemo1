# 사용자용 역사서: 도달 지점의 실제 저장과 불러오기

사용자 요청: 디버그용 `장면 이동`과 유사하지만 일반 플레이어가 사용하는 **역사서**(이름은 가칭)를 추가한다. 플레이어가 실제로 도달한 지점마다 보이지 않는 저장을 남기고, 역사서에서 자기가 도달한 곳까지만 보여 준다. 각 항목 오른쪽에는 그때의 **유비 레벨과 저장 날짜**를 표시하고 선택하면 해당 저장을 불러온다. 디버그 장면 이동의 이전 전투 플래그 임의 수정은 제공하지 않는다. 실제로 플레이한 당시의 장수·레벨·장비·자원·플래그·스토리 진행을 보존해야 한다.

스타크래프트 II의 임무 기록실처럼 이미 경험한 지점을 다시 즐기고 싶다는 맥락이다. 블리자드 공식 설명은 완료한 임무 재플레이를 확인한다: https://news.blizzard.com/en-gb/article/9990070/its-a-matter-of-choice-campaign-difficulty , https://news.blizzard.com/en-gb/article/9991304/uncovering-guest-mode-and-offline-mode . 다만 본 요청은 플레이 당시의 실제 저장을 불러오는 방식이므로 SC2와 저장·분기 동작이 같다고 가정하지 않는다.

## 반드시 해결할 동작

- 현재 스토리 웨이포인트(1막/2막/연의/가상), 일반 저장 및 자동 저장·불러오기 경로와 상태의 직렬화·무결성 검증을 조사한다. 10개 순환 자동 저장과 별도로 역사서 지점별 스냅샷을 보존해 기존 수동/자동 저장이나 다른 플레이 기록을 덮지 않는다.
- 어느 시점에 지점이 목록에 나타나고 스냅샷이 잡히는지(장면 도달 vs 전투 완료, 전투 전 저장 등) 플레이어의 '실제로 거기까지 갔고 깬 곳까지만'이라는 요구를 충족하도록 명확히 설계·기록한다. 특정 전투를 다시 도전할 수 있게 그 전투 **진입 전 실제 상태**를 보존하되, 미도달·미완료 구간이 열린 것으로 오인되지 않도록 구분한다. 기존 진행 기록이 기능 도입 이전에 소급 복원 가능한지 조사하고 없는 상태를 지어내지 않는다.
- 사용자용 UI는 장면 이동과 어울리되 디버그용 조작·플래그 변경은 없고, 실제로 선택 가능한 지점만 제공한다. 오른쪽에 유비 레벨과 저장 날짜를 보여 준다. PC·모바일, 작은 화면과 UI 크기를 고려해 스크롤 및 터치·휠을 지원한다. 실제 UI·저장 경로와 접근 위치를 조사해 사용자에게 자연스러운 메뉴에 넣는다.
- 사용자의 핵심 우려: **서주 구원전(B12)**에서 제갈현 또는 고순을 구하지 못하면 그 진행은 가상모드로 갈 수 없는지, 역사서로 되돌아가 다시 구하면 어떤 일이 생기는지다. 현재 `ver5/docs/fullstory.md`와 `story24.json`에는 제갈현 생존, 고순 합류/생존, 관우·미방 화해가 모두 필요하고 24장에 느린 길을 선택해야 가상모드로 진입하도록 되어 있다. 실제 코드·조건·시점 확인 후, B12 이전 저장에서 다시 플레이해 조건을 바꿀 수 있도록 설계한다. 같은 기록의 미도달 분기를 임의로 해금하거나 과거 저장의 플래그를 편집하지 않는다. 원래 플레이 기록과 이후 새 진행이 덮이거나 예기치 않게 바뀌지 않도록 보존한다.
- 과거 기록을 불러온 후 기존 진행과 새 진행을 어떻게 식별·보존할지, 같은 지점을 다른 결과로 다시 통과할 때 기존 저장을 어떻게 보존할지 구체적으로 설계하고 UI에서 혼동이 없게 한다. 손상·실패 시 기존 수동 저장과 진행을 잃지 않도록 원자적 저장, 복원·버전 호환·불러오기 실패를 검증한다. 유저 데이터 손실이 예상되는 불가역적 선택은 자동으로 하지 않는다.

## 검증·결과

- `ver5/README.md`, 저장·스토리·장면 이동 관련 코드, 테스트 및 프로젝트 지침을 먼저 읽고 설계 문서를 작성한 뒤 실제 구현한다. 기존 미커밋 변경을 보존한다.
- B12 전→제갈현·고순 생존/미생존→22장 조건→24장 연의/가상 분기, 서로 다른 기록의 보존, 도달·완료 경계, 날짜·레벨 표시, 세션 재시작, 저장 실패·손상, 일반 저장과의 격리 및 UI 선택·복원을 테스트한다. 실제 게임 흐름·PC/모바일 캡처를 확인하고 수행 범위와 한계를 기록한다.
- 처리 중 `process/<name>/progress.md`에 매분 실제 시각과 진행을 기록한다. 구현 후 요청 문서를 `test/<name>/`으로 옮겨 테스트 명령·실제 시간·결과·버그 수정과 재시험을 기록한다. 모든 필수 테스트 통과 후에만 `result/YYYYMMDD/<name>/`으로 이동한다. 프로젝트의 `ver5/docs/history.md`를 갱신한다.
