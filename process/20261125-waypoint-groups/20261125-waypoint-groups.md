# 장면 이동 막별 분류 및 앞선 전투 결과 잘림 수정

사용자 요청을 실제 구현한다.

1. 장면 이동 화면의 선택 목록을 **1막, 2막, 2막-연의, 2막-가상**으로 분류하여 사용자가 각 범주를 구분하고 원하는 장면을 찾을 수 있게 한다. 현재 이야기 데이터의 막 구성·공통 구간과 연의/가상 분기, 웨이포인트 순서를 먼저 확인해 각 지점을 올바른 범주에 배치한다. 분류 화면에서 현재 선택·스크롤 위치와 난이도 선택 및 기존 이동 기능이 자연스럽게 동작해야 한다. 같은 이름을 가진 범주의 의미는 실제 데이터에 맞게 파악하고, 지점을 누락하거나 잘못된 분기로 이동시키지 않는다.
2. 장면 이동의 **앞선 전투 결과가 너무 길어서 잘리는 문제**를 고친다. 오른쪽 영역에서 항목의 수와 텍스트 길이 때문에 표시·선택이 잘리는 경우를 실제 게임 화면에서 확인하고, 모든 항목과 내용에 접근하고 읽을 수 있도록 스크롤·줄바꿈·배치 등 적절한 방법을 선택한다. 전체 선택·없음 및 개별 토글, 이동 시 플래그 적용을 유지한다.

참고 코드: `ver5/internal/gui/waypoints.go`의 `waypointWindow`, `waypointSetup`, `updateWaypoints`, `ver5/internal/content/scenario.go`의 `Data.Waypoints`와 스토리 플래그 데이터. 기존 부분 수정과 다른 세션의 미커밋 변경을 보존한다. 공통 스크롤 입력이 있다면 기존 패턴을 활용하며, 본문 터치 드래그·휠·스크롤바와 중첩 입력을 확인한다.

`ver5/README.md` 및 프로젝트 UI 캡처 지침을 따르고, 복수 파일·데이터 구조 변경이면 설계 문서를 먼저 작성한다. 웨이포인트 분류 누락·경계·분기, 결과 항목 마지막까지의 스크롤·텍스트·선택 유지·실제 점프 플래그를 의미 있는 테스트로 검증한다. PC와 휴대폰 크기/배율에서 실제 게임 화면 캡처를 만들고 잘리지 않는지 확인한다.

`result/YYYYMMDD/<task-name>/`에 변경 및 분류 기준, 테스트 결과, PC·휴대폰 화면 캡처와 미확인 사항을 기록하고 `ver5/docs/history.md`를 갱신한다. 실제로 확인하지 않은 것은 완료로 적지 않는다.
