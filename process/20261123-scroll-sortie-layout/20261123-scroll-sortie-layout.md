# 공통 스크롤 적용 및 출전 부대 모바일 3열·PC 5열

사용자가 승인한 공통 스크롤 방식 시안 `result/20261123/scroll-window-proposal/index.html`과 설명 `result/20261123/scroll-window-proposal/summary.md`를 바탕으로 **게임에 실제 적용**하고, 출전 준비의 출전 부대를 모바일은 가로 3개, PC는 가로 5개가 나오도록 바꾼다. 기존 전수 점검 요청 `process/20261123-scroll-input-audit/20261123-scroll-input-audit.md`의 미완료 사항을 함께 해결하고 중복 작업하지 않는다.

## 1. 공통 스크롤

- 스크롤바가 있는 모든 화면을 조사·목록화하고, 공통 스크롤 영역이 본문 마우스 드래그, 터치 스와이프 및 손을 놓은 뒤 관성, 마우스 휠, 스크롤바 조작을 일관되게 처리하도록 적용한다.
- 출전 부대 카드처럼 자식 버튼 위에서 시작한 드래그도 스크롤되어야 하며, 짧게 누르면 기존 장수 선택·부관 선택 등이 그대로 작동하고 드래그 후에는 오동작하지 않아야 한다.
- 고정 헤더, 역순 전투 기록, 가변 높이 카드, 겹친 창, 게임 입력 우선순위와 스크롤 한계를 포함해 기존 화면 동작을 보존한다. 모든 스크롤바가 있는 화면을 점검해 누락 없이 연결한다.
- 기존 부분 작업 `result/20261123/scroll-input-audit/summary.md`와 기존 미커밋 변경을 보존한다. 여러 파일을 바꾸므로 구현 전 설계 문서를 작성하고 프로젝트 지침에 따른다.

## 2. 출전 부대 카드 배치

- 모바일 출전 부대 카드는 한 줄 **3개**, PC는 **5개**를 목표로 한다. 화면 크기와 UI 배율이 작은 경우에는 카드·터치 영역의 읽기와 조작성을 보장하도록 반응형으로 조정하고, 실제로 3열·5열이 나오는 조건과 예외를 결과에 적는다.
- 현재 `ver5/internal/gui/sortie_unified.go`의 `sortieGrid`는 2열 제한이며 PC 카드 기본 크기는 104×124, 모바일은 120×124 UI 단위(`platform_desktop.go`, `platform_mobile.go`). PC의 현재 게임 캡처 `result/20261123/scroll-sortie-request/pc/frame-0020.png`를 참고한다. 실제 화면·UI 배율에 따라 크기가 달라진다.
- 주장의 초상·이름과 부관 원형 표시·부관 교체 버튼을 식별하고 터치할 수 있게 유지한다. 다른 표와 상세 패널, 출진 버튼 등이 가려지지 않게 한다.

## 검증과 결과

- 모바일 참조 크기·여러 UI 배율, PC 참조 크기에서 게임 화면 캡처와 직접 입력 또는 터치 재현 테스트로 행 수, 스크롤, 선택·부관 동작 및 경계·관성·휠을 확인한다. `ver5/AGENTS.md` 및 프로젝트 지침의 `cmd/_uidemo-vm` 캡처 절차를 따르고, 필요하면 전용 데모를 추가한다.
- 스크롤 화면 목록과 지원 여부, 변경 파일, 실제 테스트 및 확인하지 못한 항목, 모바일·PC 캡처를 `result/YYYYMMDD/<task-name>/`에 기록한다. 실제로 확인하지 않은 내용을 완료로 기록하지 않는다. `ver5/docs/history.md`도 갱신한다.
