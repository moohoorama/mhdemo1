# 공통 스크롤 전수 적용과 출전 부대 배치 모두 구현

사용자는 이전 `process/20261123-scroll-sortie-layout/20261123-scroll-sortie-layout.md`의 공통 스크롤 전수 적용과 모바일 3열·PC 5열 출전 부대 배치를 **둘 다 실제로 해 달라고 명시했다**. 이전 `result/20261123/20261123-scroll-sortie-layout/result.md`는 순서를 물으며 미착수로 끝났으므로, 이 요청에서 그 두 작업을 이어서 수행한다. 순서와 단계는 기존 코드와 프로젝트 지침을 살펴 스스로 정한다. 단지 범위가 크거나 순서를 선택해야 한다는 이유로 착수하지 않고 끝내지 않는다.

## 구현 대상

1. `result/20261123/scroll-window-proposal/index.html`의 승인된 공통 스크롤 방향을 게임에 적용한다. 스크롤바가 있는 모든 화면을 조사해 목록화하고, 마우스 휠·스크롤바·본문 드래그·터치 스와이프 및 관성이 일관되게 동작하게 한다. 출전 카드나 자식 버튼 위에서 밀면 스크롤하고, 짧게 누르면 기존 선택·부관 동작이 되게 한다. 고정 헤더, 역순 기록, 가변 높이, 중첩 창, 입력 우선순위와 화면 전환을 다룬다.
2. 출전 준비의 출전 부대 카드는 모바일 한 줄 3개, PC 한 줄 5개를 목표로 구현한다. 작은 화면과 UI 배율에서도 이름·초상과 부관 버튼이 식별·조작되도록 반응형 처리하고 조건·예외를 기록한다. 현재 PC 화면 참고: `result/20261123/scroll-sortie-request/pc/frame-0020.png`.
3. 선행 부분 수정·검증 내용 `result/20261123/scroll-input-audit/summary.md`를 확인하고 기존 미커밋 변경을 보존한다. 이전 요청 본문의 상세 요구도 모두 적용한다.

## 수행과 검증

- 프로젝트 지침대로 관련 코드를 읽고 여러 파일 변경 전 설계 문서를 작성한다. 필요한 구현을 실제로 끝까지 진행한다.
- 스크롤 화면별 지원 현황과 수정 내용을 기록한다. 모바일·PC 참조 크기와 UI 배율에서 게임 캡처를 남기고, 터치 재현·휠·관성·경계·클릭과 드래그 구분·부관 버튼·중첩 화면에 대한 의미 있는 테스트를 실행한다.
- `result/YYYYMMDD/<task-name>/`에 변경 파일, 테스트와 캡처, 실제 미완료·한계를 기록하고 `ver5/docs/history.md`를 갱신한다. 확인하지 않은 내용을 완료로 쓰지 않는다.
