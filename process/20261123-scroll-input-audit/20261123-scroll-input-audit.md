# 스크롤바가 있는 모든 화면 입력 점검·수정

사용자 요청: 스크롤바가 있는 모든 화면의 목록을 확인하고, 목록 본문 마우스 드래그·휴대폰 터치 스와이프와 마우스 휠이 빠진 곳을 모두 고친다. 손을 놓은 뒤 튕겨 이어지는 터치 스크롤도 확인해 자연스럽게 동작하게 한다.

## 이미 수행한 부분

`result/20261123/scroll-input-audit/summary.md` 및 `design.md`를 먼저 읽는다. 공통 표 `drawTable` 휠 등록과 전투 기록 본문 드래그를 추가했고 관련 테스트가 통과했다. **전수 점검과 관성 스크롤은 미완료**이므로 이 요청에서 실제로 완료한다. 기존 미커밋 변경 및 위 부분 수정을 보존하고 이어서 작업한다.

## 작업

- 공통 표·목록·카드 선반, 전투 HUD 기록 및 장수 목록, 상점, 저장·불러오기, 장수·장비·인수 선택, 출전·배치, 각종 브라우저·편집기, 이동 지점 등 실제 스크롤바가 그려지는 모든 화면을 코드와 실제 화면에서 찾고, 화면별 스크롤바·본문 드래그·터치·휠·관성 지원 및 수정 결과를 목록으로 기록한다. 그 밖의 독자 구현도 탐색한다.
- 누락된 입력을 고치고, 터치 스와이프 이후 관성·경계 정지, 클릭과 스크롤의 구분, 스크롤바 드래그, 중첩 팝업 및 화면 전환 시 입력 충돌을 확인한다. 손가락과 마우스에서 화면이 자연스러운 방향으로 움직여야 한다.
- 공통 표의 휠 영역 등록과 기존 `updateUnitList`·`updateShopList` 같은 별도 휠 처리, 모달·에디터 입력 순서를 조사해 중복 스크롤이나 다른 화면으로 입력이 전달되지 않게 한다.
- `ver5/README.md`와 기존 구현을 읽고 프로젝트의 설계·테스트 지침을 따른다. 3개 이상 파일을 수정한다면 먼저 설계 문서를 작성한다. 의미 있는 회귀 테스트를 작성하고 직접 터치 또는 터치 입력을 재현한 테스트와 휠 입력·경계·클릭 구분을 검증한다. 대표적인 본문·작은 화면을 게임 캡처로 확인한다.
- `result/YYYYMMDD/<task-name>/`에 목록, 수정 파일, 테스트, 화면 캡처와 직접 확인하지 못한 항목을 기록한다. `ver5/docs/history.md`를 갱신한다.
