# 기존 변경 체크포인트 커밋 후 공통 스크롤·출전 배치 구현

사용자는 공통 스크롤과 출전 부대 3열·5열 작업이 다른 세션의 미커밋 변경 때문에 멈춘 데 대해 **다른 세션 변경을 알아서 git add·commit하고 구현하라**고 명시적으로 승인했다. 이전 미구현 보고서 `result/20261123/20261123-scroll-sortie-implement/result.md`와 구현 요청 `process/20261123-scroll-sortie-implement/20261123-scroll-sortie-implement.md`를 확인하고, 단지 미커밋 변경이 있다는 이유로 멈추지 말고 이어서 실제 작업한다.

1. 현재 브랜치·상태·staged/unstaged/untracked 변경, 관련 다른 세션의 작업 여부를 확인한다. 사용자가 승인한 기존 변경을 보존하며 관련 변경을 이해하기에 충분히 검토하고 민감 정보·자격 증명·로그·불필요한 대용량 임시 산출물이 커밋에 들어가지 않도록 확인한다. 진행 중인 세션이 같은 파일을 쓰고 있다면 덮어쓰거나 진행 중 파일을 불완전하게 커밋하지 않도록 조율·완료 확인 후 진행한다. 현재 사용자 환경에서는 main 브랜치가 확인됐고, 커밋은 사용자 승인 범위다. push는 승인되지 않았다.
2. 필요한 기존 변경을 알맞게 `git add`하고 Conventional Commits 형식의 체크포인트 커밋을 만든다. 여러 독립 변경이 섞여 있으면 검토 가능한 단위로 정리하고, 실제로 포함한 파일과 커밋 ID를 기록한다. 검토할 수 없거나 민감한 파일은 무턱대고 포함하지 않는다. 기존 변경을 되돌리거나 삭제하지 않는다.
3. 그 상태에서 이전 요청대로 공통 스크롤의 모든 스크롤바 화면 적용과 출전 부대 모바일 3열·PC 5열을 구현한다. 이전 시안 `result/20261123/scroll-window-proposal/index.html`, 부분 작업 `result/20261123/scroll-input-audit/summary.md`를 읽는다. 터치 드래그·관성·휠·스크롤바와 카드 선택 및 부관 조작을 포함한다. 단계와 작업 순서는 스스로 정한다. 별도 worktree를 쓸 경우에도 승인된 기존 변경이 실제 작업에 포함되고 결과가 사용자의 현재 작업 공간에 반영되도록 한다.
4. 프로젝트 지침대로 설계 문서, 의미 있는 입력 테스트, 모바일·PC 게임 화면 캡처, `ver5/docs/history.md` 기록을 수행한다. GUI 캡처는 다른 캡처와 겹치지 않게 실행한다. 결과 폴더에 커밋 ID, 수정 파일, 화면별 검증 및 미완료를 기록한다. 확인하지 않은 사항을 완료라고 하지 않는다.

별도의 스크롤바 5종 시안 요청 `20261124-scrollbar-design`은 사용자가 디자인을 고르는 별도 작업이다. 디자인 승인 전 임의의 시안을 최종 채택하지 않되, 공통 스크롤 기능 구현은 진행한다.
