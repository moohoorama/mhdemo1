# 공통 스크롤·출전 배치 구현 및 스크롤바 5종 시안 제작

사용자의 명시적인 최신 지시: **기존 변경을 적당히 파악하고 알아서 진행하라. 구현하라고 했으며 멈추라고 하지 않았다.** 이전 `20261124-scroll-sortie-checkpoint`와 `20261124-scrollbar-design`은 불필요한 확인 질문으로 미착수했다. 이 요청은 두 작업을 실제로 수행하라는 지시다. 계획·질문·미착수 보고만 남기고 끝내지 않는다.

## 사용자 승인과 작업 방법

- 사용자는 다른 세션의 기존 변경을 살펴 필요한 것은 `git add`·`git commit`하고 작업을 진행하라고 이미 승인했다. 현재 변경을 적절히 파악하고, 필요한 범위를 스스로 판단해 자격 증명과 명백한 임시 산출물을 제외하여 검토 가능한 체크포인트를 만든다. 기존 변경을 보존하고 진행 중인 파일과 실제 충돌이 있으면 안전하게 조정하되, 독립적으로 가능한 조사·구현·검증은 계속한다. 커밋 분류 방식이나 임시 캡처 도구 추가 여부를 다시 묻지 않는다. Push는 하지 않는다.
- 작업 내용이 많으면 설계·구현·검증을 단계로 나누어 순서대로 수행하고, 한 단계만 마쳤다는 이유로 종료하지 않는다. 실제로 진행할 수 없는 명확한 기술적 장애가 있으면 가능한 모든 대안을 시도하고 그 증거와 완료 범위를 결과에 적는다.

## 구현

1. 공통 스크롤 영역을 구현하고 스크롤바가 있는 모든 관련 화면에 적용한다. 출전 부대 카드 등 자식 버튼 위에서 시작한 터치·마우스 드래그, 터치 관성, 휠, 스크롤바 조작이 동작해야 한다. 짧은 누름으로 카드·부관 선택이 되고 드래그 시에는 선택되지 않아야 한다. 고정 헤더, 역순 기록, 중첩 창, 경계 처리와 기존 입력 충돌도 확인한다. 참고: `result/20261123/scroll-window-proposal/` 및 `result/20261123/scroll-input-audit/summary.md`.
2. 출전 준비의 출전 부대를 모바일 가로 3개, PC 가로 5개가 나오도록 적용한다. 화면·UI 배율이 작으면 조작성과 가독성을 지키는 반응형 예외를 판단해 기록한다. 초상·이름·부관 버튼·다른 패널을 확인한다. 이전 상세 요구: `process/20261123-scroll-sortie-layout/20261123-scroll-sortie-layout.md`.
3. 공통 스크롤바의 서로 다른 디자인 시안 5개를 만들고 동일한 실제 게임 화면에서 PC·모바일 참고 크기로 캡처해 나란히 비교할 HTML 또는 이미지를 만든다. 캡처를 위한 전용 데모나 임시 변형 경로는 필요한 범위에서 스스로 만들고, 사용자 선택 전 어느 시안도 최종 디자인으로 확정하지 않는다. 이전 상세 요구: `process/20261124-scrollbar-design/20261124-scrollbar-design.md`.

## 검증과 결과

- `ver5/README.md`, 프로젝트 지침과 관련 코드를 먼저 읽고 복수 파일 변경 전 설계 문서를 작성한다. 현재 작업 트리의 다른 변경을 보존한다.
- 스크롤 화면 목록을 작성해 각 화면의 휠·본문 드래그·터치·관성·스크롤바 지원을 점검하고 의미 있는 테스트를 작성·실행한다. 작은 화면을 포함한 모바일·PC 실제 게임 캡처, 3열·5열, 선택·부관 동작과 스크롤바 시안을 검증한다. GUI 캡처 충돌은 직렬화한다.
- `result/YYYYMMDD/<task-name>/`에 구현 결과, 체크포인트 커밋 ID, 파일 목록, 테스트·캡처 결과, 5개 시안 비교와 실제 한계를 기록하고 `ver5/docs/history.md`를 갱신한다. 미완료인 항목은 명확히 적는다.
