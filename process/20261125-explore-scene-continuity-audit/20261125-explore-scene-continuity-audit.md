# 탐험·시나리오 전환 연속성 전수 조사

사용자 제보: **13장 소패 관청에서 조운이 떠날 때**, 탐험과 시나리오 사이에 인물 위치가 바뀌어 순간이동처럼 보이고 갑자기 페이드인만 나와 깜빡인다. 이런 사례가 많으므로 자동 테스트로 검출하고 싶다. 우선 현재 게임에 어떤 사례가 있는지 전수 조사한다.

## 사용자 기준

- 탐험에서 시나리오로 진입할 때 **건물 출입 등 실제 장소가 바뀌는 전환이 아니라 같은 장소의 연속된 화면**이라면, 전환 직전·직후의 해당 인물 배치가 이어져야 한다. 화면에서 순간이동처럼 보이지 않아야 하고 이 경우 불필요한 페이드인·페이드아웃이 없어야 한다.
- 실제 장소 이동, 건물 안팎 이동, 명시적 장면 전환, 시간 경과, 인물의 명시된 이동·퇴장 등은 맥락과 엔진 동작을 확인해 구분한다. 같은 맵 이름만으로 연속 장면이라 단정하거나 좌표가 다르다고 무조건 오류로 분류하지 않는다. 사람의 위치뿐 아니라 바라보는 방향, 카메라·보이는 연출과 페이드 타이밍도 확인한다.

## 조사 범위·방법

- `ver5/README.md`, `ver5/docs/presentation-scene.md`, `ver5/docs/presentation-facing.md`, 관련 탐험·시나리오 전환 코드와 데이터 구조를 읽는다. 13장의 `explore13*.json`, `story13.json`, `scenes/ch13.json` 및 엔진의 페이드·배치 연결을 조사한다. 필요하면 이야기 인덱스로 관련 대사·전후 상황을 찾아 맥락을 확인한다.
- 13장 제보 사례는 **실제 게임 흐름**을 재현하는 캡처 또는 영상을 남겨 위치 변화와 깜빡임의 원인을 코드·데이터에 연결해 설명한다. 데모가 재현하지 못하면 실제 경로를 재현하는 데모를 추가하고 확인한다.
- 전 챕터 탐험→시나리오의 연결을 데이터·코드 기준으로 전수 조사한다. 필요한 경우 읽기 전용 분석 스크립트를 만들고, 각 전환에 대해 맵/장소, 양쪽 인물 좌표·방향, 명시적 이동·출입 여부, 페이드 조건과 코드 근거를 수집한다. 동적 분기·랜덤 배치·조건부 이벤트 때문에 정적 분석만으로 확정하지 못하는 것은 별도 표시한다. 의심 사례는 실제 캡처로 확인한다.
- 결과에 **확정 문제 / 정상적인 장소 전환·의도된 연출 / 추가 확인 필요**를 구분하고, 각 사례의 장·노드·파일·라인과 이유를 적는다. 조사한 전체 범위와 누락·제한도 밝힌다.
- 이 규칙을 자동 검증할 의미 있는 단위/콘텐츠 테스트의 설계를 제안한다. 어떤 데이터와 전환을 비교할지, 건물 출입·의도적 전환을 어떻게 표현·제외할지, 동적 배치·카메라·페이드에 대한 한계와 오탐 방지를 구체화한다. 회귀 테스트에서 13장 문제를 어떻게 재현할지도 적는다.

이번 요청은 **우선 전수 조사**다. 사용자의 명시적 후속 결정 없이 이야기나 연출을 일괄 수정하거나 기존 데이터를 임의로 바꾸지 않는다. 조사·재현에 필요한 테스트·데모·스크립트는 기존 미커밋 작업을 보존하여 작성할 수 있다. 프로젝트의 화면 캡처·시선 지침과 `ver5/docs/history.md`를 따른다.

`result/YYYYMMDD/<task-name>/`에 조사 목록, 자동 테스트 설계, 13장과 의심 사례의 실제 게임 캡처/영상, 실행한 명령·검증과 남은 한계를 기록한다.
