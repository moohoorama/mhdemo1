# 출전 카드 축소 및 도트 기반 스크롤바 시안

사용자의 정정: 모바일 3열·PC 5열은 **출전 부대 왼쪽 칸을 넓히라는 뜻이 아니라, 출전 카드 자체를 작게 해 기존 공간에 넣으라는 뜻**이다. 현재 카드는 모바일에도 크고 PC에서는 훨씬 너무 크다. 앞선 스크롤바 시안도 마음에 들지 않아 거부했다. 실제 코드와 게임 캡처로 확인해 아래를 수행한다.

## 1. 출전 부대 카드 축소

- 이전 구현 `result/20261124/20261124-scroll-execute/result.md`와 변경 전후 출전 준비 레이아웃을 조사한다. 열을 늘리기 위해 왼쪽 칸이나 출전 준비 창을 넓힌 변경은 사용자 요구에 맞게 되돌리거나 조정하고, **카드와 부관 표시 자체를 축소**하여 기존 왼쪽 공간에서 모바일 3열, PC 5열을 목표로 한다.
- 모바일과 PC에서 각각 실제 게임 캡처로 카드가 과도하게 크지 않고 필요한 열 수가 나오는지 확인한다. 카드가 작아져도 초상·이름·출전 상태, 부관 표시와 터치 영역이 식별·조작 가능해야 한다. 부관 선택과 카드 선택·드래그 스크롤을 검증하고 다른 창·패널은 가리지 않게 한다. 화면/UI 배율에서 목표를 물리적으로 충족하지 못하는 경우 실제 조건과 대안을 기록한다.
- 기존 공통 스크롤 입력 동작 및 다른 세션 변경을 보존한다. 관련 설계·회귀 테스트와 모바일·PC 캡처를 수행한다.

## 2. 도트 기반 스크롤바 시안

- 이전 A~E 시안은 거부되었다. **픽셀을 찍어 만든 도트 기반 이미지 조각을 조합하는 형태**로, 현재 창의 금색 테두리와 어울리는 새 스크롤바 시안을 만든다. 코드로 벡터 원·곡선 등을 매끈하게 그리는 스타일이 아니라 도트 윤곽과 질감이 보이게 한다.
- 기존 `ver5/internal/gui/skin.go`의 `window`는 `assets.UI["window_rim"]` 이미지를 `nineSlice`로 사용한다. 실제 테두리 원본·UI 아트 제작 경로와 확대·샘플링 방식을 조사하고, 기존 프로젝트의 스프라이트/그래픽 지침과 자산 위치를 따른다. 높이가 다른 스크롤바에도 모서리와 반복/늘어나는 부분이 자연스럽게 유지되게 한다. 터치 가능한 영역은 도트 그림과 별개로 충분하게 확보한다.
- 앞선 요청의 취지대로 서로 구별되는 약 5개 새 시안을 만들고, 기존 게임 창과 함께 PC·모바일 참고 화면에서 실제 게임 캡처로 비교한다. 각 시안의 확대 PNG와 나란히 비교 가능한 HTML을 결과 폴더에 저장한다. 실제 캡처가 아닌 부분은 구분하고, 사용자가 고르기 전 최종 시안을 선택하지 않는다.

## 결과

- 프로젝트 지침대로 `ver5/README.md` 및 UI·아트 가이드를 읽고 여러 파일 변경 전 설계 문서를 작성한다. 기존 변경을 되돌리지 않는다.
- `result/YYYYMMDD/<task-name>/`에 변경 내역, 구·신 카드 및 왼쪽 영역의 실제 크기·열 수, 검증, PC·모바일 캡처, 5종 비교 페이지와 미확인 사항을 남기고 `ver5/docs/history.md`를 갱신한다. 실기 터치나 렌더링을 확인하지 못하면 명시한다.
