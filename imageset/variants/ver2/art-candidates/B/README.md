# 후보 B — 조조전 정밀

조조전처럼 위에서 비스듬히 내려다보는 정사각 격자 전장입니다. 타일은 48px 원본을 **×1로 표시**해 18×14 맵 전체를 한 화면에 담습니다. 부대는 56×56 셀에 약 3.7등신, 높이 약 37px로 그렸습니다. 명암은 좌상단 광원을 기준으로 5단계 램프로 넣고, 1px 짙은 외곽선과 라멜라 갑옷 무늬로 밀도를 냈습니다. 오른쪽 세로 열에 미니맵·전황, 큰 초상화(64×72, ×3 표시)·수치·특성·장비, 전투 예측을 둡니다. 행동 메뉴는 선택한 부대 옆에 뜹니다. 패널은 짙은 남색 바탕에 금색 이중 테두리를 씁니다.

`python3 art-candidates/B/gen.py` (ver2/에서 실행, Pillow만 사용, 결정적)

## 규격

| 항목 | 값 |
|---|---|
| 지형 타일 | 48×48 원본, 표시 ×1 |
| 부대 셀 | 56×56, 기준점 (28,50) = 발/말발굽 외곽선의 최하단 행 |
| 배치 | 기준점을 타일 (x·48+24, y·48+42)에 맞춤, 셀 위쪽은 윗 타일로 넘어갈 수 있음 |
| 방향 | 시트는 오른쪽(남동) 방향. 왼쪽은 기준점 x=28을 축으로 좌우 반전 |
| 시트 | 행=스프라이트, 열=프레임. infantry-ally: 대기 0–7 / 걷기 8–15, cavalry-ally: 대기 0–7 / 걷기 8–15, bandit-enemy: 대기 0–7 |
| 재생 | 보병 대기 140ms·걷기 100ms, 기병 대기 150ms·걷기 110ms, 적병 대기 140ms (초안) |
| 초상 | portrait.png 64×72, 표시 ×3 |
| 알파 | 0/255만 사용 |

## 팔레트

외곽선 `#1a1622` 1색과 5단계 램프 12개(청람 갑옷, 동금, 피부, 상아, 강철, 말 갈색, 짙은 천, 머리카락, 적색, 황색 두건, 목재, 황토 옷)를 씁니다. 시트에 실제로 쓰인 색은 58색이고, 초상에는 붉은 얼굴과 옥록 램프를 더 씁니다. 지형은 초원·흙·물·기와·잎 램프 5개를 별도로 씁니다. 처음 목표였던 약 40색보다 많아서, 최종본에서는 램프를 4단계로 줄여 정리할 수 있습니다.

## 프레임 규칙

- 대기: 다리와 치마는 고정하고, 머리·상체·팔만 1px 내려갔다 올라옵니다(`0,0,0,1,1,1,1,0`).
- 걷기: 양발 보폭 `3,2,0,-2,-3,-2,0,2`, 들어올림 `0,0,0,0,0,1,2,1`(반대 발은 4프레임 위상차), 몸 높낮이 `0,1,0,-1,…`입니다. 팔은 반대쪽 다리와 엇갈려 움직입니다. 땅을 딛는 발은 항상 기준 행에 있습니다.
- 기병: 다리 4개를 측대보 위상(0/4/2/6)으로 움직이고, 머리 끄덕임과 꼬리를 흔듭니다. 대기 때는 말발굽을 고정하고 기수만 숨쉬고 말 머리와 꼬리가 움직입니다.
- 모든 부위는 같은 도형 호출을 정수 오프셋으로 옮겨 그립니다. 그래서 움직이지 않는 부위는 프레임 간 픽셀이 같습니다. 프레임별 trim·재중앙·크기 조정은 하지 않습니다.
- 자동 검사: 40프레임 모두 알파 ⊆ {0,255}, 최하단 불투명 행 = 50, 셀 가장자리 접촉 없음.

## 강점과 한계

- 강점: 정보 밀도와 화면 구성이 조조전에 가깝습니다. 맵 전체와 미니맵, 큰 초상, 예측창을 한 화면에 함께 보여 줍니다. 초상은 관우의 붉은 얼굴, 긴 수염, 녹색 두건이 분명히 드러납니다.
- 한계:
  - 1280×850 화면에 ×1로 표시하므로 부대가 작게 보입니다. 원작은 640×480 화면에 48px 셀을 쓰던 비율이라, 같은 체감을 원하면 ×2 표시와 화면 스크롤로 바꿔야 합니다.
  - 도형과 램프로 절차적으로 그린 원화라서 손으로 찍은 도트만큼 얼굴과 손 표현이 섬세하지 않습니다. 기병의 팔과 창 쥔 손은 단순합니다.
  - 공격·피격·탈진, 궁병, 일기토 측면 기마는 아직 없습니다.
  - (7,6)의 황건 적병은 공격 대상을 보여 주려고 추가한 목업 전용 부대입니다. 피해·명중 수치도 목업 값입니다.
  - 오른쪽 위 전황 칸의 "라운드 1 / 20"과 정보창의 "운장"(관우의 자)은 근거 자료 없이 넣은 목업 텍스트입니다. "1 / 20"의 라운드 상한은 실제 콘텐츠에 없는 값입니다.
