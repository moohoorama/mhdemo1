# 후보 C2 — 아이소메트릭 + Codex 원화

후보 C의 아이소메트릭 전장·UI 구성을 유지하고, 부대와 초상을 Codex 내장 이미지 생성 원화로 교체했다.
원화는 `src/`에 프롬프트(`*.prompt.txt`)와 함께 보관하고, `pixelize.py`가 게임 해상도 도트로 변환한다.

## 제작 과정

1. `gen_images.sh <이름> <프롬프트>`: `codex exec`로 원화 1장 생성 → `src/<이름>.png`
   - 초상 5종(유비·관우·장비·정원지·장각): 동일 구도·배경·눈높이 프롬프트
   - 부대 6종(경보병·경기병·황건 적병 × 대기/걷기): 마젠타 배경, 남동 방향, 8프레임 1행
2. `python3 pixelize.py`
   - 초상: 48색 양자화 후 블록 최빈색으로 96×96 축소(새 색 없음)
   - 부대: 마젠타 제거 → 빈 열로 8프레임 분할 → 스트립당 단일 배율 → 영역 평균 축소 →
     부대 전체(대기+걷기 16프레임) 공용 32색 팔레트 → 1px 외곽선 → 고정 기준점 배치
   - 적 기병은 아군 기병의 청색 계열을 적색으로 치환
3. `python3 compose.py`: 후보 C의 화면 합성 코드에 새 시트와 초상을 연결해 `out/screen.png` 생성

## 규격

| 항목 | 값 |
|---|---|
| 부대 셀 | 64×64, 기준점 (32,58), 전장 ×2 표시 |
| 부대 높이 | 보병 44px, 기병 54px(창 포함) |
| 프레임 | 대기 8(150ms) → 걷기 8(110ms) |
| 초상 | 96×96, ×2 표시 |
| 지형 | 후보 C와 동일(32×16 마름모, 상위 저장소 objects.png 나무·바위) |

검사: 전 프레임 알파 0/255, 최하단 행 = 기준점 58, 셀 가장자리 비접촉 — 통과.

## 장점

- 초상의 완성도가 후보 A~D보다 크게 높다. 5명이 같은 구도·조명·밀도로 맞춰진다.
- 부대도 갑옷 비늘·방패·말 마구 등 디테일이 살아 있고, 대기·걷기의 팔레트가 일치한다.

## 한계와 다음 단계

- AI가 대기와 걷기를 별도 이미지로 그려, 같은 부대라도 자세·무기 방향이 다르다
  (기병 걷기는 창이 수직, 적병 걷기는 창을 아래로 듦). 확정 시 기준 포즈 1장을 고정하고
  나머지 프레임을 그 원화의 편집으로 생성해야 한다.
- 프레임 정렬은 머리 중심 기준 보정을 쓴다. 생성 원화 자체의 프레임 간 흔들림이 일부 남는다.
- 축소 도트는 수작업 정리 전 단계다. 얼굴·손의 픽셀 정리, 외곽선 정돈이 필요하다.
- 서로 붙은 칸(관우·유비)에서 부대가 겹친다. 64px 셀은 아이소메트릭 타일보다 크다.
- 북쪽을 바라보는 뒷모습 방향, 공격·피격·탈진, 일기토 측면 원화는 아직 없다.
