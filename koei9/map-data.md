# 원작 맵 데이터에서 확인한 내용

근거: [vonleibniz, San9 수정 연구(2011)](https://game.ali213.net/forum.php?action=printable&mod=viewthread&tid=3635680)의 1~3절. 아래 값은 그 제작자의 분석이며, 이 저장소에서 원작 파일을 직접 해석하여 검증한 결과는 아니다. 언어·플랫폼·업데이트 간 동일성도 미확인이다.

## 논리 격자

| 항목 | 분석 글의 설명 |
|---|---|
| 크기 | 200×200, 40,000개 지점 |
| 원점 | 북서쪽 `(0, 0)` |
| 좌표 범위 | `x`, `y` 각각 0~199 |
| 축 | 동서가 x, 남북이 y |
| 저장 인덱스 | `square = x + 200*y` |
| 역변환 | 위 식으로부터 `x = square % 200`, `y = square // 200` |

마지막 행은 식에서 계산한 역변환이다. 이 인덱스만으로 파일의 바이트 위치를 알 수는 없다. 레코드 크기·파일 헤더·오프셋은 확보하지 않았다.

## 속성

각 지점에 7개 속성이 있다고 설명한다. 그중 이름이 밝혀지지 않은 항목에 관해 다음 값을 제시한다.

| 항목 | 글에서 보고한 내용 |
|---|---|
| 첫 번째 미상 항목 | `512`: 통행 가능, `513`: 건설 가능, `1022`: 통행 불가 |
| 두 번째·세 번째 미상 항목 | 주변 지점 및 다른 값과 함께 지형 외관에 관여. 완전한 해석은 되지 않음 |
| 네 번째 미상 항목 | 다리·경계의 방향. 다리의 경우 `1`: 동서, `0`: 남북 |
| 그 밖의 설명 | 지형 속성, 해당 지점이 소속된 도시·거점을 수정하는 사례가 있음 |

위 숫자를 모든 플래그의 완전한 정의나 독립적인 비트 마스크로 가정하면 안 된다. 원작 코드와 동일한 포맷으로 저장할 수 있는 정도의 정보는 아니다.

건물 위치를 바꿀 때 해당 칸의 소속과 통행 속성도 맞춰야 하며, 지형 판정을 바꿔도 지도 외관이 그대로인 사례가 나온다. 따라서 타일 작업에서도 **보이는 지형과 이동 판정을 별도 레이어로 관리하는 방식**을 권한다. 이 권고는 제작 제안이다.

## 좌표를 옮길 때 주의할 점

- 원문의 북평 `(100,100)`과 남피 `(112,26)`은 **수정 예시**다. 원래 도시 좌표로 도시 목록에 입력하지 않았다.
- 게임의 200×200 논리 격자와 지도 이미지의 픽셀 좌표 사이 투영식·원점·여백은 확보하지 않았다.
- 북서 원점은 논리 좌표 설명이다. 스크린샷 좌상단 픽셀이 그 원점이라는 뜻은 아니다.
- 바다·산·강을 눈으로 읽어 칠한 맵은 시각 자료를 토대로 재구성한 맵이며, 원작 데이터 덤프와 구분해야 한다.
